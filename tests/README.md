# 测试计划

当前 `test_retrieval.py` 有 165 个测试：基础 PDF 11 个、学术 PDF 17 个、Word 8 个、TXT/Markdown 8 个、分块 21 个、Embedding 接口 3 个与评测公式 2 个、三档检索评测 5 个、Chroma 操作 15 个、BM25 11 个、RRF 融合 7 个、混合检索 9 个、精排 7 个、重排模型加载 3 个、批量导入 12 个、批量索引 9 个、Streamlit 界面 17 个。使用临时生成的实际文件验证中文、来源与位置、稳定文档标识、Word 正文/表格顺序、UTF-8 BOM 和 Markdown 保真。

分块用例调用真实的三种策略，核验大小/重叠、256/512/1024 字符设置、段落与中英文句子、结束引号、小数与 DOI、超长单句兜底、空内容与参数校验、稳定块 ID、原文区间和 CRLF 行号。重复段落与大重叠的组合验证位置向前推进且正文非空白字符全部覆盖；实际 Word/PDF/TXT 加载结果可直接分块，独立表格与公式来源元数据保留。配置测试只替换配置输入，不替换切分器；不把这些测试当作检索召回评测。

256/512/1024 三档大小效果对比只用于固定策略；递归和句段的实验使用 YAML 默认 512/64 参数。单元测试中的小大小/大重叠用于验证边界和缺陷回归，与参数选型实验区分。

Embedding 单元测试隔离模型构造，验证本地加载参数、归一化、模型复用和缺失权重报错；指标测试使用明确排名验证 Hit@5、Recall@5、MRR@10 的边界，以及题数不等时四组语言等权宏平均和最差组记录。它们不需要下载大模型，mock 不作为模型质量或速度数据。论文双语基准由 `reports/prepare_paper_benchmark.py` 准备，真实两模型对比由 `reports/compare_embeddings.py --sample ...` 运行，结果写入 QA 与独立原始 JSON；保留旧中文网页基准，不在每次单元测试中重复数分钟的性能实验。问题由 Codex 编写，尚未经人工复核。业务仍选定 M3E，不需要查询前缀包装层；BGE 的推荐前缀仅在对比实验中使用。

Chroma 用例使用真实临时数据库和明确的二维测试向量，验证正文/来源保留、余弦排序与负分、文档过滤、查重且不重复编码、只编码新增项、按文档删除、重开、配置不一致、参数/ID 校验、相同正文的不同来源、真实 Markdown 加载与超过 500 块的批量操作。另验证默认 K 来自 YAML、切换查询只编码问题、空问题无需读取数据库。不加载真实模型，也不把这些向量当性能实验数据；独立进程重启与真实 M3E 双语检索实验另见 [向量数据库 QA](../docs/QA/5.1.3%20向量数据库对比与选择.md)。

BM25 用例使用真实 rank_bm25 与临时 Chroma。已知词频、长度和文档频次按公式独立计算分数；验证中文、英文术语/大小写、全角字符归一化、K/文档过滤、来源和同正文多来源、空库/无词项、零/负分命中保留、重建/重开与数据库错误。只读正文、重复入库与空/无匹配向量查询不加载模型，真正向量操作才加载。页面用例另验证无需权重的 BM25 查询、上传/删除后的当前语料、错误恢复。真实论文核验见 [BM25 QA](../docs/QA/5.1.4%20BM25关键词检索.md) 与 [验证结果](../reports/BM25关键词检索验证结果.json)，不作为完整系统质量评测。

RRF 用例用独立手算排名验证公式、平滑常数、原始分数不参与、单路重复、同分顺序及同正文多来源。混合用例共享真实临时 Chroma 和 BM25，验证候选数与最终 K 分离、配置/过滤、单路或空结果、新增/删除后的最新语料、查询编码及异常上报。页面另验证混合排序/标签/来源、空库与模型错误恢复、文献变更；新增共 16 个测试。821 个真实论文块的 7 组现场查询另见 [RRF QA](../docs/QA/5.1.4%20RRF混合检索.md) 与 [验证 JSON](../reports/RRF混合检索验证结果.json)，融合公式/来源核验不当作 Hit@5/MRR 质量实验。

模型重排新增 16 个用例：成对输入、模型分数排序/同分、单条/空候选、Top-K、来源保留、非法配置/非有限分数、错误及恢复、本地参数和模型缓存，以及页面模式/来源/过滤/删除。混合链路核验融合第 20 项可以经模拟评分成为最终 Top-1，避免在重排前截成最终 K。仅模型构造/评分隔离，Chroma/BM25 与界面使用真实组件。真实 BGE 离线核验另见 [模型重排 QA](../docs/QA/5.1.4%20模型重排序.md) 与 [验证 JSON](../reports/模型重排序验证结果.json)：100 个分数逐项对照官方 Transformers 方式，模拟分数不当作模型质量数据。

学术 PDF 用例通过真实绘制文字、横线、网格和图片，验证双栏/通栏顺序、单栏防误判、两页与三页续表、重复表头去重、中文续表、无编号或不兼容表格防误合并、网格/三线表共存、空单元格、密集公式行、复杂表头回退、数学符号/上下标及图像原文裁剪。它们不依赖网络下载；公开论文的人工核对另记录在 [学术 PDF 解析优化](../docs/QA/5.1.2%20学术论文PDF解析优化.md)。

批量用例验证多格式导入、进度与状态、失败不阻断后续文件、仅重试失败项、保存失败恢复、同名文件保护、重复项和大小限制。批量索引用实际加载器、切分器和临时 Chroma，验证多格式入库、新文献只编码新块、重复任务和重新上传不重算、索引失败保留原文并跳过加载重试、部分批次恢复、阶段中断恢复、模型延迟初始化和空分块失败。600 块的用例模拟第 501 块所在批次失败，验证前 500 块保留、重试只编码剩余 100 块；小窗口仅用于批次边界测试。

界面用例通过 Streamlit AppTest 实际操作上传组件与按钮，检查状态表、进度条、索引字段、缺失模型恢复和新增/重复上传；检索表单核验持久化库搜索、K、负分、跨页/Word/TXT 来源、文档过滤、空输入/空库，以及模型/数据库错误后的重新提交。原文与索引均使用临时目录，大模型替换为明确二维向量，数据库不替换。所有文件使用临时目录，不修改真实文献。真实 M3E 离线四格式入库与增量验证另见 [批量索引 QA](../docs/QA/5.1.3%20批量向量化与增量索引.md)，不将小型测试向量当效果或速度数据。

真实 M3E 的 Top-K 核验另见 [Top-K QA](../docs/QA/5.1.3%20向量相似度Top-K检索.md) 和 [原始结果](../reports/向量Top-K检索验证结果.json)：复用 821 个真实文档向量，查询现场编码，并用 NumPy 全量余弦计算核对分数和排名，不当作答案质量或性能评测。

三档检索新增 5 个用例，按明确块 ID 验证 Hit@5/Recall@5/MRR@5 的第五名、越界、无命中、多相关块、非法标注/重复 ID、组间题数不等的宏平均和三轮延迟汇总。真实模型实验独立运行 `reports/compare_retrieval.py`，已在 821 块、96 条配对查询上完成三轮测量；原始排名与计时见 [检索质量 QA](../docs/QA/5.1.4%20检索质量评估实验.md)，不在每次单元测试中重复模型性能实验。

测试使用标准库 `unittest` 和已安装 Streamlit 自带的 AppTest，不增加测试依赖；不等同于浏览器视觉检查。

AppTest 等待上限为 10 秒，兼顾新环境首次加载界面依赖的耗时，避免默认 3 秒等待误报。

在项目根目录执行：

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_retrieval.py' -v
```

也支持从任意目录直接运行测试文件。使用已安装 `requirements.txt` 依赖的 Python，例如项目虚拟环境：

```bash
/Users/rean/github/RAG+Agent/.venv/bin/python /Users/rean/github/RAG+Agent/tests/test_retrieval.py -v
```

测试入口会按 `__file__` 定位项目根目录，避免直接运行时找不到 `src`。

新增的 Word 测试需要 `python-docx`。依赖已安装到项目 `.venv`；若使用其他 Python 解释器，应先为该解释器安装 `requirements.txt`，仅更换启动路径不会共享虚拟环境的依赖。

其他业务仍为占位，不为占位代码编写无意义的测试。

实现后按以下顺序添加有明确预期的用例：

1. 检索：比较五组分块设置的召回，并补充人工复核的独立评测集；Chroma 增量索引、BM25/RRF 与模型重排已有实际用例。
2. 生成：引用准确性、流式输出、缓存失效与三类降级场景。
3. Agent：工具选择、并行、超时、最大循环次数、会话隔离与记忆截断。
4. 端到端：上传 → 索引 → 提问 → 决策 → 带引用回答；空库、大文档、长对话。

后续课程要求的检索与 Agent 用例分别放入 `test_retrieval.py`、`test_agent.py`；实际采用的测试依赖在首次使用时加入。
