`test_generation.py` 有 123 个测试：8 个 Prompt、16 个上下文策略、17 个引用溯源、6 个降级上下文、10 个本地生成接口、17 个流式/增量引用、14 个语义缓存、8 个日志文件、21 个聊天界面和 6 个生成评分规则测试，当前合计 288 个测试通过。直接使用真实 LangChain 模板，检查四部分与消息角色、空上下文提示、空问题拒绝、公式/花括号/Markdown 保真、动态文本不改变系统消息、调用之间互不污染、长文本/空白保留，以及上游 Context 字典的文本接口。样例由测试中明确构造，不调用模型或网络；消息结构检查不代表模型能抵御所有提示词注入，也不代表模型引用语义准确性或答案质量已验证。详见 [Prompt QA](../docs/QA/5.2.1%20RAG专用Prompt模板.md)。

上下文用例使用真实 Document 与模板，按明确分数和字符预算验证降序/同分/负分、动态余量、自然边界和 Unicode 截断、标题及分隔符开销、各格式来源、非法配置/分数、预算不足与输入不变。只隔离 YAML 配置，不替换排序或截断逻辑。既有真实论文三档排名回放另见 [上下文 QA](../docs/QA/5.2.1%20上下文智能拼接与截断.md)，不将字符数当作模型 Token 数，也不将回放当作重新运行模型的质量实验。

引用用例验证入选块映射与元数据快照、正文补全文档名/页码、实际使用来源、重复/无效编号、跨页/Word/文本位置、截断可见证据、无引用和不完整来源提示、代码/转义/普通链接处理及输入不变。实际临时 PDF/DOCX/TXT/MD 经真实加载/分块得到 6 块，逐一核对原文、路径、稳定 ID 和位置。两个公开论文的原 PDF 事实/页码另见 [引用 QA](../docs/QA/5.2.1%20引用溯源机制.md)；答案人工构造，不冒充 LLM 生成或引用准确率实验。

分块用例调用真实的三种策略，核验大小/重叠、256/512/1024 字符设置、段落与中英文句子、结束引号、小数与 DOI、超长单句兜底、空内容与参数校验、稳定块 ID、原文区间和 CRLF 行号。重复段落与大重叠的组合验证位置向前推进且正文非空白字符全部覆盖；实际 Word/PDF/TXT 加载结果可直接分块，独立表格与公式来源元数据保留。配置测试只替换配置输入，不替换切分器；不把这些测试当作检索召回评测。

256/512/1024 三档大小效果对比只用于固定策略；递归和句段的实验使用 YAML 默认 512/64 参数。单元测试中的小大小/大重叠用于验证边界和缺陷回归，与参数选型实验区分。

Embedding 单元测试隔离模型构造，验证本地加载参数、归一化、模型复用和缺失权重报错；指标测试使用明确排名验证 Hit@5、Recall@5、MRR@10 的边界，以及题数不等时四组语言等权宏平均和最差组记录。它们不需要下载大模型，mock 不作为模型质量或速度数据。论文双语基准由 `reports/prepare_paper_benchmark.py` 准备，真实两模型对比由 `reports/compare_embeddings.py --sample ...` 运行，结果写入 QA 与独立原始 JSON；保留旧中文网页基准，不在每次单元测试中重复数分钟的性能实验。问题由 Codex 编写，尚未经人工复核。业务仍选定 M3E，不需要查询前缀包装层；BGE 的推荐前缀仅在对比实验中使用。

在项目根目录执行：

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

```bash
/Users/rean/github/RAG+Agent/.venv/bin/python /Users/rean/github/RAG+Agent/tests/test_retrieval.py -v
/Users/rean/github/RAG+Agent/.venv/bin/python /Users/rean/github/RAG+Agent/tests/test_generation.py -v
```
