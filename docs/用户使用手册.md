# 用户使用手册

当前版本支持 PDF、Word（.docx）、TXT/Markdown 的批量上传、正文加载、保存、进度显示和失败项重试。导入成功表示文件已保存且正文加载成功；索引、智能问答、引用与对话会话尚未接入。

## 1 本地启动

从项目根目录执行：

```bash
# 创建隔离环境，避免修改系统 Python 依赖。
python3 -m venv .venv
source .venv/bin/activate

# 安装运行依赖，并启动文档导入应用。
python -m pip install -r requirements.txt
python -m streamlit run src/frontend/app.py
```

Windows PowerShell 的激活命令为 `.venv\Scripts\Activate.ps1`，其余 Python 命令相同。

浏览器打开 http://localhost:8501。在左侧上传文档，在主区域查看本批导入结果和五个课程模块的开发状态。当前页面无需 Ollama、模型权重或向量数据库。

Python 支持范围与安装方法见 [Streamlit 官方安装文档](https://docs.streamlit.io/get-started/installation)。当前直接依赖版本固定在 `requirements.txt`；完整业务实现时还需补齐模型库及完整环境记录。

## 2 Docker 启动

已安装并启动 Docker 的环境中，从项目根目录执行：

```bash
# 构建并启动 Streamlit 应用。
docker compose -f docker/docker-compose.yml up --build

# 停止并清理本项目容器。
docker compose -f docker/docker-compose.yml down
```

页面仅监听本机 8501 端口。本部署文件当前不启动 Ollama 或数据库，完整系统部署将在业务接入后验证。容器首次构建需要联网下载基础镜像和 Python 依赖。

本次初始化所在机器缺少 Docker Compose 子命令，因此未实测容器构建与启动。执行前可用 `docker compose version` 确认 Compose 已可用。

## 3 文件与配置

- `config.yaml` 的 `app` 控制页面名称与描述，`importing.max_file_size_mb` 控制单份文件大小，默认 20 MB；其余模型等字段仍是后续参数样例。
- `paths.raw_documents` 指定原始文献目录，默认 `data/raw/`，按“内容 SHA-256/原文件名”保存，避免同名不同内容互相覆盖；`data/index/` 仍预留给向量索引。
- `logs/` 预留给运行日志。
- 原始课程资料保留在 `docs/`，不会自动导入论文知识库。

### 批量导入操作

1. 左侧“选择多份文档”支持 `.pdf`、`.docx`、`.txt`、`.md`、`.markdown`，可一次选择多份文件；单份默认不超过 20 MB。
2. 点击“开始导入”。系统逐份处理，状态从“等待”变为“处理中”，然后为“成功”或“失败”。状态表显示尝试次数、内容单元数、本次耗时和错误原因。
3. 查看结果。进度 100% 表示本轮全部尝试完毕，失败项也计入已处理数量；成功与失败数量另行显示。内容单元是 PDF 页、Word 段落/表格或整篇纯文本，不是向量分块。
4. 遇到临时读写失败，可点击“重试失败项”。每次点击仅对失败文件再尝试一轮，成功文件不重复加载。损坏文件或编码错误应先修正，再重新选择文件导入；TXT/Markdown 需为 UTF-8 编码。

同名且内容相同的文件在本批合并。全部尝试结束后，相同选择的“开始导入”禁用；普通页面重跑不会重新执行导入。导入状态只保留当前页面会话，刷新页面或断开连接后可能清空，成功保存的文件仍在磁盘。当前状态表仅展示本批结果，全知识库管理与文件删除将在后续实现。

## 4 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 提示缺少 streamlit 或 yaml | 在激活环境内重新执行 `python -m pip install -r requirements.txt` |
| 8501 端口已占用 | 追加 `--server.port=8502`，然后访问对应地址；Docker 需调整宿主机端口映射 |
| 配置文件找不到 | 确认 `config.yaml` 位于项目根目录，入口仍在 `src/frontend/app.py` |
| 页面不能提问 | 当前只提供文档导入，问答尚未实现 |
| TXT/Markdown 显示 UnicodeDecodeError | 将文件转换为 UTF-8 后重新上传；重复重试不会修正编码 |
| PDF/Word 解析失败 | 检查文件是否损坏、格式是否正确；需要密码或无文本的 PDF 不支持当前加载器 |
| 导入显示读写错误 | 检查原始文献保存目录是否可写，修正后点击“重试失败项” |
| 是否需要下载大模型 | 当前页面无需下载；业务实现后再按经过验证的模型部署步骤准备 |
