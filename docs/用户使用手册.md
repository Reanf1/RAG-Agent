# 用户使用手册

当前版本支持 PDF、Word（.docx）、TXT/Markdown 批量导入、自动分块、M3E/Chroma 增量索引、进度及失败项重试、向量/BM25/RRF/模型重排检索，以及本地 RAG 流式问答和动态引用。导入成功表示原文已保存、全部预期块已处理并写入索引；新增文献保留旧索引，重复块不重新编码。中央“多轮对话”已接入 SQLite 会话与多轮记忆，标签内展示实际决策轨迹；“单轮对话”保留逐 Token 正文和引用，其历史和引用已保存到 SQLite，只用于展示，不作为 RAG 多轮推理上下文。“检索文档”展示Top-K检索和检索分数分布；其右侧“知识库”标签展示文件列表与完整解析内容。左侧支持会话新建、切换、回收删除和恢复；Agent 的 Observation 正文支持真实逐包输出；增量为待校验文本，最终完成状态与引用以校验结果为准。PDF 引用可查看真实物理页及下载原文。

## 1 本地启动

Windows首次部署请按[Windows部署教程](Windows部署教程.md)操作，其中包含当前未提交代码迁移、Python3.10.10、Windows版Ollama、四类模型文件、PowerShell命令及部署后的交接流程。

从项目根目录执行：

当前项目环境为 Python 3.10.10；使用 pyenv 时，根目录 `.python-version` 选择该版本。已有配置好的 `.venv` 可直接激活，只有首次创建或重建时才执行创建命令。

```bash
# 创建隔离环境，避免修改系统 Python 依赖。
python3.10 --version  # 应输出 Python 3.10.10。
python3.10 -m venv .venv
source .venv/bin/activate

# 安装运行依赖，并启动文档导入应用。
python -m pip install -r requirements.txt
python -m streamlit run src/frontend/app.py
```

Windows PowerShell 的激活命令为 `.venv\Scripts\Activate.ps1`，其余 Python 命令相同。

浏览器打开 http://localhost:8501。在左侧上传文档并查看入库进度，中央切换 Agent/RAG 对话，底部查看轨迹与指标，页面后部保留检索实验与健康检查。页面启动不加载模型；新文档入库或有效向量/混合查询需准备本地 M3E，模型重排及 RAG 问答另需 BGE。文档导入/检索无需启动 Ollama，生成答案前需启动下文的本地 Ollama；Chroma 使用本地文件。

Python 支持范围与安装方法见 [Streamlit 官方安装文档](https://docs.streamlit.io/get-started/installation)。当前直接依赖版本固定在 `requirements.txt`；本地和容器均使用 Python 3.10.10。

## 2 Docker 启动

先按下文准备 M3E、BGE、Qwen 词表，以及 `data/models/ollama/models/` 下的 Qwen2.5:7b 权重。Mac 的 Ollama 可执行文件不能用于 Linux 容器；Compose 使用固定 `ollama/ollama:0.34.0` 镜像读取同一模型目录。首次构建需要联网下载镜像和 Python 依赖。

```bash
# 在项目根目录构建并启动一个业务应用与本地推理运行时。
docker compose -f docker/docker-compose.yml up -d --build
# 查看真实容器状态和日志。
docker compose -f docker/docker-compose.yml ps
docker compose -f docker/docker-compose.yml logs --tail=80
# 停止项目容器，挂载的原文、索引、会话和日志保留。
docker compose -f docker/docker-compose.yml down
```

若本机只有独立 Compose，以上 `docker compose` 换为 `docker-compose`。本项目开发机采用 Colima 测试环境与独立 Compose；使用 Docker Desktop 的机器可直接使用其 Compose 插件。

页面仅映射 [本机 8501](http://127.0.0.1:8501)。配置只读挂载，`data/` 和 `logs/` 持久挂载；`RAG_OLLAMA_BASE_URL=http://ollama:11434` 只覆盖本地服务地址。Ollama 不映射宿主端口，两个容器在内部网络通信，模型列表健康后才启动应用。默认是 CPU 推理，不能把开发机 Metal 的响应速度当成容器速度。

权重与镜像准备后，内部网络阻断业务容器访问外网；Embedding/重排开启离线读取，可选联网搜索应保持关闭。没有模型时不会自动下载或切换云端，页面会明确报错。应用的健康探针只检查 Streamlit 可访问；模型和现有 Chroma 仍需点击“检查服务状态”，并完成一次真实问答核验。

构建、依赖与实际链路记录见 [项目交付验证](../reports/5_5_4%20项目交付/README.md)。镜像与运行时验证阶段分别记录，连接健康不代替答案质量。

## 3 文件与配置

- `config.yaml` 的 `app` 控制页面名称与描述，`importing.max_file_size_mb` 控制单份文件大小，默认 20 MB。`llm`、`generation`、`agent` 与 `memory` 已分别控制本地生成、上下文/缓存、循环/恢复和窗口/摘要参数。
- `chunking` 控制页面和 Python 索引流程的默认策略、字符大小和重叠，当前为 `recursive`、512、64。
- `embedding` 已启用：选定 `moka-ai/m3e-base`，权重位置为 `data/models/m3e-base`，默认 CPU、批大小 32，版本固定在 YAML 的 `revision`；推理只读本地模型。
- `paths.raw_documents` 指定原始文献目录，默认 `data/raw/`，按“内容 SHA-256/原文件名”保存，避免同名不同内容互相覆盖；`paths.vector_index` 指定 Chroma 目录，默认 `data/index/`。
- `retrieval` 已启用 Chroma、集合名 `paper_chunks`、`search_ef=100`、4 个索引线程与默认 Top-5；混合检索两路候选默认各 20 项、RRF 常数为 60；重排已启用本地 bge-reranker-base，CPU、批次 8、输入上限 512 Token。
- `paths.logs` 已用于本地 RAG 请求日志，默认 `logs/rag_YYYY-MM-DD.jsonl`，按北京时间分日追加；包含问题、原文和回答，Git默认忽略。
- 原始课程资料保留在 `docs/`，不会自动导入论文知识库。

### 批量导入操作

1. 左侧“选择多份文档”支持 `.pdf`、`.docx`、`.txt`、`.md`、`.markdown`，可一次选择多份文件；单份默认不超过 20 MB。
2. 先确认本地 M3E 权重已准备，再点击“开始导入”。系统逐份执行“加载中→分块中→向量化与索引中→成功/失败”。第一次有效索引会加载模型，之后同进程复用。
3. 查看结果。进度 100% 表示本轮全部尝试完毕，失败项也计入；成功与失败数量另行显示。表格显示内容单元、分块数、已处理块、本次新增块和写入后的全库块数。内容单元是加载结果；已处理块包含重复项，本次新增不含旧块。库中块数是该文档最近一次写入后的快照。
4. 遇到失败，可修正原因后点击“重试失败项”。每次点击仅对失败文件尝试一轮，成功文件不重做；索引失败保留原文、加载结果和已写入块，重试只补缺失块。损坏文件或编码错误应先修正后重新上传，TXT/Markdown 需为 UTF-8。模型缺失需按下文准备权重，索引配置不匹配需新目录重建。

同名且内容相同的文件在本批合并。全部尝试结束后，相同选择的“开始导入”禁用；普通页面重跑不会重新执行导入。新选择的文献追加到原集合；重新选择同一原文新增为零，不重算已有向量。任务状态只保留当前页面会话，刷新或断开后可能清空；原文与已写入索引保留，重新上传可补齐缺失块。本批表展示当前任务；全知识库列表、向量化状态、删除恢复和汇总面板见下文。实现与故障恢复证据见 [批量索引 QA](QA/5.1.3%20批量向量化与增量索引.md)。

### 学术 PDF 的处理范围

常见居中双栏按区域读完整左栏后再读右栏；网格表和规则三线表作为独立表格内容，符合条件的跨页续表合并并保留逐行页码。公式保留文本符号和可识别上下标；复杂分式或图片公式保留原 PDF 与位置，不自动转为 LaTeX。多级表头、合并单元格或不规则栏布局仍需对照原文核验，未进行公式 OCR。当前界面展示导入状态，尚未提供公式/表格预览面板。具体边界见 [学术 PDF 解析优化](QA/5.1.2%20学术论文PDF解析优化.md)。

### 三种分块的 Python 调用

在项目根目录、已激活 `.venv` 的 Python 中执行：

```python
from src.data_loader import load_document
from src.chunking import split_documents

documents = load_document("data/raw/论文.pdf")  # 替换为实际文件路径。
chunks = split_documents(documents)  # 使用 YAML 的 recursive、512/64 字符。
for size in (256, 512, 1024):  # 只有固定切分比较三种大小。
    chunks = split_documents(documents, strategy="fixed", chunk_size=size)
    print("fixed", size, len(chunks))
for strategy in ("recursive", "semantic"):  # 其余策略使用 YAML 默认参数。
    chunks = split_documents(documents, strategy=strategy)
    print(strategy, len(chunks), chunks[0].metadata)
```

`chunk_size` 必须为正整数，`chunk_overlap` 满足 `0 <= chunk_overlap < chunk_size`。固定切分按窗口移动；递归切分按段落、换行、标点到字符逐级处理；语义切分优先保留段落，长段落拆句，超长单句按字符兜底，不需下载模型。

固定正文重叠精确等于设置值；递归和句段策略只在完整切分单元间选重叠，实际可能更少或为零。独立 PDF/Word 表格整块保留，可能超过大小上限。块保留来源并新增 `chunk_id`、`start_index`、`end_index`；字符区间相对父内容单元，末尾不含在区间内。TXT/Markdown 行号细化到块；Word 不产生物理页码。规则说明见 [三种文本分块策略](QA/5.1.2%20三种文本分块策略.md)。

### 本地 Embedding 的准备和调用

本机已经准备 M3E 权重。首次在其他电脑使用时，在项目根目录、已安装依赖的环境中执行以下 Python 代码，仅下载选定模型：

```python
from huggingface_hub import snapshot_download
from src.utils.config import load_config

config = load_config()["embedding"]
snapshot_download(
    config["model"], revision=config["revision"], local_dir=config["local_path"],
    allow_patterns=["*.json", "vocab.txt", "model.safetensors"],
)
```

权重准备需要联网，约 409 MB；`data/models/` 已忽略，不提交到 Git。准备完成后可离线调用：

```python
from src.retrieval.vector_store import get_embeddings

embeddings = get_embeddings()  # 首次加载，之后在同一进程内复用。
vectors = embeddings.embed_documents([chunk.page_content for chunk in chunks])
query_vector = embeddings.embed_query("论文使用了什么实验方法？")
print(len(vectors), len(query_vector))  # 查询向量维度为 768。
```

M3E 对查询、正文均直接编码，不加 BGE 的检索前缀；中英文使用同一接口，例如 `embeddings.embed_query("Which optimizer does the paper use?")`。模型输出归一化浮点列表，最大输入为 512 Token；超长文本会被截断，这与分块的 512 字符不是同一单位，超长表格仍需后续处理。基于中英文人工智能论文的对比后保留 M3E，但英文及跨语言检索质量仍不足；四组实测、速度与选择理由见 [Embedding QA](QA/5.1.3%20Embedding模型对比与选择.md)。

配置路径按项目根目录解释。缺少模型目录会明确报错，损坏权重不会自动转云端；修改模型配置后重启进程，避免复用旧实例。页面启动、读取正文和 BM25 查询无需模型；新块向量化或有效向量/混合查询时需要本地 M3E 权重。

### 页面 Top-K 检索

1. 文档索引成功后，在“检索文档”标签的“文档 Top-K 检索”选择“向量相似度”、“BM25 关键词”、“RRF 混合检索”或“RRF + 模型重排”，填写中英文查询内容。
2. 设置返回数量 K，默认从 YAML 读取，为 5；必须为正整数。
3. “限定文档 ID”可留空，搜索全部已持久化文档；也可从结果复制前八位文档 ID，仅搜索该篇文献；唯一前缀自动匹配完整编号，前缀冲突时需输入完整 ID。
4. 点击“检索”。结果按所选检索方式的分数降序展示原文块、分数、文件名、文档/块 ID 与位置；PDF 为物理页码或跨页范围，Word 为段落/表格位置，TXT/Markdown 为行范围。

知识库重开后仍可查询，不需要重新上传或重新计算旧文档向量。K 大于匹配块数时返回全部匹配块；空查询提示输入，空库或文档 ID 无匹配提示检查导入和 ID。模型/数据库错误单独显示，修复后重新提交查询即可。检索表单提交时更新结果，其他页面操作重跑后可重新检索。

向量相似度、BM25、RRF 和模型相关性分数均不代表命中概率，不能直接比较。BM25 只返回有词项交集的块，因此可能不足 K 个；小语料中零分或负分的命中也保留。英文按词并统一大小写，中文按单字，不做词级分词或同义词扩展；分词前对全角英文/数字做 NFKC 归一化，结果正文仍保留原样。英文术语与空格写法不同，例如 BatchNormalization 不自动等同于 Batch Normalization。该表单只做检索；生成答案请使用“单轮对话”或“多轮对话”标签。具体说明见 [Top-K QA](QA/5.1.3%20向量相似度Top-K检索.md) 与 [BM25 QA](QA/5.1.4%20BM25关键词检索.md)。

### Chroma 索引与检索的 Python 调用

已准备本地 M3E 后，从项目根目录运行：

```python
from src.data_loader import load_document
from src.chunking import split_documents
from src.retrieval.vector_store import VectorStore

chunks = split_documents(load_document("data/raw/论文.pdf"))  # 改为实际路径。
store = VectorStore()  # 打开 YAML 指定的 data/index/，实际向量操作时才加载模型。
print("实际新增：", store.add_chunks(chunks))  # 重复执行不会重新编码旧块。
print("全部块数：", store.count())
for document, score in store.search("论文使用了什么方法？", k=5):
    print(document.metadata, score, document.page_content)

# 限定一篇文档检索与读取，适用于后续论文对比和管理。
doc_id = chunks[0].metadata["doc_id"]
results = store.search("What method does this paper use?", doc_id=doc_id)
stored_chunks = store.list_chunks(doc_id)
# 按需删除该文档的索引，原始 PDF 保留。
# print("删除块数：", store.delete_document(doc_id))
```

再次启动 Python，重新构造 `VectorStore()` 即可读取持久化索引，无需全量重建。查询返回原正文和来源，以及余弦相似度；分数不是置信概率。空库或空问题返回空列表。增量导入按稳定块 ID 去重；改变分块策略或内容会生成新 ID，替换同一文档的分块方案时应先按旧 `doc_id` 删除索引，再添加新块。

修改模型版本、距离或索引参数后，旧集合与配置不一致会明确报错。将 `paths.vector_index` 改为新目录后，从原文重新分块和编码；旧目录保留，便于核验。不手动修改或删除 Chroma 内部文件。两库实测与选型见 [向量数据库 QA](QA/5.1.3%20向量数据库对比与选择.md)。当前页面可自动入库并选择向量、BM25、RRF 或模型重排搜索，知识库支持回收删除与恢复；完整 Python 批量接口示例见 [批量索引 QA](QA/5.1.3%20批量向量化与增量索引.md)。

### RRF 混合检索的 Python 调用

已有 Chroma 索引且准备本地 M3E 权重后：

```python
from src.retrieval.hybrid_retriever import HybridRetriever

retriever = HybridRetriever()
for document, score in retriever.search("Transformer 的实验结果", k=5):
    print(document.metadata, score, document.page_content)

# 可获取融合后的 Top-20；默认 rerank=False，此调用只融合。
candidates = retriever.search("注意力机制", k=20)
```

默认两路各取 20 项，最终 K 更大时各取 K 项；按稳定块 ID 合并，累加 `1/(60+排名)`，再保留最终 Top-K。混合实例每次查询重建当前 BM25 语料，新增/删除后无需手动刷新或重新编码旧文献。可传入 `doc_id` 限定两路范围。某一路正常无结果时使用另一路；模型/数据库错误明确显示，不静默降级。说明及真实核验见 [RRF QA](QA/5.1.4%20RRF混合检索.md)。

### 本地模型重排

本机已准备 bge-reranker-base 权重。其他电脑首次在项目根目录显式联网下载固定版本：

```python
from huggingface_hub import snapshot_download
from src.utils.config import load_config

config = load_config()["retrieval"]
snapshot_download(
    config["reranker_model"], revision=config["reranker_revision"],
    local_dir=config["reranker_local_path"],
    allow_patterns=["*.json", "model.safetensors", "sentencepiece.bpe.model"],
    max_workers=2,
)
```

权重约 1.11 GB，另有 Tokenizer 文件，均保存在忽略目录 data/models/bge-reranker-base。已安装的依赖可直接加载；准备后可断网运行。页面选择“RRF + 模型重排”，或调用：

```python
from src.retrieval.hybrid_retriever import HybridRetriever

results = HybridRetriever().search("Transformer 编码器有多少层？", k=5, rerank=True)
for document, score in results:
    print(document.metadata, score, document.page_content)
```

默认将 RRF 的 Top-20 交给模型后再保留最终 K，K 更大时扩大候选。问题与正文合计超过 512 Token 会截断，原文与来源仍完整展示；模型未必读到长表格尾部。分数由 sigmoid 映射到 0～1，不是命中概率。首次有效精排才加载并缓存，同一进程后续复用；修改模型、设备或输入上限后重启进程。权重缺失/损坏或推理异常会显示错误，修复后重新提交；不自动下载或改用关键词重排。操作与核验见 [模型重排 QA](QA/5.1.4%20模型重排序.md)。

### RAG 专用 Prompt 的 Python 调用

从项目根目录使用已准备的检索上下文字符串生成消息：

```python
from src.generation.prompt_template import build_rag_messages

# 人工构造的功能示例，真实检索时应使用文档原文与实际来源位置。
context = "[参考文档1 - 来源: 示例论文.pdf；第3页]\n本研究使用自注意力机制。"
messages = build_rag_messages("这篇论文使用什么方法？", context)
for message in messages:
    print(message.type, message.content)
```

该函数返回 System/Human 两条 LangChain 消息，分别包含固定角色/回答规范和检索上下文/当前问题；生成由 rag_pipeline/streaming 接口调用。上下文可通过下面的 `build_context()` 准备，编号、文件名和位置须来自实际文献；模板不会自动创建引用映射。省略上下文时填入“当前知识库中未找到相关文档。”，空白问题抛出 `ValueError`。版本与测试见 [Prompt QA](QA/5.2.1%20RAG专用Prompt模板.md)。

### 按相关性拼接与截断上下文

使用现有本地索引和已准备模型，从项目根目录调用：

```python
from src.retrieval.hybrid_retriever import HybridRetriever
from src.generation.rag_pipeline import build_context
from src.generation.prompt_template import build_rag_messages

question = "Transformer 的编码器使用什么结构？"
results = HybridRetriever().search(question, k=5, rerank=True)

messages = build_rag_messages(question, context["context"])
print(context["sources"], context["chunk_count"], context["truncated"])
```

结果必须来自同一种检索方式，分数越高越相关，同分保持顺序。配置 `generation.max_context_chars=6000` 和 `max_prompt_chars=12000`；问题越长，上下文余量越小。来源标题不截断，超长正文优先在句段边界保留前缀并标注，未入选文件不列入来源。`context_chars`、`prompt_chars` 均是字符数，不能当成 Token 数或直接配置模型窗口；当前只组织消息，未生成答案。预算不足时缩短问题或调整配置。完整规则和验证见 [上下文 QA](QA/5.2.1%20上下文智能拼接与截断.md)。

### 答案引用溯源

`build_context()` 会为本轮实际入选的文档块生成 `references` 映射。得到完整原始答案后，和同一份 Context 一起调用：

```python
from src.generation.rag_pipeline import resolve_citations

# 人工构造的接口演示；只有 context 中实际存在该编号时才能成功溯源。
raw_answer = "## 回答\n结论依据原文[参考文档1]。\n\n## 参考来源\n[参考文档1]"
resolved = resolve_citations(raw_answer, context)
print(resolved["answer"])
print(resolved["warnings"])  # 不能隐藏无效引用、缺失来源或没有引用的提示。
for citation in resolved["citations"]:
    print(citation["source_file"], citation["location"], citation["text"], citation["metadata"])
```

正文中的编号会补全文档名和 PDF 物理页码；Word/文本使用真实段落、表格或行位置，不虚构页码。系统按正文实际引用重建来源区，不信任模型手写文件名或页码，不自动为没有引用的答案附上全部检索来源。证据包含实际已入上下文的原文前缀、原文件路径、已有稳定 ID 和定位元数据，截断时明确标记；定位范围仍是原始块范围。

当前 Prompt 为 `rag-v3`，模型须使用严格的 `[参考文档N]`，不跨请求复用编号。非流式处理完整原始答案；流式在编号闭合后立即映射同轮来源，结束时补来源清单。实际本地问答与动态引用已接通，编号映射正确仍需人工确认原文能否支持结论。见 [引用 QA](QA/5.2.1%20引用溯源机制.md) 和 [流式 QA](QA/5.2.2%20流式输出与引用.md)。

### 页面流式问答

启动本地 Ollama 和 Streamlit 后，先上传论文并完成索引，再在页面底部的“询问已上传论文”输入框提交问题。默认使用混合检索＋BGE 重排的 Top-5 上下文，不受上方仅检索表单的选项影响。

正文随模型片段持续显示；`[参考文档N]` 被拆开时暂存，收到闭合标记后立即补全文档名和真实页码/段落/行位置。结束后显示来源清单、实际 Token 与耗时，展开引用证据可读本轮送入模型的原文。首次加载模型可能较慢，页面等待真实输出，不模拟速度。

断流或失败显示“回答未完成”并保留已收到的文本；检查服务后重新提交。输出达到 Token 上限会单独提示。无文档时明确提示没有文献依据，模型漏写正文编号或引用无效时有警告，不会自动为答案猜测来源。可点击“清空当前对话”移除当前会话已保存的 RAG 记录及答案缓存；历史只用于展示，不支持“上一轮那篇论文”等指代记忆。每个问题先查缓存，未命中才独立检索生成。

Python 调用示例（沿用上文的 `case`，只验证生成，不重复检索）：

```python
from src.generation.streaming import stream_answer

for event in stream_answer(case["question"], case["context"]):
    if event["type"] == "token":
        print(event["answer"])  # 当前完整正文快照；前端用它替换占位区，不能再次累加。
    elif event["type"] == "done":
        print(event["answer"], event["usage"], event["warnings"])
    else:
        print("回答未完成：", event["message"])
```

### 三类降级与重试

没有有效文献正文时，系统使用本地模型解释通用概念，回答开头固定显示“当前知识库中未找到相关文档”及纯模型提示。此时没有知识库引用；具体论文数据和结果需先上传对应资料。

候选正文最高 BGE 重排分数低于 `generation.low_relevance_threshold=0.1` 时，页面先显示问题、候选文件名、真实位置和原文，暂不生成。核验后可点击“使用这些内容继续生成”，或“取消本次回答”。确认后仍保留低相关性提示，且不会缓存这类答案。分数不是正确率；确认并不能使不相关文献成为可靠依据。普通页面重跑不会自动确认；新问题或清空对话会移除旧请求，知识库/配置改变后需重新提交。

模型调用失败时，查看“回答未完成”和重试建议。连接失败需启动本机 Ollama 并检查端口；404需检查 YAML 的模型名称/地址，用 `ollama list` 核验；超时需等待加载或缩短问题/上下文；其他服务错误查看日志与内存。系统保留已输出部分，修复后在聊天框重新提交问题。两个生成接口直接连接本机服务，不依赖系统HTTP代理；失败不会自动再次生成。实现与真实记录见 [降级 QA](QA/5.2.3%20降级策略.md)。

### 语义缓存使用

缓存自动启用，页面会保留本会话正常结束、非空且有有效正文引用、没有警告的答案。相同问题直接命中；中英文近似改写使用本地M3E余弦相似度匹配，默认阈值0.97，数字、模型标识、否定和语言要求变化时保守拒绝复用。超过256字符只允许精确匹配。

命中显示“缓存已返回”、匹配方式和原问题，正文及原文证据直接出现，本次不运行检索/重排/LLM，输入/输出Token为0。语义匹配仍需要一次问题编码。知识库新增、删除、替换及配置或Prompt变化后旧缓存失效；修改实际模型权重后需重启页面进程。清空对话、关闭会话或重启进程后不保证保留缓存。

容量在 `generation.cache.max_entries` 设置，默认100条；最早写入条目超限淘汰。`similarity_threshold` 越低可能增加命中，也会增加不同问题共用答案的风险；相似度不是正确率。无文献依据、低相关性（包括确认后）、引用警告、长度截断和失败回答不存。缓存只复用原答案，不验证或修正原模型的事实错误；仍需查看证据。实际中文误拒答和中英命中时序见 [语义缓存 QA](QA/5.2.3%20语义缓存.md)。

### 请求日志与检索分数分布

每次提交聊天问题都会记录请求编号、会话编号与状态。日志保存完整Top-K原文/来源及实际截断上下文、原始/展示回答、检索/生成/处理耗时、服务实际输入和输出Token、引用警告及错误建议。正常问答按开始→检索→结束追加快照；低相关性确认/取消沿用原请求编号。清空对话移除当前会话已保存的 RAG 历史和缓存，运行日志会保留。

页面底部“检索分数分布”显示实际RAG检索的Top-1重排分数区间、次数、均值与范围；不同模型版本分别统计，重新打开页面可从已有日志恢复。空库、检索失败和缓存跳过单独计数，不补成0分；确认同一次检索不重复计数。有结果后生成失败的检索也会计入，分数分布不能代替Hit@5或人工正确率评测。上方独立检索表单不混入本分布。

缓存命中本次Token为0，原始用量单列；失败请求没有服务用量时显示为未知，JSON记录为 `null`。日志写入失败会提示，已完成答案保留。可直接在本地查看UTF-8 JSONL文件，每行是快照；同一个 `request_id` 的最后一行是最新状态。日志目录或文件不能读写时检查 `paths.logs` 配置及目录权限。

读取最新请求和分布的Python示例：

```python
from src.utils.logger import read_rag_requests, retrieval_score_distribution

requests, invalid_lines = read_rag_requests()
print("请求数：", len(requests), "无法解析的行数：", invalid_lines)
print(retrieval_score_distribution())  # 实际模型分数统计，不是回答正确概率。
```

完整字段、统计口径和真实JSONL见 [日志与检索质量自评 QA](QA/5.2.4%20日志与检索质量自评.md)。

## 4 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 提示缺少 streamlit 或 yaml | 在激活环境内重新执行 `python -m pip install -r requirements.txt` |
| 8501 端口已占用 | 追加 `--server.port=8502`，然后访问对应地址；Docker 需调整宿主机端口映射 |
| 配置文件找不到 | 确认 `config.yaml` 位于项目根目录，入口仍在 `src/frontend/app.py` |
| 如何提问 | 完成索引并启动本地 Ollama 后，在底部聊天框提交问题；上方检索表单只查原文 |
| 回答未完成或没有输出 | 检查 Ollama 是否监听本机11434、Qwen权重与 YAML 名称是否匹配；检查页面错误后重新提交 |
| 答案没有引用或引用无效 | 查看警告及原文，正文需有有效的 `[参考文档N]`；末尾来源列表不能替代正文依据 |
| 为什么相似问题没有命中缓存 | 检查是否有正常结束且引用有效的原答案；阈值、数字/标识/否定/语言、问题长度、知识库或配置变化均可能拒绝复用 |
| 如何清理缓存或修改容量 | “清空当前对话”同步清缓存；在 `generation.cache` 调整阈值或容量，页面读取新配置 |
| TXT/Markdown 显示 UnicodeDecodeError | 将文件转换为 UTF-8 后重新上传；重复重试不会修正编码 |
| PDF/Word 解析失败 | 检查文件是否损坏、格式是否正确；需要密码或无文本的 PDF 不支持当前加载器 |
| 导入显示读写错误 | 检查原始文献保存目录是否可写，修正后点击“重试失败项” |
| 是否需要下载模型 | 新块向量化/有效向量或混合查询需要 M3E；模型重排另需 BGE；页面启动与已有知识库 BM25 查询无需权重 |
| 本地 Embedding 模型不存在 | 按上方步骤下载固定版本到 `embedding.local_path`，再调用 `get_embeddings()` |

## 前端文档管理与轨迹查看

1. 点击“检索文档”右侧的“知识库”标签：左列显示文件名与前八位文档ID，编号与“ID：”同行，点击文件后右列显示该原文的完整解析内容。PDF标注物理页、Word保留段落与表格、Markdown渲染标题与表格；此处不使用检索片段或模型摘要。下方“知识库管理面板”可核对索引块数与向量化状态，块数不代表本批全部预期块导入成功。
2. 点击文件旁的“删除”，该位置变为“确认删除”和“取消”。确认后，该文档检索块被移除，原文存入本地 `.trash`；此操作影响共享知识库，历史答案和日志保留。原文缺失时需先补全，页面不会执行回收删除。
3. 在“已归档知识”选择文件名与ID，点击“恢复”，重新执行实际加载与索引，并选中恢复的文件展示内容。恢复后查看导入表，失败时点击“重试失败项”。已重新上传的同ID原文不会被恢复覆盖。
4. 中央 Agent 标签提交问题，查看用户/助手消息；RAG 标签通过聊天输入框提问，逐步展示 Markdown 答案及文档名/真实位置引用，展开来源查看原文。两种历史分开显示。
5. 底部轨迹图按实际调用ID关联分支与结果；各轮明细展示公开决策说明、参数、结果、异常恢复和终止条件，Token和工具成功率均来自实际事件。页面重跑只重绘已有请求。

## 对话历史管理

1. 左侧“对话历史管理”点击“新建会话”，Agent 与 RAG 两个标签同时进入空会话；知识库继续共享。
2. 在“历史会话”按首条问题及短会话编号选择记录。Agent 载入该会话问答、记忆和最近一次公开轨迹；RAG 载入已保存答案与引用，切换不会重新生成。
3. 保留或收藏当前完整地址。刷新、重开该地址可找回同一访客的会话；仅打开不含访客标识的首页会建立新访客。地址中的随机标识用于本机演示历史入口，不能代替登录认证，不应作为多用户公开服务的权限机制。
4. 点击“删除当前会话”，核对名称后“确认删除会话”，该会话进入回收区并切换到另一会话；最后一个会话删除后自动新建空会话。也可点击“取消删除会话”。
5. 在“会话回收区”选择原编号并点击“恢复会话”，同一编号的问答、引用和摘要可继续使用。删除不清理知识库或请求日志；回收记录仍占本地数据库空间。

切换会取消尚未确认的低相关性请求，并清空上一会话的答案缓存、输入草稿和待删除状态。RAG“清空当前对话”只删除当前会话的 RAG 历史与缓存，Agent 记忆保留。保存失败会明确提示，页面答案不等于已经持久化；检查数据库后再操作。旧数据库自动迁移，历史正文保留；未曾保存过的状态与轨迹不会补造。详见[会话历史QA](QA/5.4.3%20对话历史管理.md)。


## 知识库列表与向量化状态

“知识库”标签左列列出已保存原文及已有索引的文献，显示文件名与八位ID；右列显示选中原文及向量化状态和当前块数。点击“刷新知识库状态”重新读取本地数据，不重新向量化、生成回答或切换会话。

在“知识库”标签下方展开“知识库管理面板”，查看总文档数、已向量化文档数、总块数及逐文档表格。表格可以横向滚动、搜索和导出；表内显示前八位文档ID，可用于限定文献检索，内部仍保存完整编号。

“已向量化”仅表示有索引块，不保证全部块写入成功。请同时核对当前批次导入结果、预期块数和错误；写入失败但保留部分块时仍显示实际块数。刷新浏览器后本页批次结果未知显示“—”，原文/向量化状态仍从磁盘与Chroma读取。索引不可读会明确报错，不显示虚假的零统计。原文缺失但索引仍在时，两种状态分别标注。

同内容不同文件名按指纹合并，回收文档不计入活动列表；未通过解析/未保存的上传文件只列在本批失败表中。失败时沿用左侧“重试失败项”，删除与恢复沿用前述操作。字段与真实截图见[知识库面板QA](QA/5.4.3%20知识库管理面板.md)。

### 人工评阅180条答案

使用[180条评分表](../reports/5_5_2%20系统性能评估/答案质量人工评分表_180条.xlsx)，覆盖default与no_rules基线120条、optimized优化60条，三个配置各60题。原120条表保留为历史版本，正式评阅使用180条表。

1. 在“答案与依据”查看问题、参考答案、评分要点和实际答案；按论文清单打开原PDF对应物理页，不能只看模型输出的来源名称。
2. 在“人工评分”填写正确性、完整性、引用准确性，均为0～4整数；0是有效低分，空白是尚未评阅。
3. 同时填写评分理由、评阅人和日期；评分完整列自动核验，不能手改公式。各项评分标准见“评分标准”工作表。
4. 保存副本后回传，保留原表以复查。汇总程序拒绝重复题号、错误配置和半填记录；未评分不计为0分，均值仍未知。
