# 用户使用手册

智能科研助理提供“科研对话、文档检索、知识库”三个标签。先上传论文并建立索引，再由Agent回答；文档检索用于查看原文块，知识库用于浏览与管理原文。

## 1 启动与模型准备

已有Python3.10.10虚拟环境时无需重建。在项目根目录执行：

```bash
# 首次创建；已有环境可省略前两行。
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run src/frontend/app.py
```

打开[本机页面](http://localhost:8501)。Windows安装／下载／PowerShell流程见[Windows部署教程](Windows部署教程.md)，可直接使用`.venv\Scripts\python.exe`避免激活问题。

| 用途 | 本地资源 |
| --- | --- |
| 向量化／向量与混合检索 | data/models/m3e-base |
| 混合＋模型重排／科研文献问答 | data/models/bge-reranker-base |
| Agent／生成／摘要 | 本机Ollama与qwen2.5:7b |
| 会话窗口 | data/models/qwen2.5-tokenizer/tokenizer.json |

模型版本与路径以[config.yaml](../config.yaml)为准，下载步骤见Windows教程，选型与固定revision见[QA](QA/README.md)。复制权重后核对文件完整性；不能将Mac虚拟环境或运行包直接复制给Windows／Linux。缺权重明确报错，不自动下载或转云端。

Mac已有项目内Ollama运行包时，在另一终端从根目录启动：

```bash
# 仅适用于本机已准备的Mac运行包，保持终端运行。
OLLAMA_MODELS="$PWD/data/models/ollama/models" OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 OLLAMA_NUM_PARALLEL=1 data/models/ollama/runtime/ollama serve
```

页面启动、读正文和BM25无需加载模型；生成前需Ollama，入库需M3E，模型重排需BGE。侧栏“系统状态”显示时间、目标LLM模型与Chroma，检查连接正常不等于答案质量达标。

## 2 上传与导入

1. 左侧“文档上传与管理”中“上传文档”可多选PDF、DOCX、TXT、MD／Markdown，单份默认最多20MB。
2. 点击“开始导入”，才显示本批进度与成功／失败；成功文件从选择区清除，失败原因可展开查看。
3. 修正原因后点同一行的“重试失败项”，只对失败项再尝试一轮。索引部分失败保留原文／已写入块，重试补缺项；损坏文件或编码问题先修正后上传。

进度100%表示尝试结束，包含失败项。原文按内容指纹保存，同名不同内容分开；相同内容重复导入不重算旧向量。刷新可能清空本批状态，磁盘原文／索引保留，可重新上传补齐缺项。纯文本须UTF-8，旧`.doc`需转换为DOCX。

PDF物理页从1开始，与印刷页号可不同；支持常见双栏、规则表格／续表、文本公式及原位置。扫描件无OCR，复杂表头／多栏／图片公式需核对原PDF；DOCX使用段落／表格位置，文本使用行号。

## 3 科研对话与来源

1. 打开“科研对话”，在消息框输入问题并点击内部“发送”；输入清空，运行时转圈，正文逐步显示。可继续追问，Agent读取当前会话窗口／摘要。
2. 消息区内部滚动，每轮有独立边框，回答末尾显示本次Token与Agent响应耗时。输入框下查看本轮阶段／轮次／工具／输入输出Token／耗时／状态表；“状态统计”累计当前会话。
3. 有来源时点击“查看文档名 · 位置”核对PDF物理页，或下载原PDF；引用编号合法仍需确认原文支持该陈述。
4. 低相关候选出现后先读来源，再“确认”或“取消”。确认复用已展示证据生成；取消不调用模型。新问题、切换会话或知识库变化后旧确认失效，请重新提问。

空知识库明确提示未找到相关文档，可纯模型回复，不能作为论文证据。服务失败／断流保留部分回答并提示重试，不当完整答案。缓存命中可复用当前会话同范围的RAG答案，Agent其他阶段仍可耗Token；前轮缺失用量显示未知。

单篇摘要、元信息、关键词、论文对比、计算、时间与文献列表由Agent调用对应工具；可用文件名提问，歧义时先查看知识库或列出文献。联网搜索默认关闭，本地失败不会自动联网。

## 4 文档检索

“检索方式、Top-k、文档ID”同一行，下一行输入查询，点“检索”。可选择向量、BM25、RRF或RRF＋模型重排；默认K=5。文档ID留空搜索全库，唯一八位前缀可限定文献，冲突时使用完整ID。

结果显示原文块、来源位置与分数，不生成答案。各方式分数不可横比，也不是命中概率；BM25仅返有词项交集的块，可能不足K且保留零／负分。英文术语不同空格写法不会自动同义匹配。

“检索分数分布”来自本地RAG日志，反映BGE Top-1相关性分布，课程5.2.4要求用于诊断；不表示Hit@5或答案正确率。

## 5 知识库管理

知识库左列滚动文件列表，文件名旁显示八位ID；选中文件后右侧滚动显示完整解析内容。下方直接显示管理面板：文件名、ID、原文状态、向量化状态、索引块数。已向量化仅表示当前存在块，不保证整篇完全导入。

- 删除：文件旁“删除”原位变为同尺寸“确认删除／取消”。确认移除检索块，原文进本地回收目录；共享知识库受影响，已有对话／日志保留。
- 刷新：列表下“刷新知识库状态”重新读取磁盘／索引，不重新生成或向量化。
- 恢复：在“已归档知识”选择文件名＋八位ID，点击“恢复”，实际重新加载／构建索引；失败回上传区重试。

原文缺失／指纹改变会报错，不能假显示全文；恢复不覆盖已重新上传同ID原文。

## 6 会话管理

左侧“新建会话”开启空对话；点击“最近”中的标题切换，当前高亮，问答／引用／执行表／统计一起恢复，不再次调用模型。

“删除当前会话”原位变为确认／取消，切换会话取消待删除；确认归档，最后一个会话删除后新建。“恢复会话”选择标题＋八位ID，再点“恢复”，继续使用原问答／摘要。

保留完整访客URL可刷新找回演示历史，该标识不是登录认证。切换清空草稿／候选确认，知识库继续共享；数据库保存失败明确提示，页面答案不表示已持久化。

## 7 Docker与配置

已准备Linux适用镜像、依赖和本地模型后，从根目录执行：

```bash
# 一个Streamlit业务应用与本地Ollama运行时。
docker compose -f docker/docker-compose.yml up -d --build
docker compose -f docker/docker-compose.yml ps
docker compose -f docker/docker-compose.yml logs --tail=80
# 停止后挂载数据保留。
docker compose -f docker/docker-compose.yml down
```

页面映射本机8501，data／logs持久挂载；容器内部Ollama地址覆盖为http://ollama:11434，配置文件不改写。首次构建需联网，运行按内部网络离线设计；默认CPU，完整容器业务／断网／重开验收尚未完成，当前按用户要求暂停部署测试。记录见[项目交付](../reports/5_5_4%20项目交付/README.md)。

日常配置统一在config.yaml：默认递归512／64、Chroma／Top-5／候选20、LLM0.1／0.9／40；原文data/raw、索引data/index、会话data/sessions/memory.sqlite3、日志logs。更改模型／索引配置不能混用旧向量；模型参数变化后重启进程，保留原数据再在新目录构建。

## 8 常见问题与评阅

| 情况 | 操作 |
| --- | --- |
| LLM异常 | 确认Ollama运行、目标模型已安装及本机地址配置，再检查服务状态 |
| 缺权重／词表 | 按教程准备本地文件，核对路径／revision后重启 |
| 导入失败 | 展开失败原因；检查格式、UTF-8、大小、文件损坏，再重试失败项 |
| 原文有但无向量 | 核对上传失败项；重新导入补索引，不以原文存在判断入库成功 |
| 检索不到／低相关 | 检查文献范围与实体，尝试关键词或调整问题；确认原文确有依据 |
| 引用无效／答案错误 | 查看原文，保留问题／答案／日志作Bad Case，不能只凭来源按钮判正确 |

人工评阅使用[180条正式评分表](../reports/5_5_2%20系统性能评估/答案质量人工评分表_180条.xlsx)，基线120＋优化60。逐题核对参考答案与原PDF，填写正确性／完整性／引用准确性各0～4整数、理由、评阅人和日期，保存副本回传；0有效，空白未评。目前0/180已评，均值未知。实际成员资料与总计100%贡献也由本人提供。

开发接口见[QA](QA/README.md)，实验复现见[reports](../reports/README.md)，自动测试见[tests](../tests/README.md)，普通使用无需运行评测脚本。
