# 用户使用手册

当前版本支持 PDF、Word（.docx）、TXT/Markdown 的批量上传、正文加载、保存、自动分块、M3E 批量向量化、Chroma 增量索引、进度显示和失败项重试。导入成功表示原文已保存、全部预期块已处理并写入索引；新增文献保留旧索引，重复块不重新编码。智能问答、引用与对话会话尚未接入。

## 1 本地启动

从项目根目录执行：

当前项目环境为 Python 3.10.10；使用 pyenv 时，根目录 `.python-version` 选择该版本。已有配置好的 `.venv` 可直接激活，只有首次创建或重建时才执行创建命令。

```bash
# 创建隔离环境，避免修改系统 Python 依赖。
python3.10 --version  # 应输出 Python 3.10.10。
python3.10 -m venv .venv
source .venv/bin/activate

# 安装运行依赖，并启动文档导入应用。
python -m pip install -r requirements.txt
python -m streamlit run src/frontend/app.py
```

Windows PowerShell 的激活命令为 `.venv\Scripts\Activate.ps1`，其余 Python 命令相同。

浏览器打开 http://localhost:8501。在左侧上传文档，在主区域查看本批入库结果和五个课程模块的开发状态。页面启动不加载模型；点击导入前需按下文准备本地 M3E 权重。无需启动 Ollama 或数据库服务器，Chroma 使用本地文件。

Python 支持范围与安装方法见 [Streamlit 官方安装文档](https://docs.streamlit.io/get-started/installation)。当前直接依赖版本固定在 `requirements.txt`；完整业务实现时还需补齐模型库及完整环境记录。

## 3 文件与配置

- `config.yaml` 的 `app` 控制页面名称与描述，`importing.max_file_size_mb` 控制单份文件大小，默认 20 MB；LLM、Agent 等字段仍是后续参数样例。
- `chunking` 控制页面和 Python 索引流程的默认策略、字符大小和重叠，当前为 `recursive`、512、64。
- `embedding` 已启用：选定 `moka-ai/m3e-base`，权重位置为 `data/models/m3e-base`，默认 CPU、批大小 32，版本固定在 YAML 的 `revision`；推理只读本地模型。
- `paths.raw_documents` 指定原始文献目录，默认 `data/raw/`，按“内容 SHA-256/原文件名”保存，避免同名不同内容互相覆盖；`paths.vector_index` 指定 Chroma 目录，默认 `data/index/`。
- `retrieval` 已启用 Chroma、集合名 `paper_chunks`、`search_ef=100`、4 个索引线程与默认 Top-5；候选数与重排模型留待后续模块使用。
- `logs/` 预留给运行日志。
- 原始课程资料保留在 `docs/`，不会自动导入论文知识库。

### 批量导入操作

1. 左侧“选择多份文档”支持 `.pdf`、`.docx`、`.txt`、`.md`、`.markdown`，可一次选择多份文件；单份默认不超过 20 MB。
2. 先确认本地 M3E 权重已准备，再点击“开始导入”。系统逐份执行“加载中→分块中→向量化与索引中→成功/失败”。第一次有效索引会加载模型，之后同进程复用。
3. 查看结果。进度 100% 表示本轮全部尝试完毕，失败项也计入；成功与失败数量另行显示。表格显示内容单元、分块数、已处理块、本次新增块和写入后的全库块数。内容单元是加载结果；已处理块包含重复项，本次新增不含旧块。库中块数是该文档最近一次写入后的快照。
4. 遇到失败，可修正原因后点击“重试失败项”。每次点击仅对失败文件尝试一轮，成功文件不重做；索引失败保留原文、加载结果和已写入块，重试只补缺失块。损坏文件或编码错误应先修正后重新上传，TXT/Markdown 需为 UTF-8。模型缺失需按下文准备权重，索引配置不匹配需新目录重建。

同名且内容相同的文件在本批合并。全部尝试结束后，相同选择的“开始导入”禁用；普通页面重跑不会重新执行导入。新选择的文献追加到原集合；重新选择同一原文新增为零，不重算已有向量。任务状态只保留当前页面会话，刷新或断开后可能清空；原文与已写入索引保留，重新上传可补齐缺失块。当前仅展示本批任务，全知识库管理与删除面板待实现。实现与故障恢复证据见 [批量索引 QA](QA/5.1.3%20批量向量化与增量索引.md)。

### 学术 PDF 的处理范围

常见居中双栏按区域读完整左栏后再读右栏；网格表和规则三线表作为独立表格内容，符合条件的跨页续表合并并保留逐行页码。公式保留文本符号和可识别上下标；复杂分式或图片公式保留原 PDF 与位置，不自动转为 LaTeX。多级表头、合并单元格或不规则栏布局仍需对照原文核验，未进行公式 OCR。当前界面展示导入状态，尚未提供公式/表格预览面板。具体边界见 [学术 PDF 解析优化](QA/5.1.2%20学术论文PDF解析优化.md)。

### 三种分块的 Python 调用

在项目根目录、已激活 `.venv` 的 Python 中执行：

```python
from src.data_loader import load_document
from src.chunking import split_documents

documents = load_document("data/raw/论文.pdf")  # 替换为实际文件路径。
chunks = split_documents(documents)  # 使用 YAML 的 recursive、512/64 字符。
for size in (256, 512, 1024):  # 只有固定切分比较三种大小。
    chunks = split_documents(documents, strategy="fixed", chunk_size=size)
    print("fixed", size, len(chunks))
for strategy in ("recursive", "semantic"):  # 其余策略使用 YAML 默认参数。
    chunks = split_documents(documents, strategy=strategy)
    print(strategy, len(chunks), chunks[0].metadata)
```

`chunk_size` 必须为正整数，`chunk_overlap` 满足 `0 <= chunk_overlap < chunk_size`。固定切分按窗口移动；递归切分按段落、换行、标点到字符逐级处理；语义切分优先保留段落，长段落拆句，超长单句按字符兜底，不需下载模型。

固定正文重叠精确等于设置值；递归和句段策略只在完整切分单元间选重叠，实际可能更少或为零。独立 PDF/Word 表格整块保留，可能超过大小上限。块保留来源并新增 `chunk_id`、`start_index`、`end_index`；字符区间相对父内容单元，末尾不含在区间内。TXT/Markdown 行号细化到块；Word 不产生物理页码。规则说明见 [三种文本分块策略](QA/5.1.2%20三种文本分块策略.md)。

### 本地 Embedding 的准备和调用

本机已经准备 M3E 权重。首次在其他电脑使用时，在项目根目录、已安装依赖的环境中执行以下 Python 代码，仅下载选定模型：

```python
from huggingface_hub import snapshot_download
from src.utils.config import load_config

config = load_config()["embedding"]
snapshot_download(
    config["model"], revision=config["revision"], local_dir=config["local_path"],
    allow_patterns=["*.json", "vocab.txt", "model.safetensors"],
)
```

权重准备需要联网，约 409 MB；`data/models/` 已忽略，不提交到 Git。准备完成后可离线调用：

```python
from src.retrieval.vector_store import get_embeddings

embeddings = get_embeddings()  # 首次加载，之后在同一进程内复用。
vectors = embeddings.embed_documents([chunk.page_content for chunk in chunks])
query_vector = embeddings.embed_query("论文使用了什么实验方法？")
print(len(vectors), len(query_vector))  # 查询向量维度为 768。
```

M3E 对查询、正文均直接编码，不加 BGE 的检索前缀；中英文使用同一接口，例如 `embeddings.embed_query("Which optimizer does the paper use?")`。模型输出归一化浮点列表，最大输入为 512 Token；超长文本会被截断，这与分块的 512 字符不是同一单位，超长表格仍需后续处理。基于中英文人工智能论文的对比后保留 M3E，但英文及跨语言检索质量仍不足；四组实测、速度与选择理由见 [Embedding QA](QA/5.1.3%20Embedding模型对比与选择.md)。

配置路径按项目根目录解释。缺少模型目录会明确报错，损坏权重不会自动转云端；修改模型配置后重启进程，避免复用旧实例。页面启动无需加载模型，但点击导入构建索引时需要本地 M3E 权重。

### Chroma 索引与检索的 Python 调用

已准备本地 M3E 后，从项目根目录运行：

```python
from src.data_loader import load_document
from src.chunking import split_documents
from src.retrieval.vector_store import VectorStore

chunks = split_documents(load_document("data/raw/论文.pdf"))  # 改为实际路径。
store = VectorStore()  # 首次加载模型；数据库文件写入 YAML 指定的 data/index/。
print("实际新增：", store.add_chunks(chunks))  # 重复执行不会重新编码旧块。
print("全部块数：", store.count())
for document, score in store.search("论文使用了什么方法？", k=5):
    print(document.metadata, score, document.page_content)

# 限定一篇文档检索与读取，适用于后续论文对比和管理。
doc_id = chunks[0].metadata["doc_id"]
results = store.search("What method does this paper use?", doc_id=doc_id)
stored_chunks = store.list_chunks(doc_id)
# 按需删除该文档的索引，原始 PDF 保留。
# print("删除块数：", store.delete_document(doc_id))
```

再次启动 Python，重新构造 `VectorStore()` 即可读取持久化索引，无需全量重建。查询返回原正文和来源，以及余弦相似度；分数不是置信概率。空库或空问题返回空列表。增量导入按稳定块 ID 去重；改变分块策略或内容会生成新 ID，替换同一文档的分块方案时应先按旧 `doc_id` 删除索引，再添加新块。

修改模型版本、距离或索引参数后，旧集合与配置不一致会明确报错。将 `paths.vector_index` 改为新目录后，从原文重新分块和编码；旧目录保留，便于核验。不手动修改或删除 Chroma 内部文件。两库实测与选型见 [向量数据库 QA](QA/5.1.3%20向量数据库对比与选择.md)。当前页面可自动入库，尚无向量搜索或知识库删除面板；完整 Python 批量接口示例见 [批量索引 QA](QA/5.1.3%20批量向量化与增量索引.md)。

## 4 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 提示缺少 streamlit 或 yaml | 在激活环境内重新执行 `python -m pip install -r requirements.txt` |
| 8501 端口已占用 | 追加 `--server.port=8502`，然后访问对应地址；Docker 需调整宿主机端口映射 |
| 配置文件找不到 | 确认 `config.yaml` 位于项目根目录，入口仍在 `src/frontend/app.py` |
| 页面不能提问 | 当前只提供文档导入，问答尚未实现 |
| TXT/Markdown 显示 UnicodeDecodeError | 将文件转换为 UTF-8 后重新上传；重复重试不会修正编码 |
| PDF/Word 解析失败 | 检查文件是否损坏、格式是否正确；需要密码或无文本的 PDF 不支持当前加载器 |
| 导入显示读写错误 | 检查原始文献保存目录是否可写，修正后点击“重试失败项” |
| 是否需要下载模型 | 页面启动无需权重，上传索引与 Python 向量化需先按上方步骤准备 M3E |
| 本地 Embedding 模型不存在 | 按上方步骤下载固定版本到 `embedding.local_path`，再调用 `get_embeddings()` |
