# 智能科研助理课程报告

本报告按课程模板整理真实实现、实验与交付证据，资料截止2026年10月4日。人工评分及成员身份、贡献比例仍待真实提供，不以自动指标代替。

## 一 项目概述

### 1.1 项目背景

科研人员需要从多篇专业论文中查找方法、数据集和实验结论。通用大模型可能缺少私有文献知识，回答也可能没有可靠依据。本项目以本地论文知识库为基础，用检索增强生成提供可追溯问答，再由 Agent 选择检索、摘要、对比和计算工具，辅助完成科研文献分析。

### 1.2 项目目标

完成文献导入、三种分块、增量向量索引、混合检索与模型重排、带来源生成、工具决策、多轮记忆和交互界面；通过实际评测识别不足，保留失败与优化数据，交付源码、技术设计、用户手册、课程报告、评测数据、容器文件和演示材料。采用本科生可解释的单应用结构，不将课程模块拆成微服务。

## 四 技术实现记录

### 4.1 模块一 文档处理与检索层

PDF 选择 PyMuPDF。按用户要求只查询官方资料比较 PyPDF2、pdfplumber、PyMuPDF，没有实现另两个解析器，也没有把资料比较写成三库同机性能实验。解析器读取正文及位置，常见双栏按列和段落排序，规则表格单独保留并关联续页来源；可提取公式文本，同时保留页码与原文定位。扫描 PDF 的 OCR、任意复杂跨页表格和公式语义解析不在当前实现中。

Word 通过 python-docx 读取段落与表格，纯文本读取 TXT、Markdown。批次逐文件显示加载、分块、向量化与索引阶段；100% 表示全部尝试完成，失败另计。新文件按 SHA-256 分目录保存。失败项重试保留已保存原文和已写入块，只补缺失部分；整份文档不提供事务回滚。

五组完整实验共300次实际查询、K=3/5/10的900组指标复核通过。递归512/64的Hit@5为66.67%、Recall@5为42.97%，五组最高；固定512的MRR@5为0.3708更高。保留递归默认与Top-5，不宣称所有指标最优或达到85%。时间记录有共享负载和断点恢复限制，fixed1024最初构建耗时未知。

三种分块共享稳定来源与块 ID。固定按字符长度切；递归沿用 RecursiveCharacterTextSplitter；句段策略按段落及中英文句子边界，超长单句按字符兜底。表格作为完整内容单元保留，可能超出目标字符数。字符预算不等于 Embedding 的 512 Token 上限，长表格仍可能在模型输入处截断。

M3E 输出 768 维归一化向量，Chroma 持久化保存块正文、来源与向量。稳定块 ID 查重使旧块无需重新编码；新增文件只编码新块。BM25 复用库中正文，英文按词、中文按字并做全角归一化。RRF 对每路排名计算 1/(60+排名)，按块 ID 汇总，两路原始分数不直接相加。融合 Top-20 交给本地 BGE 模型精排，再返回 Top-5。

双语 AI 论文模型比较中，M3E 与 BGE-large-zh 的 Hit@5 分别为 34.38% 和 31.25%，821 块编码中位数分别为 54.439 秒和 170.747 秒，保留用户选择的 M3E。英文查中文是两模型的弱项，该结果不能证明可靠跨语言能力。

### 4.2 模块二 RAG 生成层

RAG Prompt 固定系统角色、证据上下文、当前问题和回答格式；要求依据文献回答、缺依据时说明。上下文按相关性排序，并在 6000 字符上下文与 12000 字符 Prompt 预算内截断。引用编号只对应真正送入模型的内容，再映射为文档名、物理页或 Word 段落、文本行位置；非法编号不会被静默映射到其他来源。

流式读取 Ollama NDJSON 正文，处理跨包的引用编号，完成后补齐可读来源。无完成包、网络异常或输出上限明确显示未完成，保留部分文本。语义缓存先检查相同问题，再匹配问题 Embedding，默认阈值 0.97；知识库、会话与配置指纹变化时失效。缓存可能复用原始语义错答，当前仅保证功能与来源保持，不保证缓存答案正确。

空检索回退纯模型并明确没有知识库依据；BGE Top-1 低于 0.1 时展示候选并等待确认；模型失败返回友好错误和重试建议，不转云端。日志记录请求 ID、问题、实际 Top-K、送入上下文、答案、状态、耗时和实际用量。Top-1 sigmoid 分数分布是排序诊断，不是回答正确概率。八组生成参数的 160 条真实回答实验后保留 Temperature=0.1、Top-p=0.9、生成 Top-k=40。

### 4.3 模块三 Agent 决策层

Thought 生成简短公开决策与下一步计划；Action 根据被选工具的 Schema 生成参数，再实际执行；Observation 读取结果，输出继续、完成或信息不足。最多 8 轮；相同及交替重复调用都有上限。System Prompt 描述角色、实际可用工具与 JSON 输出约束，不要求披露模型私有思维过程。

八工具通过简单注册列表调用。论文 ID 必须为已上传内容指纹；文献列表将 ID 交给后续元信息、摘要或对比工具，避免模型生成“ViT”等伪 ID。计算器限定表达式 AST 节点，不用 eval 执行代码。时间读取系统时区，论文分析返回真实依据和必要缺失说明。

同轮最多两个独立调用可并行执行，包括同名检索工具的两组不同参数。完全相同的重复调用仍拒绝；并行计划与实际调用按数量匹配。超时仅有界等待，正在运行的线程不能强杀；重试只针对允许的错误，失败后禁用工具并让下一轮选择替代，不能无限自愈。

SQLite 按访客和会话隔离历史，user_id 的归属检查不是完整登录认证。历史使用 Qwen 官方词表计数，按整轮截断到 2000 Token；超过 10 轮时对旧历史生成摘要并保留最近 4 轮。摘要失败退回窗口并提示，功能验证不能替代摘要语义准确性评测。

Observation 支持真实正文包增量，只展示 answer 字段，隐藏未完成 JSON 的其他字段。增量不重复累计 Token，也不保存半轮历史；最终完成事件校验状态和来源，并将单次完整 RAG 答案按原文引用规范保留。断流保留部分文本并标记未完成。

### 4.5 模块五 评测

研究方向为 Transformer 在图像分类与目标检测中的应用，论文包括 ViT、DeiT、Swin、PVT、T2T-ViT、CaiT、DETR 及其变体。12 篇公开完整论文共 179 物理页；60 题按事实、对比、归纳、推理各 15 条，中英各 30 条。每题有参考答案、评分要点和证据位置。原文全部英文，ViT 与开发资料重叠，参考答案待独立人工复核，不能称完全独立来源盲测。

在默认递归 512/64 的 1694 块上，纯向量、混合、混合加重排的 Hit@5 分别为 40.00%、36.67%、66.67%；MRR@5 分别为 0.2503、0.1911、0.3536；页级 Recall@5 分别为 23.94%、23.25%、42.97%。候选 10/20/40 中，20 在本集效果最好。单独混合并未改善全部指标，不能宣称 RRF 必然提升。

![检索效果与配置](../reports/5_5_2%20系统性能评估/检索配置与质量.png)

初始默认 Agent 路径准确率 81.67%、平均 1.5833 轮、平均完整响应 44.264 秒、实际 Token 均值 14506.40。关闭规则路由仍是 Agent，不能作为“固定 RAG”对照。Token 取 Ollama 实际计数，失败题保留；路径准确率不代替参数正确、任务完成或答案质量。

四类 Bad Case 包括漏召回、模型事实错误、错误来源、Agent 选错工具或无效循环。十例保留原文、结果和根因，对 ID 交接与单次完整 RAG 引用保持实施一轮优化，后测完整 60 题。路径准确率提高到 88.33%，平均轮次降至 1.3833，Token 均值降到 12956.15，约减少 10.69%；平均响应 47.6983 秒，增加 7.76%。无效必填 ID 调用 15→0，重复终止 5→0，条件 RAG 来源文本保持 0/22→22/22。语义错答仍在，不能以这些结构指标宣称答案准确率提升。

| HybridRetriever.search | 查询 K rerank | RRF 融合及可选 BGE 精排结果 |
| prepare_rag_context 与 stream_answer | 问题 真实候选 | 预算内上下文、引用映射、正文与完成错误事件 |
| run_react 与 run_session | 问题 工具 Context 会话 | 决策、调用、结果、观察、正文增量与 done |
| MemoryManager | 访客 会话与历史 | 归属检查、窗口、摘要与持久化记录 |
| check_health 与 read_pdf_page | 配置或真实引用 | 模型及索引独立状态；原 PDF 页图像与下载数据 |

消息采用 LangChain HumanMessage、AIMessage、ToolMessage，论文内容采用 Document。Context 使用简单字典，含 question、history、observations、iterations、task_complete、full_response、usage；统一事件的 request_id、call_id 关联日志与指标，缺失用量不补零。

### 5.3 核心数据流向

导入：文件大小校验→SHA-256 保存原文→解析 Document→分块→只编码新块→持久化 Chroma→刷新 BM25 与缓存范围。问答：当前会话历史→Agent 规划→工具参数校验→实际检索或论文工具→观察判断→带来源答案与公开轨迹→SQLite 保存完整问答。直接 RAG 标签走缓存、检索和生成，展示历史但不将历史送入多轮推理。

### 5.4 配置文件说明

config.yaml 是唯一运行配置。Embedding 模型固定 revision、CPU、批次32；检索 Top-5、候选20、RRF常数60。模型窗口8192 Token、输出上限512 Token，检索上下文预算6000字符、整份提示词预算12000字符，字符数不等于Token数；Temperature0.1、Top-p0.9、生成Top-k40。Agent 最多8轮、并行上限2、工具超时300秒、重试上限1；历史窗口2000 Token，10轮触发摘要并保留最近4轮。默认单文件上传20 MiB。

容器仅用 RAG_OLLAMA_BASE_URL 将同一配置里的服务地址覆盖为 http://ollama:11434，程序只允许回环地址或容器内固定服务名；不支持任意云端地址。原文、索引、会话和日志分别来自 paths 字段，模型权重在 data/models，运行期不自动下载。

## 六 总结与展望

### 6.1 项目总结

项目完成从多格式文献到混合检索、带出处生成、Agent 工具决策和多轮界面的主要链路。通过手写 RRF 和 ReAct，可说明召回融合与有界任务决策的过程。评测表明模型重排能改善本集检索，ID 交接与来源保持能减少结构错误；时延和语义质量仍有明确局限。课程材料中的 85% 命中率、80% Token 节省和成本数字没有在本项目中被默认当作已取得成果。

### 6.2 主要困难与解决方案

复杂 PDF 的双栏、表格与公式需要保留位置，使用坐标排序与表格内容单元处理，仍记录无法可靠解析的情况。中英跨语言召回不足，模型双语对比后保留 M3E，再用 BM25 和 BGE 补充；不把小样本选择推断为普遍优势。Agent 曾生成伪论文 ID、丢失引用和重复空转，加入真实 ID 列表与唯一别名约束、单次完整 RAG 答案保持及循环终止，并用完整 60 题复测。

流式 JSON 跨包会出现转义、半个 Unicode 和不完整正文，只增量解析公开 answer 字段，完成后验证其余字段；断流保持未完成。引用按钮不能依赖索引必然保存 file_type，改用文件扩展名与物理页，读取时再核对真实 SHA-256。历史事件已保存但按钮需重新绘制，因此将原文入口接入本轮与 SQLite 历史两条路径。

实验数据中的整页字符坐标造成排名文件膨胀，保留评测需要的正文、ID 和页码，从有效断点续跑，并用原子写入避免半份结果。全部已有题目和索引保留，不依据效果修改标注。文档渲染发现中文字体不可见，使用临时字体配置检查页面；原课程资料保持不变。

### 6.3 待改进方向

完成实际人工评分与参考答案复核后，再评价语义质量。优先处理跨语言漏召回、多论文证据覆盖、对比字段混淆、无依据推断和错误答案缓存。扩大独立来源与重复实验，报告方差；复杂版式可另行研究 OCR 和公式处理。多用户仅验证小规模演示隔离，正式部署还需要身份认证、权限与容量规划，不能用访客地址替代登录系统。
