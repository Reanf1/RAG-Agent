## 1 参考与取舍

- 已阅读固定上游 [search.py](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/tools/search.py)、[weather.py](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/tools/weather.py) 和 [工具测试](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/tests/test_tools.py)。沿用 `@tool`、简单注册列表、实际 `invoke()`、HTTP 超时、HTML 解析与 `uddg` 链接解包。上游没有课程要求的论文结构化摘要或独立系统时间工具，二者为课程补充。

- 摘要读取上传原文，复用现有加载器、分块、上下文预算和引用解析；不要求先建立向量索引，也不新增另一套 RAG 引擎。只调用已有本机 Ollama + Qwen2.5:7b，不转云端。

## 2 工具接口与处理流程

| 工具 | 输入 | 真实输出 |
| --- | --- | --- |
| `paper_summary` | `doc_id`：上传原文件的 64 位 SHA-256 指纹 | `sections` 四栏、展示答案、真实引用/位置、缺项/截断提示、模型/实际 Token 和耗时 |
| `current_time` | 无参数 | `system_time`：含 UTC 偏移的 ISO 8601 字符串；`timezone`：系统时区名称；生成 Token 为 0 |
| `web_search` | 非空 `query`，且配置启用 | 最多五条 `title/snippet/url`、提供方、查询时间、耗时；无结果或真实错误 |

### 2.1 结构化摘要

1. `_uploaded_paper()` 检查上传目录、支持格式及原始内容指纹；未知 ID、任意路径与已改变的原文不能进入模型。
2. 使用现有 PDF/DOCX/TXT/Markdown 加载和默认分块。开头五块中识别独立 `Abstract/摘要` 标题时从该块开始，排除其前仅含标题/作者等的块；未识别时从开头开始。优先放入开头五块，再放入可识别 `Conclusion/Conclusions/Concluding remarks/结论/总结` 标题与后续两块，其余按原文顺序补足。
3. `build_context()` 沿用 6000 字符上下文预算与动态截断。此处按读取顺序处理，不是检索评分；内部排序占位值从返回来源中删除，不冒充 BGE 置信度。未送入的内容及排除的开头块通过 `input_truncated` 明示。
4. 一次本地 JSON 结构化生成：`background/method/results/conclusion`，每栏 `text` 与 `reference_ids`。提示要求一句中文、80 字以内，程序和 Schema 上限为 100 字；引用最多两个且必须是本轮真实、不重复的整数编号。
5. 程序补入“背景—方法—结果—结论”标题并调用已有 `resolve_citations()` 填真实文件名/位置。PDF 使用物理页码，Word 使用段落/表格位置，文本使用真实行范围；不信任模型自己填写的页码。
6. 缺证据返回空文本/空编号，展示“资料不足”，整体状态 `insufficient_evidence`。既有 Observation 会拒绝将该状态误标为任务完成。模型未正常停止、输出截断、非法字段/编号和 API 故障进入执行器真实 `error`，不使用部分摘要或重试。

返回的 `sections` 是模型生成的摘要，与 `paper_metadata` 中直接取自原文的 `abstract` 不同。已获得的 Token 取 Ollama 响应；未获得用量为 `null`，不会补成 0。摘要依据为预算内原文，不是全文精读或文献综述。

### 2.2 当前时间

使用 Python `datetime.now().astimezone()` 读取运行机器时钟和本地时区；不写死日期或北京时间。`system_time` 包含偏移，避免只用 `CST` 等缩写造成时区歧义。工具自身不调用模型或联网，因此用量为 0；Agent 规划、Action 和 Observation 的模型调用仍有各自真实用量。

### 2.3 联网搜索与注册

`AVAILABLE_TOOLS` 只包含六个本地工具；`get_available_tools()` 每次读取 `agent.online_search_enabled`，只有 YAML 布尔值 `true` 才附加 `web_search`。`run_react()` 默认使用该实际列表；显式 `tools=[]` 仍禁用工具。搜索内部再次核验开关，手动传入工具列表不能绕过禁用。

启用方法：将 `config.yaml` 中现有的 `agent.online_search_enabled: false` 改成 `true`。本次没有修改默认值。调用时只发送查询词到 `https://html.duckduckgo.com/html/`，沿用 `q/kl=cn-zh` 参数和 15 秒超时；解析结果标题、摘要与解包后的 HTTP(S) 链接，不请求链接全文。网页摘要是外部搜索材料，没有本地论文页码。

明确的 `.no-results` 页面返回 `no_results`；验证页、非 200/未知结果页、HTTP 错误和连接/超时错误明确报错，执行器保存 `status=error`、原始详情和真实耗时。不会将被阻挡的页面当成空结果、伪造搜索回答、自动重试或自动启用联网。

```python
from src.agent.tools import current_time, paper_summary, get_available_tools, execute_tool

# doc_id来自已上传文件的SHA-256指纹，而不是文件名或临时示例ID。
summary = paper_summary.invoke({"doc_id": uploaded_doc_id})
clock = current_time.invoke({})
# 仅配置已启用时可成功调用；默认关闭时保存明确的未知/禁用工具错误。
search = execute_tool("web_search", {"query": "Attention Is All You Need paper"}, get_available_tools())
```

初次生成将部分参考编号指向作者/标题块，不能支持对应陈述。针对这一实际问题补排除规则与引用提示，并加入回归用例；没有覆盖首次结果。复测核心概括与可见原文相符，但仍有引用粒度问题，例如 ViT 方法额外引用的块主要谈小数据训练准确率，结论的 ResNet 比较来自相邻块而非唯一引用块。合法编号不能保证每个编号都支持整句，也不能自动保证引用完整性；正式质量评测仍需人工核对。

中文样例中的“50题、43题正确、86%”是明确构造的输入，不是本项目性能或质量实测数据；生成摘要可能省略“构造数据”的限定，应与返回原文一同查看，不能引用为项目成绩。真实论文摘要没有提供定量质量准确率。

仍有限制：标题识别是简单规则，扫描件需先 OCR；未覆盖所有摘要/结论标题变体、长作者列表及复杂版式。预算与生成 Token 上限会限制摘要内容，部分证据缺失应报告资料不足。未进行正式 50+ 问题评分、物理断网、并发或前端 Agent 界面验收。联网工具代码/故障处理已实现，本轮外部搜索服务可用性没有通过，不计为成功的实网验证。
