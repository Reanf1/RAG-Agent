# 5.4.4 边缘场景测试

测试日期：2026 年 10 月 3 日。空知识库、文件大小边界、超长历史的功能核验通过；13项磁盘/浏览器证据检查通过，全项目633项自动化测试通过。测试脚本的两项记录/判定错误已修正，原始记录保留，没有用重新生成的答案替换长对话实测结果。

## 1. 范围与配置

使用当前Python 3.10.10、单个Streamlit页面、SQLite、Chroma、本地M3E及Qwen2.5:7b；业务配置不变，原文、索引、会话与日志指向新的临时目录。阅读固定参考仓库`app/api/knowledge.py`的格式/大小校验、`tests/test_api.py`的上传测试，以及SQLite/记忆实现；不新增HTTP服务。

| 配置 | 本轮实际边界 |
| --- | --- |
| 单文件上限 | `max_file_size_mb=20`；实际比较20×1024×1024=20,971,520字节，即20 MiB。页面文字仍称20 MB |
| 历史预算 | `max_history_tokens=2000`，按本地Qwen词表统计摘要+历史JSON |
| 摘要阈值 | 未压缩历史累计10轮触发，保留最近4轮，摘要最多400 Token |
| 摘要输入/次数 | 单批占模型上下文一半，当前4096 Token；一次上下文读取最多3批 |
| 模型窗口 | `num_ctx=8192`；历史2000 Token不等于整个模型请求的预算 |

## 2. 空知识库提问

**真实Agent：**在新的0块Chroma库提问“知识库中的论文使用了什么实验数据集？请根据已上传原文给出名称和来源。”规则路由实际调用知识库工具，空检索仍调用本机Qwen；工具正文及最终答案均明确包含“当前知识库中未找到相关文档”，来源与引用为空，没有调用联网搜索。由于缺少论文依据，最终`task_complete=false`、`stop_reason=incomplete`，保存一整轮问答，库仍0块。这是正确的边缘行为，不能要求空库论文问题被标为完成。

实际耗时16.961秒，4365 Token；未伪造数据集名称或知识库来源。7项功能检查通过，模型请求、响应、公开事件与SQLite历史保存于原始报告。

**真实浏览器RAG流式：**空库提交“什么是 Transformer？请简短说明，没有文献时不要编造引用。”先显示纯模型生成提示，随后完成通用概念回答，正文固定显示无知识库文献依据，来源区为“无可引用来源”。实际0个候选、444输入Token、117输出Token，共561 Token，响应5.949秒；SQLite保存RAG历史与空引用。通用概念可回答，与上述要求论文证据的问题区分。

## 3. 超大文档与大小边界

通过PyMuPDF创建有效单页PDF，尾部补空白到指定大小；原页面文本保持不变。每份文件用真实PyMuPDF重新打开，核对页数及文本。该样例验证字节大小边界，不冒充内容复杂的20 MiB学术论文或大页数解析性能实验。

| 文件 | 字节数 | 实际加载/索引结果 |
| --- | --- | --- |
| `limit_minus_one.pdf` | 20,971,519 | 加载成功，真实M3E编码，持久化1块 |
| `limit_exact.pdf` | 20,971,520 | 恰好达到上限，成功，持久化1块 |
| `limit_plus_one.pdf` | 20,971,521 | 拒绝：“文件过大，单份最大支持20 MB”；无原文/块 |
| `oversized_21MiB.pdf` | 22,020,096 | 同样拒绝，无原文/块 |

超限文件排在有效文件前面，失败没有阻断后续文档。显式重试超限项仍失败，attempts为2；成功项不重复编码，库仍2块。磁盘重新核对两个成功源文件的大小/SHA与块元数据一致，两个拒绝文件只留在明确的`fixtures/`测试目录，未混入知识库原文目录或索引。

前端另通过Streamlit **AppTest真实上传组件与按钮**，传入20 MiB+1字节和一份有效TXT：超限项显示失败与重试入口，有效项继续入库，重试不重复编码成功项。模型在该自动化用例中用明确二维向量隔离，SQLite/Chroma/业务页面实际运行；AppTest绕过浏览器的文件大小预校验，专门验证服务端业务保护。真实M3E的边界入库另由上表实测完成。本轮未通过原生浏览器文件选择器验证超限拦截，不将AppTest称为手动浏览器上传。

## 4. 超长对话

历史由脚本明确构造并写入真实SQLite，不是50轮模型生成对话；追问、摘要及回答使用真实本机模型。

| 场景 | 原历史Token | 实际发送历史 | 结果 |
| --- | --- | --- | --- |
| 50轮普通长历史 | 7538 | 560 Token；46轮摘要、最近4轮原文 | 两次实际摘要均保存，真实追问返回最新代号；SQLite保留51轮 |
| 12轮含超大旧问答 | 19723 | 1571 Token；移出1个完整旧问答对，保留11轮 | 旧单轮超过摘要输入预算，明确警告并回退窗口；无假摘要；追问正确，SQLite保留13轮 |
| 浏览器12轮旧事实追问 | 构造历史；代号仅在第1轮 | 565 Token；8轮摘要、最近4轮原文 | 旧代号仅在摘要中，实际默认Agent返回UI_LONG_21126C17D6；SQLite保留13轮 |

50轮场景摘要模型输入分别为3658/3687 Token，输出27/52 Token；包括摘要及Agent回答的总用量11295 Token，完整响应53.380秒。包含超大旧问答的场景5708 Token、20.035秒，预算检查在摘要模型调用前拒绝巨型输入，摘要calls为空，已知用量没有补造。

浏览器使用默认八个工具注册，实际从摘要提取旧事实，未调用无关工具；7194 Token，日志完整耗时22.982秒左右（SQLite保存前的展示快照为22.981秒）。前端用量表真实显示“记忆摘要”1093输入+47输出Token；Thought/Observation分别3002/3052 Token。窗口、摘要、原始归档和最新答案分别核对，不把压缩后的摘要当作原文被删除。

本轮只验证历史输入过长，不声称任意超长当前问题、无限轮次或有损摘要一定保留全部事实。模型科学回答质量、复杂大文档的解析质量与系统容量不由这些功能样例证明。

## 5. 判定与失败记录

- 首轮空库实测通过；随后保存上传任务时，测试脚本未把LangChain Document转为JSON结构，发生序列化异常。已修正测试脚本，在新的目录/报告完整复测，首次JSON、运行日志及临时数据原样保留。
- 完整复测中50轮摘要确实保存，Context中`summarized_turns=46`、两次`calls.saved=true`，SQLite摘要正文一致。但测试脚本误要求流中出现独立`memory_summary`事件，导致其`summary_saved=false`、总判定失败。当前业务实际将摘要调用汇入metrics，没有单独yield该事件。
- 已修正判定为读取实际Context调用状态，另用只读证据核验器确认SQLite摘要/归档、模型完成包、原文大小/SHA、索引与浏览器记录。没有重新调用模型改写长对话答案；原总判定为false的报告继续保留。最终13项证据核验全部为true，其中一项聚合了原后端其他功能检查。后端原26项判定中的唯一误判已由真实Context和SQLite证据核正。
- 空库论文任务的`incomplete`和巨型旧问答的摘要警告均是预期降级，不将它们删掉或记作隐含成功。此前正常/并发测试的引用编号Bad Case仍未解决，不能据本轮将答案质量标为全部通过。

新增2项有意义回归：批量索引的边界/解析前拒绝/失败重试及成功向量不变；前端超限与有效文件混合上传/失败显示/重试不重复编码。专项2项通过（1.087秒）；全项目633项通过（44.478秒）：检索202、生成126、Agent305。业务源码本轮未修改，测试脚本语法与diff空白检查通过。

浏览器刷新后的持久化与日志核验见下方刷新证据；本轮临时页面、模型服务及测试标签关闭，原始证据与临时数据保留，业务配置和默认索引/会话库状态与基线一致。
