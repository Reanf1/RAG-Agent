## 1 实现范围与参考

支持一次上传多份 PDF、Word（.docx）、TXT/Markdown，顺序加载、保存并显示进度。每份文件记录状态、尝试次数、本次耗时、正文内容单元和错误信息；失败不阻断后续文件，提供手动“重试失败项”。不增加服务、线程池或任务队列，保持本科生项目的简单结构。

沿用 [参考仓库固定版本](https://github.com/dsy1018/ai-chatbot/tree/6979d7173ed0f92910a8571dd4ca1b4a171a2c49) 的格式分发、上传大小校验和加载流程，已阅读 `app/core/rag.py`、`app/api/knowledge.py`、`frontend/app.py` 和 `tests/test_api.py`。上游采用单文件上传，本项目在现有加载器之上补批处理；不照搬 FastAPI 和 HTTP 上传接口，也不声称上游已实现本功能。

前端使用 Streamlit 官方的 [多文件上传组件](https://docs.streamlit.io/develop/api-reference/widgets/st.file_uploader)、[进度条](https://docs.streamlit.io/develop/api-reference/status/st.progress) 和 [页面会话状态](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state)，直接调用 Python 业务函数。单份默认 20 MB，前端和批量函数均校验，统一由 `config.yaml` 的 `importing.max_file_size_mb` 配置。

## 2 代码位置与接口

| 位置 | 职责 |
| --- | --- |
| `src/data_loader/__init__.py` | `load_document()` 按扩展名调用现有三个加载器；`create_import_tasks()` 创建任务；`batch_import()` 加载、保存、更新状态并产出进度 |
| `src/frontend/app.py` | 多文件上传、开始导入、进度与状态表、失败项重试 |
| `src/utils/config.py` | 按文件位置读取根目录唯一的 `config.yaml`，不依赖当前工作目录 |
| `tests/test_retrieval.py` | 既有加载器测试、新增批量导入和界面测试 |

Python 调用示例：

```python
from src.data_loader import batch_import, create_import_tasks

# 上传内容用“原文件名、原始字节”表达，不新增请求模型。
tasks = create_import_tasks([
    ("论文.txt", "论文正文".encode("utf-8")),
    ("笔记.md", "# 阅读笔记\n正文".encode("utf-8")),
])
# batch_import 是生成器，需要迭代才会执行加载和保存。
for progress in batch_import(tasks, "data/raw"):
    print(progress)  # completed/total 表示本轮已处理数量。

# 只重试失败项，每次调用对每份失败文件最多尝试一次。
for progress in batch_import(tasks, "data/raw", retry_failed=True):
    print(progress)
```

任务使用普通字典：`id`、`name`、`data`、`status`、`attempts`、`error`、`elapsed`、`documents`、`path`。`id` 为文件名与内容的 SHA-256，用于本批去重；`documents` 为加载器返回的 Document 列表，不是向量块。`elapsed` 记录最近一次尝试耗时。

## 3 状态与重试规则

| 状态 | 含义与转换 |
| --- | --- |
| `pending`（等待） | 已创建任务，尚未尝试 |
| `loading`（处理中） | 本次尝试开始，尝试次数加一；处理被中断后可再次开始 |
| `success`（成功） | 正文加载并保存完成；普通重跑和失败项重试均跳过 |
| `failed`（失败） | 解析或保存异常，记录异常类型和信息；手动重试后重新进入处理中 |

每轮进度按目标文件数计算，成功和失败都计入已处理数量，100% 表示本轮结束。重试进度的分母只包含失败项，状态表仍展示整个批次。永久损坏或非 UTF-8 文件不会自动无限重试，需用户修正文件后重新上传。

## 4 保存与状态保留

先在临时目录解析；成功后保存到 `data/raw/<内容 SHA-256>/<原文件名>`，并把 Document 的 `source` 更新为实际保存路径，保留页码、段落/表格或行范围等原元数据。同名不同内容分别保存，不覆盖；相同保存位置的内容一致时复用文件，不一致时明确失败。格式、文件名路径和大小校验失败不会写入文献目录；解析临时文件自动清理。

状态通过 `st.session_state` 保留，仅限当前页面会话，不是持久任务数据库。页面重新连接或刷新后状态可能丢失，已保存文件仍保留。本批导入成功不代表向量化完成：分块、索引、检索、全知识库列表与删除仍待实现。
