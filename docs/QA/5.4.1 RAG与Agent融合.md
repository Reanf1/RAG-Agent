# 5.4.1 RAG与Agent融合

## 深度融合与来源路由

Agent统一决策，`knowledge_base_search`复用模块二混合＋BGE检索、上下文、生成、引用、缓存、降级与日志，不在Agent外先检索一遍。普通概念可直接回答，论文事实优先本地工具；指定已上传文件／ID不自动联网。

明确最新外部或联网任务只有在开关启用且搜索注册时走web_search；关闭时明确incomplete，搜索失败不以旧本地材料冒充最新事实。复合、依赖、追问保留模型规划。grounded回答缺有效引用返回insufficient_evidence，Observation不得标完成；编号校验不等于引用语义正确。

## 统一Message／Context

内部共用LangChain Message／Document，`utils/messages.py`的`messages_to_ollama()`转原生role／content和工具字段，RAG、三阶段Agent及摘要共用。`normalize_context()`统一human／ai历史及summary，拒绝无法传输值。

Context为简单字典，history、summary、history_window、memory_summary描述记忆；observations、last_observation、recovery只存在当前执行。RAG context／sources／references保持独立工具结果，不将检索证据与长期历史扁平混合。Action需把追问改成完整问题／已知ID；记忆存在不保证所有指代正确。

`run_session()`按用户／会话获取摘要＋窗口，调用ReAct并保存最终问答。页面历史还保存引用／轨迹／指标details，重绘不重新生成，模型历史仍只读正文与摘要。
