实现及核验日期：2026年10月2日；Python 3.10.10。两个工具位于`src/agent/tools.py`，正式本地注册表从6个补齐为8个；联网搜索保持默认关闭，另作可选第9个。

## 1. 参考与实现范围

编码前读取固定上游版本`6979d7173ed0f92910a8571dd4ca1b4a171a2c49`的`app/tools/weather.py`、`tests/test_tools.py`及`app/core/rag.py`的`list_documents()`。沿用`@tool`、简单注册列表、工具输入检查及独立测试方式。上游文献列表按扩展名扫描原文文件，本项目按现有SHA-256上传目录、Chroma块元数据适配；上游没有计算器，本次按课程背景中的计算示例补充。未新增依赖或文献管理子系统。

## 2. 计算器 calculator

输入`expression`为纯四则算式，支持小数、负数、括号、运算优先级及中文/符号运算符：乘以、除以、加、减、×、÷。例如：

```python
calculator.invoke({"expression": "3.14乘以2.56"})
# {"expression": "3.14*2.56", "result": "8.0384", "usage": {"prompt_eval_count": 0, "eval_count": 0}}
```

仅解释AST中的数字、加减乘除、一元正负号；不使用`eval`，不允许变量、函数、幂、整除、取模或科学计数法。算式最多256字符、AST最多128节点，非法表达式及除零通过既有工具执行器返回真实错误。数字从原文构造`Decimal`，按28位有效数字运算，结果返回字符串：`0.1+0.2`得到`0.3`，`1/3`得到`0.3333333333333333333333333333`。有限精度舍入仍适用于长数字和循环小数。

工具内部不调用模型、不联网，Token用量为0。Agent的Action生成参数及Observation组织答案仍调用本地模型，不能把工具零Token写成整个Agent请求零Token，也不据此宣称节省80%。首轮明确算式复用已有计算器路由，已有上下文或复合任务仍由模型规划。

## 3. 文献列表 paper_list

无输入，返回`papers`、`total`与零模型用量。每条文献包含：

| 字段 | 含义 |
| --- | --- |
| doc_id | 上传原文SHA-256，后续元信息、摘要、对比工具可直接使用 |
| source_file | 现有原文解析规则确定的文件名 |
| indexed_chunks | 当前Chroma中该文献实际存在的块数 |
| source_available | 当前上传原文可访问且内容指纹校验通过 |
| index_status | has_index / not_indexed / source_missing |

`has_index`仅表示至少有一个索引块，不等于全部预期块处理完成；`not_indexed`表示上传原文可用但没有索引；`source_missing`表示索引还在、上传原文已不存在。损坏原文、越界链接或索引读取异常会返回工具错误，不能伪装为空知识库。

复用配置中的原文/索引路径、`VectorStore.list_chunks()`及已有原文校验函数，按doc_id合并上传与索引信息。相同内容的多个文件名只列一条，同名不同内容分别列出；删除索引后仍列出未索引原文，删除原文后仍列出残存索引。结果按文件名及ID排序。当前知识库是共享库，工具不新增用户文献权限隔离。

仅检查已有索引文件后才打开Chroma；空知识库不会因列举而创建数据库、向量化或检索。既有块列表接口会在内存中读取块正文，工具输出仅包含元数据，适合本课程的小型知识库。

“文献列表”“上传了哪些论文”等明确列表意图接入规则路由。“哪些论文使用Transformer？”以及“列出这篇论文的实验结果”保持知识库问题，避免把内容检索误当作文件列表。先列文献再按ID提取元信息属于有依赖的多步任务，交给ReAct循环逐轮完成。

| 新增检查 | 实际结果 |
| --- | --- |
| 计算器直接执行 | 8.0384；工具零模型用量 |
| 文献列表直接执行 | 两个真实ID、文件名、94/167块与has_index状态 |
| 默认Agent计算器路由 | 调用calculator并回答8.0384，9.256秒 |
| 默认Agent文献列表路由 | 返回两个完整ID、文件名和块数，17.737秒 |
| 列表→元信息 | 先paper_list取得ID，再paper_metadata提取《Attention Is All You Need》及2017年，60.166秒 |

耗时仅为本机单次功能实测，不作为性能基准。

首次完整联调20项中18项通过，上表五项全部通过；失败记录保持原样：

1. 独立时间查询与关键词提取被模型拆成两轮串行，任务完成但未达到同轮并行要求。补充明确的独立任务并行提示后，第一次专项仍出现“不合法的主工具”规划错误；未保存该次原始模型规划包，不能推断错误字段的具体值。随后用Thought JSON Schema约束“工具步骤必须选择真实主工具、回答步骤无工具批次”，与原有Python验证一致。最终真实模型在同一轮产生两个成功的parallel结果。
2. 12轮构造长历史已真实摘要并保存，覆盖旧8轮、保留最近4轮232 Token；模型追问时却忽略摘要中的实验代号。补充“追问会话事实先检查summary/history”的角色提示；专项复用首次生成的实际Context，真实模型正确回答`EXP_DBA0F9E65B`。此复测只验证摘要读取，不冒充重新生成一遍SQLite长历史。
