# 5.4.3 前端布局与文档管理

本轮实现左侧文档管理、中央科研对话和底部 Agent 决策轨迹。维持单个 Streamlit 应用，直接复用已实现的加载、分块、Chroma、RAG 与 `run_session()`，不新增服务或依赖。

## 1 参考代码与本项目适配

已阅读固定版本的 [前端源码](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/frontend/app.py)、[知识库接口](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/api/knowledge.py) 和 `tests/test_api.py` 文档列表相关测试。沿用侧栏上传、主区 `st.chat_message`/Markdown、历史重绘和删除确认的简单组织方式。

上游单文件删除仅删除原文，明确保留向量库中的内容。本项目按文档内容指纹调用现有 `VectorStore.delete_document()`，移除目标文档块，同时回收原文，避免删除后仍检索到该文档。保留当前目录与 YAML 配置体系，不照搬 HTTP 接口。

## 2 页面功能

| 区域 | 实际行为 |
| --- | --- |
| 左侧 | 批量 PDF/Word/TXT/Markdown 上传、开始导入、失败重试、阶段状态表、实际处理进度；列出本地原文和索引中的全部文档、当前块数及原文状态；按文件确认删除与恢复 |
| 中央 Agent 标签 | 使用现有 SQLite 会话及记忆入口，展示当前页面真实问答历史；请求阶段更新底部指标，完成后显示 Markdown 最终答案，未完成任务明确提示 |
| 中央 RAG 标签 | 保留真实 Ollama token 流、打字机占位符、Markdown、动态引用及原文证据；缓存、低相关性确认、异常提示和请求日志继续生效 |
| 底部 | 根据实际事件绘制 Thought → Action → 工具结果 → Observation → 结束关系图；同轮工具分支，按调用 ID 连接返回，观察节点汇合；各轮明细显示公开决策说明、参数、真实结果、恢复及终止原因 |
| 页面后部 | 保留 Top-K 检索实验、健康检查、检索分数分布与开发状态 |

轨迹图使用横向布局，避免单条轨迹被按页面宽度放大成长图。公开说明与真实事件是可核验的轨迹，不要求展示模型私有思维。分支表示同轮工具，是否并行由实际执行记录判断。

## 3 文档删除与恢复

- 列表合并 `raw_documents/<SHA256>/原文件名` 与现有 Chroma 正文，不加载 Embedding/LLM，也不因空列表创建索引。有块不等同于全部预期块已入库；本批完成状态以任务表为准。
- 确认删除将整个目标原文目录移到 `raw_documents/.trash/<SHA256>/`，删除该 ID 的所有检索块，其他文档保持不变。原文回收失败不操作索引，索引操作抛错时归回原文。两个步骤不是跨资源事务；崩溃或部分数据库故障仍需检查原文与索引状态。
- 清除当前浏览器 RAG 缓存，移除对应导入任务并更新剩余任务进度。其他会话的缓存按现有语料哈希在下一请求失效；低相关性待确认请求仍按原机制核验语料变化。
- 恢复先核验原文内容指纹，再归回原文并调用现有批量加载/分块/向量化流程。只重建此文档缺失的块。模型失败时保留原文和失败任务，可用“重试失败项”继续；不会将原文恢复冒充索引成功。
- 不覆盖已有原文，不接收任意路径或符号链接。若同一 ID 已重新上传，则恢复不会覆盖新上传文件；回收位置冲突明确报错。
- 原文缺失的索引记录可展示，但页面禁用其回收删除，应先补全原文。知识库是本地共享库，删除影响所有会话；已有答案及日志保留，历史引用不代表当前知识库仍有该文档。回收区没有永久清空入口。
