# 5.3.1 Thought：当前状态与下一步规划

## 1 完成范围（2026-10-02）

在 [react_loop.py](../../src/agent/react_loop.py) 实现 `build_thought_messages()` 和 `think()`。读取用户问题、可用工具描述和简单 Context 字典，调用一次本地模型，输出本步简短计划、下一步类型与候选工具名。记录实际模型名、输入/输出Token和耗时。

**这里只完成 Thought 单轮规划。** 没有执行工具、生成 Action 参数或最终回答，没有完成 Observation采集、有界循环、恢复/并行、会话记忆或前端Agent接入。`agent.max_iterations`仍待完整循环接入，M3-01标记部分实现，八个科研工具不计完成。

Thought是一句可展示的决策说明，不要求或展示模型内部推理。直接回答计划的`next_step=answer`只表示下一阶段可回答或说明资料不足，本次并不返回答案。

## 2 参考与适配

已读取固定上游[Agent源码](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/agent.py)、[LLM源码](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/llm.py)和`tests/test_tools.py`等对应测试。上游先绑定工具、调用模型决策，再检查`AIMessage.tool_calls`；它没有独立Thought输出，也没有多步ReAct循环。当前沿用LangChain Message、`@tool`与工具描述，补充课程要求的单轮计划接口。

本步使用Ollama `format` JSON Schema生成计划，Python再次核对字段和工具合法性。该能力依据[官方聊天接口](https://docs.ollama.com/api/chat)和[结构化输出文档](https://docs.ollama.com/capabilities/structured-outputs)，并在本地Ollama0.34.0真实验证。**计划JSON不是已经实现的Function Calling Action**；原设计的工具参数、`ToolMessage`与有界执行循环仍在后续步骤完成。

复用已实现的本机直连`urlopen`和友好错误提示，没有新增依赖、模型、配置层或Agent执行框架；模型和采样参数取`config.yaml`现有`llm`字段。

## 3 接口与校验

```python
from src.agent.react_loop import think

# 需先启动本地Ollama；没有工具时不会编造工具。
plan = think("什么是过拟合？", tools=[], context={"observations": []})
print(plan["thought"], plan["next_step"])
```

需要工具时传入实际`list[BaseTool]`；描述包含名称、用途、参数Schema。Context可包含已有检索上下文与`observations`列表，原样放在Human消息中，不改变固定System消息、不修改调用方数据。观察结果由调用方提供，本阶段不会创建工具执行结果。

模型计划只含三个字段：

| 字段 | 含义与限制 |
| --- | --- |
| `thought` | 1～200字符的非空简短计划 |
| `next_step` | `tool`或`answer` |
| `tool_name` | 工具计划只能选择传入的名称；回答计划必须为`null` |

返回值另含`type=thought`、`model`、`usage.prompt_eval_count/eval_count`和`elapsed_seconds`；服务未提供Token时为`None`，不估算。空问题、重复工具名及错误Context提前拒绝；未知工具、额外/缺少字段、非法JSON、空/超长说明、输出截断、服务故障等明确报错。只允许本机HTTP Ollama；失败不重试或转云端。

工具列表为空时，没有RAG等隐含工具。计划是否合法不等于规划语义正确；工具结果只是参考数据，消息隔离测试也不能证明模型已抵御所有提示词注入。Token窗口/长历史截断与摘要在记忆阶段实现。
