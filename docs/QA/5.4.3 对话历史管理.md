# 5.4.3 对话历史管理

## 完成范围

2026年10月3日实现侧栏“新建会话 → 切换历史 → 确认/取消删除 → 回收恢复”。Agent与直接RAG共用所选会话编号，各自保存历史。刷新当前完整地址可从SQLite恢复，历史操作不重新检索或生成。

采用已有MemoryManager、Streamlit与SQLite，未增加依赖、登录系统或服务。M4-05中的会话管理完成；Agent最终回答逐Token流式与引用跳转仍待开发，不能将本轮标为全部前端需求完成。

## 实现与数据约定

| 文件/接口 | 实际行为 |
| --- | --- |
| `src/frontend/components/sessions.py` | 管理本访客会话，首条Agent问题或RAG问题作为标题，附短ID；校验后加载两类历史并同步地址 |
| `MemoryManager.list_sessions(user_id, archived=False)` | 只列所传用户的活动或回收会话，不混入其他用户 |
| `delete_session` / `restore_session` | 修改archived标记，保留原ID、消息、引用和摘要；回收状态下读取/追加/生成拒绝 |
| `append_turn(..., details=...)` | 同一事务保存完整问答及助手完成状态、终止原因、真实公开轨迹/指标快照 |
| `append_rag_message` / `get_rag_messages` | 保存并恢复RAG答案、实际引用、耗时、用量、错误状态等JSON |
| `clear_rag_messages` | 仅清空当前所属活动会话的RAG历史，Agent记忆和知识库保留 |
| `src/frontend/app.py` | 所选ID用于run_session和RAG请求；完成后重绘标题与历史，保存故障明确提示 |

SQLite增加 `sessions.archived`、`messages.details` 以及 `rag_history` 表，启动时仅补缺少的列/表。旧数据库保留原文、摘要、ID与消息顺序；旧消息details为 `{}`，没有记录过的完成状态和轨迹保持未知。测试覆盖旧库重复打开的迁移行为。

模型记忆仍从原正文和摘要读取，展示快照不送入Agent上下文；RAG历史单独存储，仅展示，不支持直接RAG的跨轮指代推理。历史Agent指标为保存时快照，响应耗时计到保存前；最终运行日志包含提交耗时，数值可能相差几毫秒。恢复时明确标注“历史请求快照”，不冒充新运行。

切换会清空旧会话答案缓存、输入草稿和待删除状态，并将未确认的低相关性请求记录为cancelled；不会将旧候选送入新会话。最后一个会话删除后创建空会话。删除确认面板说明影响范围，取消不会写库；SQLite故障保留原会话并提示，保存失败不能冒充成功。

## 使用边界

- 当前是本机演示：地址中的随机visitor用于找回历史，不是登录凭据。持有完整地址可访问同一访客记录，不适合直接作为公开多用户服务的认证方案；打开不带标识的首页会创建新访客。
- 回收删除隐藏并阻止继续使用，不永久擦除数据库内容；恢复保留数据，回收记录仍占磁盘。知识库与运行日志独立保留。
- 缓存、上传批次状态和未提交草稿不承诺刷新后恢复；已完成或错误的RAG答复、完整Agent问答及引用按实际成功保存的结果恢复。断开未完成请求不冒充已存整轮。
- 新代码初始化MemoryManager时执行迁移，旧程序不理解回收标记；不要让旧版与新版同时写同一会话库。
