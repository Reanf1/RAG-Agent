# 5.4.2 简单健康检查接口

实现与核验日期：2026年10月3日。提供本地LLM服务与Chroma集合的按需健康检查，沿用项目唯一配置和单个Streamlit应用。

## 1. 参考与实现方式

编码前阅读固定上游版本的[健康接口源码](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/main.py)、[响应定义](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/models/schemas.py)和[API测试](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/tests/test_api.py)。上游`GET /`直接返回`status=ok`和配置、知识库块数，并没有实际探测LLM服务。

本项目按[AGENTS.md](../../AGENTS.md)中的单Streamlit应用约定，提供`src/utils/config.py`内的`check_health() -> dict`供页面或Python代码直接调用。它是健康检查函数接口，不另建FastAPI服务或HTTP路由；不新增源代码目录、依赖或第二套配置。

## 2. 检查内容

| 组件 | 实际检查 | 未执行的工作 |
| --- | --- | --- |
| LLM | 按`llm.base_url`请求Ollama `/api/tags`，校验响应结构并确认`llm.model`在本地安装列表中 | 不生成回答、不加载模型到GPU、不下载权重 |
| 向量数据库 | 查找已有`chroma.sqlite3`，使用真实Chroma PersistentClient执行heartbeat、get_collection、模型版本/索引参数校验及count | 不创建集合、不增删改文档块、不加载Embedding、不执行向量查询 |

LLM只接受与业务生成入口一致的本地HTTP Ollama地址（localhost/127.0.0.1/::1），关闭环境代理与重定向，不转云端。HTTP连接/读取等网络阶段超时设为3秒，不沿用生成时的长等待；这不是对整个函数或本地Chroma读取的硬性总时限。

模型名没有标签时按`:latest`匹配，不能将另一个标签的模型误判为已安装。接口成功返回HTTP响应但JSON结构异常时仍判错误，不伪装成“模型未安装”。

Chroma读取使用`embedding_function=None`与关闭遥测的Settings。缺少索引时不调用会自动建库的`VectorStore()`业务构造方法，也不使用`get_or_create_collection()`。已有空集合读取到真实0块属于连接正常；尚未初始化时块数未知，两种状态区分。版本/参数不一致、缺集合、连接错误、损坏文件与无效路径明确返回错误，不自动修复或覆盖索引。

两项检查独立执行；LLM失败不会阻止数据库检查。每个组件返回真实检查耗时、状态与说明，顶层带北京时间检查时间。LLM服务可访问和模型已安装不能保证GPU、推理输出正常；Chroma可读和配置一致不能保证Embedding可用、HNSW向量查询或检索质量正常。健康检查是轻量连接诊断，不能代替完整端到端测试。

## 3. 返回状态与使用方法

| 字段 | 含义 |
| --- | --- |
| status | 两个组件均ok时为ok，其余为degraded |
| llm.status | ok / model_missing / error |
| llm.service_reachable | 是否已收到成功HTTP响应；HTTP错误或连接失败为false |
| llm.model_available | 是否确认配置模型在安装列表；无法确认时为null |
| vector_database.status | ok / not_initialized / error |
| vector_database.chunks | 正常读取的实际块数，未知为null，不能用0代替错误 |
| checked_at / seconds / detail | 检查时间、组件实际耗时和说明/重试建议 |

Python直接调用：

```python
from src.utils.config import check_health

health = check_health()
print(health["status"])
print(health["llm"])
print(health["vector_database"])
```

也可从项目根目录执行：

```bash
.venv/bin/python -c 'import json; from src.utils.config import check_health; print(json.dumps(check_health(), ensure_ascii=False, indent=2))'
```

Streamlit页面顶部新增“系统健康检查”，点击“检查服务状态”才执行检查。页面分别以正常、未就绪和错误样式显示组件结果，包含模型名、集合/块数、时间和耗时。启动页面不连接模型或数据库，重跑只重绘上次快照；再次点击按钮重新检查。上次正常快照不自动变成当前状态，停服后需重新点击检查。

## 5. 真实核验

[真实核验脚本](../../reports/5_4_2%20可观测性与健康检查/verify_health_check.py)只替换核验进程内的配置来触发异常，HTTP和Chroma调用均实际执行，不替换返回结果。现有配置的`paper_chunks`集合实际为0块，正常读取；前后块ID列表和集合元数据一致。缺失路径未创建，空库与损坏库均使用临时测试目录，生产配置和用户索引未写入。

| 实际场景 | LLM状态 | 数据库状态 | 结果 |
| --- | --- | --- | --- |
| 启动本地Ollama，配置Qwen2.5:7b，读取现有索引 | ok | ok，0块 | 两项正常 |
| 临时配置一个不存在的模型名 | model_missing | ok | 明确模型未安装 |
| 临时配置未监听的本地端口 | error | ok | 连接失败，仍检查数据库 |
| 临时索引路径尚不存在 | ok | not_initialized | 不自动建库 |
| 显式准备好的临时空集合 | ok | ok，0块 | 空库连接正常 |
| 临时SQLite文件损坏 | ok | error | 报告file is not a database，块数未知 |

核验脚本访问用户集合也只用get_collection，缺少用户库文件时提前拒绝；仅临时测试目录显式准备空库。六项复测均通过，初次记录保留；完整状态、时间与耗时见[实际结果](../../reports/5_4_2%20可观测性与健康检查/模块四健康检查最终真实核验_20261003.json)。这是连接功能核验，不是模型或检索速度基准。
