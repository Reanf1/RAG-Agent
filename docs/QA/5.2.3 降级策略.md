# 5.2.3 降级策略

验证日期：2026 年 9 月 29 日。范围为现有 RAG 问答的三类降级；没有增加服务、依赖或 Agent 功能。

## 1 参考依据与实现位置

阅读固定参考版本的 [RAG 上下文](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/rag.py)、[LLM 流式异常](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/llm.py)、[chat 事件](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/api/chat.py)及对应 `test_rag.py`、`test_api.py` 和 `test_integration.py`。上游空结果返回空 Context，chat 传递 error 事件，LLM 包装会把异常作为文本输出；没有候选确认流程。本项目保留简单 Context 和 token/done/error，补充课程要求，失败文本独立于答案，不伪造完成事件。

- [rag_pipeline.py](../../src/generation/rag_pipeline.py)：`prepare_rag_context()` 判断模式，`generation_error()` 提供故障与重试建议，流式/非流式共用本地请求、提示和完成校验。
- [streaming.py](../../src/generation/streaming.py)：流式前缀和最终答案保留模式提示；失败输出 error 事件并保留部分正文与引用。
- [app.py](../../src/frontend/app.py)：展示候选、确认/取消、历史提示与错误建议。
- [cache.py](../../src/generation/cache.py)：空库、低相关性及失败回答均不缓存。

## 2 三种行为

| 情况 | 系统行为 | 用户操作 |
| --- | --- | --- |
| 没有有效正文 | 以空上下文调用本地模型；系统在回答开头添加“当前知识库中未找到相关文档。以下为纯模型回答，没有知识库文献依据。” | 通用概念可以继续询问；具体论文事实需先上传文献 |
| 实际入选原文的最高 BGE 分数 < 0.1 | 暂停生成，展开候选文件名、真实位置与实际送入上下文的正文，显示分数及门槛 | 点击“使用这些内容继续生成”或“取消本次回答”；可直接提出新问题 |
| 本地模型 API 失败 | 显示“回答未完成”、具体故障和重试建议；保存已输出部分，只有真实 done 才为完成 | 修复服务/模型/配置后重新提交问题 |

空库提示由代码保证出现，不依赖模型是否主动输出；流式和历史重跑均保留。Prompt `rag-v3` 明确允许无上下文时用模型自身知识解释通用概念，但不能编造具体论文的数据集、结果等事实。没有有效引用时来源区为“无可引用来源”。旧 `rag-v2` 参数实验记录保持原样，没有声称新 Prompt 已重复完整参数实验。

低相关性确认保存本会话问题、Context 快照和知识库/配置哈希，确认前不调用 LLM；确认后复核哈希，变化时要求重新提问。新问题替换旧待确认请求，清空对话同时清除它。取消不生成；普通页面重跑不自动确认，也不重复生成。低相关性答案即使有合法引用也不入缓存，防止下次问题直接绕过确认。总耗时不计用户阅读等待时间。

## 3 相关性门槛的依据与边界

问答固定采用向量＋BM25＋RRF＋BGE 模型重排；仅把 **sigmoid 后的 BGE 重排分数**用于本策略，不把 BM25、RRF 和向量分数混用。分数随来源一起保留，只判断字符预算内实际入选的块，放不下的高分块不会使剩余低分原文自动通过。

[BGE 官方模型卡](https://huggingface.co/BAAI/bge-reranker-base#usage-for-reranker)说明重排通过问题和正文成对评分，归一化使用 sigmoid。它没有给出本项目科研语料的通用验收门槛；**0.1 是保守确认门槛，不是正确率、命中概率或最优参数**。

复查既有 [96 条三档检索记录](../../reports/检索三档对比结果.json)，不改标注、不重写原数据：低于 0.1 的 16 条中，Top-1 正确为 0 条，Top-5 命中仍有 1 条。因此保留候选给用户核验，而非删除它们。高分仍可能答非所问；中文、英文及跨语言分布不相同。后续独立评测仍需进一步校准阈值，不能把本开发集的观察当作通用结论。

设置位于 [config.yaml](../../config.yaml) 的 `generation.low_relevance_threshold`，范围 `(0, 1)`；恰好达到门槛继续通常 RAG。空白正文不算有效文献，非法分数/预算错误/检索故障明确报错，不冒充无结果。

## 4 API 故障提示

[Ollama 官方错误说明](https://docs.ollama.com/api/errors)指出：400 表示请求错误，404 可为模型不存在等情况，500 为内部错误；流中途失败会通过 NDJSON 的 `error` 字段返回，HTTP 状态可能仍为 200。因此同时检查 HTTP、数据格式、错误包和最终完成标记。

| 故障 | 重试建议 |
| --- | --- |
| 连接/读取失败 | 启动本地 Ollama，检查 YAML 的地址和端口，恢复后重新提交 |
| 响应超时 | 等待模型加载，缩短问题或上下文，检查可用内存后重新提交 |
| HTTP 404 | 检查模型名称、接口地址；用 `ollama list` 核验本地权重 |
| HTTP 400 | 修正生成参数或请求配置后重提 |
| 其他 HTTP 错误、模型错误包 | 查看本地日志和可用内存，等待当前任务或重启服务后重提 |
| 非法 JSON/响应结构、断流未完成 | 检查本地接口和日志；已有部分保留，修复后重提 |

error 事件包含 `message`、`retry_advice`、`error_detail` 和已收到的 `raw_answer`/正文快照；非流式失败抛出含建议的 RuntimeError，保留原始 cause。失败没有完成用量，不把未取得的 Token 数据写成零。不会自动重复调用或切换到云端。

实测环境设置了 HTTP 代理，第一次“关闭的本机端口”返回代理的 HTTP 502，见 [原始代理环境记录](../../reports/降级策略代理环境验证结果.json)。本次修正为 `ProxyHandler({})`，两个生成接口均直接连接本机服务。修正后的 [真实记录](../../reports/降级策略验证结果.json)取得 `URLError: Connection refused`。验证用例还设置不可用代理并启动真正的本机测试 HTTP 服务，核验两种接口均不依赖代理。

## 5 验证结果

新增17个功能测试：相关性边界、空白正文、上下文预算、未确认调用阻断、系统提示、API 故障分类、部分文本、真实本机 HTTP 代理绕过、缓存拒绝，以及页面确认/取消/清空/新问题/过期 Context/历史重跑。生成模块109项、全项目 **274项通过（14.004秒）**；`pip check` 无依赖冲突。单元测试样例隔离模型，不能证明模型答案质量。

[verify_degradation.py](../../reports/verify_degradation.py) 使用已准备的真实 M3E、BGE、Qwen2.5:7b、临时 Chroma 和 Streamlit AppTest。实际导入两个公开论文标注片段，核对 PDF SHA-256；没有修改默认用户索引或原始评测输入。

| 真实场景 | 生成 HTTP 次数 | 本次结果 |
| --- | ---: | --- |
| 空库解释机器学习 | 1 | 2.0271秒，435输入/39输出 Token，明确纯模型提示与无引用来源 |
| 地铁票价问题，论文候选最高分0.00003742 | 确认前0，确认后1 | 两个候选展开展示；确认后5.1832秒，815输入/42输出 Token，低相关提示保留 |
| 本机服务不可达 | 1 | 0.1433秒，连接错误及启动/端口建议，未标完成 |
| 实际不存在的本地模型 | 1 | 0.1432秒，真实HTTP 404及 `ollama list` 建议，未标完成 |

两个正常结束的降级回答也都未缓存。低相关例中的模型没有给出票价金额，没有有效论文引用；它仍写了“当前知识库中未找到相关文档”，而实际库内有两个候选。系统保留真实 `low` 模式和原文供核验，不把模型自述当作检索事实。这是已保留的模型输出局限，不宣称低相关资料能够支持答案。连接与404为真实故障；超时、断流、非法响应和中途错误包由确定性测试覆盖，没有声称实测了GPU超时或并发故障。AppTest是页面组件/状态验证，没有新增浏览器视觉截图。

复测先按用户手册启动本机 Ollama，再执行：

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python reports/verify_degradation.py --output /private/tmp/降级策略复测.json
.venv/bin/python -m unittest discover -s tests -q
```

输出路径已存在时拒绝覆盖。模块二运行日志、Top-1 分布统计及独立答案质量评测仍待后续完成。
