`AVAILABLE_TOOLS`当前只有这两个工具，不把开发测试工具计入课程八工具。`run_react()`省略`tools`时使用此列表，显式`tools=[]`时禁用工具，传入列表时使用调用方列表。单轮`think()/act()/observe()`仍由调用方传入工具。现有工具描述和参数Schema自动进入Agent的System Prompt。

## 2 知识库检索工具

输入：`question`为非空问题，`doc_id`可选，为已上传文档的64位SHA-256内容指纹。指定ID时先检查上传原文存在且内容未改变，再限定该论文检索；不接受任意磁盘路径或编造的论文ID。

实际链路为：

```text
HybridRetriever.search(rerank=True)
  → 向量 + BM25 + 手写RRF + BGE模型重排
  → prepare_rag_context（排序、预算、相关性判断）
  → generate_answer（模块二本地生成、引用解析）
  → 真实结果/用量 + RAG请求日志 + ToolMessage
```

返回结果包含`answer`、`generation_mode`、实际使用的`citations`（文档名、物理页码或非PDF位置、正文与稳定ID）、`sources`、Top-1分数、实际模型用量和检索/总耗时。PDF版面坐标不重复送入Agent窗口；原始加载元数据和RAG请求日志仍保留。

| 情况 | 实际行为 |
| --- | --- |
| 有相关证据 | `status=answered`，复用模块二生成与引用解析，缺失引用仍如实警告 |
| 无检索结果 | 复用纯模型降级，答案包含“当前知识库中未找到相关文档”，不能当作论文依据 |
| 相关性低 | `status=needs_confirmation`，返回候选原文/分数和阈值，不调用生成，生成Token为0 |
| 检索或模型失败 | 统一执行器返回真实错误，不伪造答案、自动重试或切换云端 |

低相关性不提供可由模型自行设定的确认参数；Observation的Prompt和Python检查均禁止把待确认结果标为任务完成。用户确认后的交互仍由后续前端集成实现。

复用`record_rag_request()`记录问题、完整Top-K原文/分数、答案、引用、响应耗时和真实Token，支持已有Top-1分布统计。每次工具调用使用独立请求ID，`session_id=agent-tool:<请求ID>`只是当前日志标识，不代表已完成持久会话记忆。生成失败时未知用量保留为未知；日志保存失败时给成功结果附加警告，保留原答案。

模块二语义缓存目前属于Streamlit页面会话。本轮没有建立跨用户全局缓存，Agent会话隔离及缓存接入待记忆和前端阶段完成。

## 3 论文元信息工具

输入：已上传原文的`doc_id`。上传器将原文保存在`paths.raw_documents/<内容指纹>/<原文件名>`；工具核对内容哈希并只读。复用PDF、Word、TXT/Markdown加载器，PDF读取前三个物理页，文本取开头连续前缀，字符预算沿用`generation.max_context_chars=6000`，不跳过中间长行拼接后文。

模型通过现有本机Ollama请求构建器，结构化提取标题、作者、年份、DOI四个短字段。使用已有Qwen2.5:7b及采样参数，没有新增模型依赖或配置。DOI必须来自输入中匹配出的`10.`候选，没有候选只能为null；摘要不让模型改写或复制。

字段经过原文匹配才可返回，匹配允许空格、大小写、连字、断词和上标归一化，再回填原文及对应位置证据；不存在于原文的作者、年份或DOI会明确失败。作者逐人列出并去重，标题保留原文大小写和中文标点。年份优先明确发表/会议年份，避免将arXiv后续版本日期当成发表年份。

摘要以独立`Abstract/摘要`行或带冒号标题为开始，关键词、引言、章节编号、参考文献或脚注为结束，直接取原文正文并保留来源。没有标准摘要标题时返回缺项；输入已截断且未看到结束边界时提示摘要可能不完整。

返回五个字段以及`source_file`、逐字段`evidence`、`missing_fields`、`input_truncated`、警告、模型名称和真实用量。缺失字段为null，缺失作者为`[]`，不联网补齐DOI，不把arXiv编号冒充DOI。

这些规则适用于本次核验的常见版式，并不保证所有期刊模板、无标题摘要或扫描件解析成功；没有新增OCR。原文匹配能核对字段文字确实存在，仍不能仅凭它证明模型选中的人名一定属于本篇作者而非机构/参考文献，后续质量评测需要独立标注与人工复核。

## 4 调用示例

以下为接口说明，不是实测数据。`doc_id`来自成功上传记录的`task["documents"][0].metadata["doc_id"]`；未实现文献列表工具前，由调用方提供真实ID。

```python
from src.agent.tools import AVAILABLE_TOOLS, execute_tool
from src.agent.react_loop import run_react

# doc_id取自上传记录，不能以文件名、路径或arXiv编号替代。
result = execute_tool("paper_metadata", {"doc_id": doc_id}, AVAILABLE_TOOLS)
answer = execute_tool("knowledge_base_search",
                      {"question": "这篇论文使用什么数据集？", "doc_id": doc_id}, AVAILABLE_TOOLS)
for event in run_react("提取论文的标题、作者和年份。",
                      context={"papers": [{"doc_id": doc_id, "source_file": "论文.pdf"}]}):
    print(event["type"])  # 返回真实规划、调用、结果、观察与终止事件。
```

`execute_tool()`外层`status=success`代表调用成功；需继续查看内层RAG结果是否为`needs_confirmation`，不能把调用成功等同于问题已回答。
