# 5.3.4 对话摘要压缩

**测试入口更新（2026-10-03）**：测试已按课程小节拆分，当前入口见[测试目录说明](../../tests/README.md)。本页历史测试数量、耗时及结论保留；复测命令使用当前路径。

## 1 范围与参考依据

在现有SQLite会话隔离和Token窗口上增加阶段性摘要，接入`run_session`。压缩后，模型使用`Context.summary`和未压缩的最近`history`，不再接收摘要覆盖的旧问答原文；`get_messages`仍返回完整归档，方便核验。

编码前读取固定上游的[记忆源码](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/memory.py)及[记忆测试](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/tests/test_memory.py)。上游有SQLite、Message和滑动窗口，没有阶段性摘要。本功能属于课程补充，沿用这些基础组件，复用本项目本机Ollama请求构建，不增加Agent框架、存储后端或云端调用。

## 2 配置和处理过程

新增配置见[config.yaml](../../config.yaml)，实现见[memory.py](../../src/agent/memory.py)。

```yaml
memory:
  max_history_tokens: 2000
  tokenizer_path: data/models/qwen2.5-tokenizer/tokenizer.json
  summary_trigger_turns: 10
  summary_keep_recent_turns: 4
  summary_max_tokens: 400
```

这里的“10轮”指尚未进入摘要的完整问答对，不是会话累计轮数。首次达到10轮时，旧6轮进入摘要，最近4轮保留原文；再累计6轮新问答后，合并已有摘要与新积累的旧6轮，更新摘要。阈值之间不重复调用摘要模型，最近历史仍按总Token预算裁剪。三个新增值均须为正整数，触发轮数必须大于保留轮数。

1. 先校验`user_id/session_id`归属，在同一读事务中取得当前归档、摘要和边界。
2. 超阈值时，选择较旧完整问答对。System Prompt要求保留目标、约束、用户纠正、待办、论文ID、代号及必要引用；不执行资料中的指令，不添加新事实。
3. 调用当前本机Qwen，要求唯一JSON字段`summary`。只有正常结束、JSON/字段/非空文本正确、摘要JSON不超过400 Token时，才允许替换。
4. 在SQLite的`summaries(session_id, content, through_message_id)`保存摘要和已处理边界。后续只读取边界之后的新历史，不重新摘要全部归档。新增表自动适配已有数据库，不改写原消息表。
5. 重读权威存储，以摘要替换其覆盖的旧历史，拼接最近窗口。`count_memory_tokens`使用本地Qwen词表统计`{"summary": ..., "history": ...}`组件，整体超过2000时移除最旧完整问答对。无摘要时沿用原历史列表计数。

`Context.summary`是会话资料，不放入System Message；Agent共同角色说明它可能遗漏细节、不能作为已核实论文事实，最新用户纠正优先。需要的事实不在摘要或最近历史时应请求补充。已有路由检测summary/history，会回退到模型处理追问。

SQLite原始记录保留；`clear_session`在同一事务中清空本会话摘要和消息。重建MemoryManager可恢复摘要与进度，其他用户或同用户其他会话不共享。

## 3 预算、失败与并发边界

- 摘要输入按模型`num_ctx`的一半分批，预留512 Token挑选空间，并对实际System/Human JSON重新计数。每批只包含完整问答，输出生成空间为`summary_max_tokens+128`，HTTP超时60秒；不依赖模型静默截断。
- 每次读取最多调用三批；超大归档未处理部分保留在数据库，下一次未压缩轮数达到阈值时继续。若旧单轮本身超过输入预算，不截断后标为已处理，直接记录警告并使用窗口。
- 超时、不可达、JSON错误、未正常结束、摘要超限或数据库保存失败，均保留已存摘要和全部原文，回退现有窗口；下一次仍符合阈值时可重试。失败不会冒充摘要成功。
- 写摘要前在事务中检查旧边界未变化、对应原文边界仍存在。并发摘要只允许一个结果推进同一边界；清空期间产生的慢结果丢弃。模型等待期间不持有写锁；并发请求仍可能产生重复模型计算，当前不增加排队服务。
- 调小总预算后，摘要本身超限时本轮整段省略，并提示可调大预算恢复；磁盘摘要不删除。不会把截断半句当成完整摘要。

`memory_summary`记录`summarized_turns`、`unsummarized_dropped_turns`、警告及本轮成功取得的模型响应用量/耗时/是否保存。调用信息不重复携带摘要全文。未知用量保留null；HTTP失败没有返回的用量无法统计。`history_window.dropped_turns`包含已被摘要替换与因预算丢弃的原文轮数，后者单独计入`unsummarized_dropped_turns`。

2000是记忆组件预算，系统规则、当前问题、工具轨迹及元数据另占模型空间；它不等于整个请求用量。摘要额外模型开销单独保留，不能仅凭压缩后的输入量宣称总Token或耗时必然减少。摘要是有损模型输出，格式有效不保证所有约束/引用语义均正确；重要论文事实仍需原文与检索工具核验。
