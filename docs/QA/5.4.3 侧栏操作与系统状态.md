# 5.4.3 侧栏操作与系统状态

2026年10月4日，在已有侧栏精简的基础上完成四项调整。

1. 文档点击“删除”后，原按钮位置显示“确认删除”和“取消”；删除长提示及列表下方的确认区。取消恢复原按钮，确认仍使用原文回收、目标索引删除与缓存清理流程。
2. 归档知识显示文件名和完整内容指纹，标签改为“已归档知识”，按钮为“恢复”。恢复仍真实重新向量化；失败保留原文并可重试。
3. 会话归档标签改为“恢复会话”，显示首问题标题和完整ID，按钮为“恢复”。只允许读取本访客归档标题，完整历史与执行仍要求先恢复；活动会话高亮、新建、切换与原会话删除流程保留。
4. 主区域健康检查移到侧栏最上方，标题为“系统状态”。依次显示系统时间、LLM服务正常及模型名/异常原因、向量数据库正常及Chroma名称/异常原因，再显示“刷新状态”。首次打开自动检查，普通交互复用快照，导入、删除、恢复知识后更新。时间在页面重绘时刷新；服务状态通过刷新按钮重新检查。检查不启动模型推理。

## 选择控件

最初使用当前已固定的Streamlit 1.64.0下拉框并设置`filter_mode=None`。AppTest能确认禁止新选项，但实际浏览器仍允许在搜索输入里键入文字。最终使用原生单选选择框：文件名/会话标题为选项，完整ID为选项说明。归档区域没有文本输入元素，用户只能点选已有记录；没有引入自定义JavaScript或新的前端框架。

## 验证

- 参考固定版本前端与SQLite记忆测试，适配现有Streamlit会话状态和本地存储；归档标题读取为本项目增补，不开放跨用户访问。
- 118项相关回归全部通过，覆盖删除确认/取消、指定归档恢复、真实临时Chroma重建、失败重试、历史切换/恢复、归属校验、首屏检查及正常/异常展示。原有健康检查后端测试继续核验本地HTTP响应与真实临时Chroma。
- 浏览器实际核验删除按钮原位替换、取消回退、两类归档区域没有可编辑输入、文档恢复重建索引、会话恢复对应历史，以及系统状态位于上传区上方。
- 仅使用临时原文、索引、SQLite和测试向量，LLM响应/正常状态明确模拟；未启动Mac模型或性能实验。Windows页面需同步代码并重启后复测，截图不作为Windows服务可用性证据。
