# 5.3.4 滑动窗口Token管理

## 1 范围与方案依据

本次为已有SQLite会话记忆增加历史Token窗口，并接入run_session：自动从最旧的完整问答对开始移除，保留连续的最近历史。SQLite原始问答保留，摘要压缩和前端会话界面仍待下一阶段。

修改前读取固定上游的 [MemoryManager._trim_history](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/memory.py) 及 [TestSlidingWindow](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/tests/test_memory.py)。沿用默认2000 Token和“超限移除最早历史”的简单循环，不增加存储后端或Agent框架。

上游使用GPT编码器、拼接消息正文计数、逐条删除并覆盖存储。本项目当前使用本地Qwen2.5，而且history放在Context JSON中，因此做以下适配：

- 使用当前Qwen官方tokenizer.json计数，不把GPT编码器、M3E分词器或字符长度当作Qwen Token。
- 统计history列表的实际JSON，包括角色、正文、引号与分隔符；每次移除后重新编码，不依赖单条Token数简单相加。
- 问题与回答成对移除，不留下缺少问题的孤立回答，也不截断公式、Unicode或引用标记。
- 只裁剪模型可见窗口，不删除SQLite原始问答，便于查看记录及后续摘要压缩。

资料依据：[Qwen官方模型与分词器](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct/blob/a09a35458c702b33eeacc393d103063234e8bc28/tokenizer.json)、[Tokenizers 0.20.3 官方API](https://huggingface.co/docs/tokenizers/v0.20.3/api/tokenizer)。from_file只读取本地JSON；encode可关闭特殊Token添加，no_truncation/no_padding用于避免计数时已经裁剪或补齐。

## 2 实现与配置

代码见 [memory.py](../../src/agent/memory.py)，新增配置统一在 [config.yaml](../../config.yaml)：

```yaml
memory:
  max_history_tokens: 2000
  tokenizer_path: data/models/qwen2.5-tokenizer/tokenizer.json
```

- count_history_tokens(history)：使用已固定的本地Qwen词表，对与Agent一致的json.dumps(..., ensure_ascii=False, allow_nan=False)编码。当前适用于qwen2.5:*；切换ChatGLM等模型需先适配对应分词器，不静默使用错误词表。
- get_context(user_id, session_id)：先校验会话归属，读取归档，按完整问答对移除最旧记录，直至窗口Token≤上限。返回history与history_window。
- run_session：自动读取get_context结果交给现有run_react；get_messages仍返回完整归档，两者用途明确。

history_window包含tokens、max_tokens、retained_turns、dropped_turns、tokenizer，随当前请求Context保留，可核验本轮实际使用多少历史。空历史记为0，其空列表框架视为基础请求开销。恰好等于上限时不删；上限必须是正整数，布尔、字符串、零和负数等配置拒绝执行。

当单个最新问答对已经超过上限，最终窗口为空，不保留更早对话去冒充最近上下文。角色提示说明部分旧对话已截断：所需信息不在可见历史时请求补充，不编造旧记录。系统角色提示和当前用户问题不由历史窗口删除。

窗口在每个新问题前重新计算；修改预算或重新创建MemoryManager均生效。计数只缓存词表，不缓存用户历史；不跨用户共享消息。当前阶段不新增摘要，也没有恢复已裁剪旧事实的语义能力。

**预算边界**：2000限制的是历史JSON组件，不是完整Ollama输入Token数或生成用量。系统提示、工具描述、当前问题、当前轮工具结果和JSON外层另占模型上下文，llm.num_ctx仍为8192；此功能不能保证任意超大问题/工具轨迹都在整个模型窗口内。实际请求用量继续以Ollama的prompt_eval_count/eval_count为准，不将历史计数相加伪装为完整用量。

## 3 本地分词器准备

本次已准备到data/models/下，不下载模型权重、不新增依赖，使用既有tokenizers==0.20.3。固定资料：

准备原始数据见 [分词器记录](../../reports/滑动窗口分词器准备_20261002.json)。data/models/保持Git忽略；复制项目到新机器后需准备该文件，否则会明确报FileNotFoundError，不自动联网下载，也不退化为字符数。仅公开分词器文件准备时联网，运行计数不访问云服务、不加载大模型；词表替换后需重启进程刷新缓存。

新环境可在项目根目录显式准备并核对文件：

```python
from pathlib import Path
from urllib.request import urlopen
import hashlib

path = Path("data/models/qwen2.5-tokenizer/tokenizer.json")
revision = "a09a35458c702b33eeacc393d103063234e8bc28"
url = f"https://huggingface.co/Qwen/Qwen2.5-7B-Instruct/resolve/{revision}/tokenizer.json"
if not path.exists():
    with urlopen(url, timeout=60) as response:
        data = response.read()
    assert hashlib.sha256(data).hexdigest() == "c0382117ea329cdf097041132f6d735924b697924d6f6fc3945713e96ce87539"
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_bytes(data)
```

离线机器可先从已准备机器复制这个固定文件。此代码是明确的准备步骤，不是运行时自动下载逻辑。
