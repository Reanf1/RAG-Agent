# 5.1.3 批量向量化与增量索引

**测试入口更新（2026-10-03）**：测试已按课程小节拆分，当前入口见[测试目录说明](../../tests/README.md)。本页历史测试数量、耗时及结论保留；复测命令使用当前路径。

## 实现范围

已将批量导入页面接通 **保存/加载→默认分块→本地 M3E 批量编码→Chroma 持久化**。新增文献追加新块；重复块使用已有向量，不清空旧集合、不重建全量索引。问答、BM25、RRF 和重排仍属于后续模块。

沿用固定参考提交 [RAGEngine.ingest_file()](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/rag.py) 的处理顺序，以及 [knowledge.py](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/api/knowledge.py) 的文件类型/大小校验思路；已阅读上游 `tests/test_rag.py`。本项目不复制其 HTTP 接口和随机 UUID，也不在索引失败时删除原文，而是复用现有安全保存、稳定文档/块 ID 和 Chroma 封装，以支持重试。

代码保持指定结构：

- [vector_store.py](../../src/retrieval/vector_store.py) 新增 `batch_build_index()`，约 55 行，协调已有模块，不新建框架。
- [app.py](../../src/frontend/app.py) 调用批量索引生成器，显示阶段、分块和新增数量。
- [test_batch_index.py](../../tests/5_1_3%20向量化与存储/test_batch_index.py) 补批量索引与界面用例，使用临时目录隔离原文/索引。

本轮没有新增依赖。仍使用选定的 M3E、Chroma，以及 YAML 默认递归 512/64 字符参数。Embedding 内部批大小 32；索引流程每 500 块提交一次并刷新状态，二者用途不同。超过 Token 限制的完整表格仍沿用模型截断限制，本轮不改变分块算法。

## 状态与增量规则

任务仍由 `create_import_tasks()` 创建，原始 `batch_import()` 保持“只加载/保存”的独立用途。新入口接收同样的任务列表，并增加索引字段：

| 字段 | 含义 |
| --- | --- |
| `status` | `pending/loading/chunking/indexing/success/failed` |
| `indexed` | 全部预期块处理成功后为 `True`，部分写入仍为 `False` |
| `chunk_count` | 当前文档按默认策略生成的块数 |
| `processed_chunks` | 本次尝试已检查/写入的块数，包含跳过的重复项 |
| `added_chunks` | 当前尝试实际新增块数；重试时从零计数 |
| `index_total` | 该任务最近一次成功写入并查询后的库中总块数，是快照 |
| `attempts/elapsed/error` | 完整入库尝试次数、本次耗时与错误；不将加载成功当索引成功 |

生成器仍产出 `{completed, total}` 文件进度，加载、分块及每批写入时也刷新状态表。100% 表示本轮所有目标文件已尝试，失败项同样计入；成功数另行展示。若页面保留上一阶段“只加载成功”的任务，尚无 `indexed=True` 时显示“待索引”，允许继续入库，不计入索引成功数。

第一个有效文档进入索引时才初始化本地模型/数据库，一批复用同一实例。初始空页面、空批次、全部加载失败的批次不初始化模型。`get_embeddings()` 在进程内复用已加载 M3E；Chroma 重开同一集合，不重算已有向量。

块 ID 由已有分块模块根据原始文档 SHA、父内容单元、切分参数和字符区间生成。`VectorStore.add_chunks()` 先查询已有 ID，再只编码缺失块。新增文献因此无需重新向量化旧文献；重新上传相同原文仍会校验、加载与分块，但不会重复编码或增加向量记录。

## 失败恢复

加载/保存错误只影响当前文件，其余文件继续。重试仍执行原加载器的格式、大小与文件保存校验。

分块、模型或数据库阶段错误保留已保存原文、加载结果及已写入块；“重试失败项”只选失败任务，复用加载结果，重新按默认策略分块并查重。若第一批 500 块写入成功、第二批失败，恢复后第一批只查重，剩余块才编码。已经加载成功但尚未索引的任务也可继续索引。

每次手动重试对目标文件最多尝试一轮；永久错误不会无限循环。失败恢复按批次追加，不提供整个文件的原子回滚，也不会把部分写入标记为成功。模型缺失或索引配置不匹配会明确报错，不转云端。

页面任务状态保存在当前 Streamlit 会话，断开或刷新后可能丢失；原文和已写入索引持久化，重新上传相同原文可通过稳定 ID 补齐缺失块。改变分块方案会产生新 ID；替换旧文档方案时需先按旧 `doc_id` 删除，再添加，不能把换参数当作普通重复导入。

## 使用方式

首先按 [用户手册](../用户使用手册.md) 准备本地 M3E 权重。启动页面，选择多份文献，点击“开始导入”；状态表分别显示内容单元、分块数、已处理块、本次新增块和写入后的库中块数。新选择的文档增量写入原集合，成功任务不会因页面重跑再次执行。

Python 也可直接调用：

```python
from pathlib import Path
from src.data_loader import create_import_tasks
from src.retrieval.vector_store import batch_build_index

# 改为实际路径；默认模型和索引配置仍统一从 config.yaml 读取。
paths = [Path("论文A.pdf"), Path("论文B.docx")]
tasks = create_import_tasks([(path.name, path.read_bytes()) for path in paths])
for progress in batch_build_index(tasks, "data/raw"):
    print(progress, [(task["name"], task["status"], task.get("added_chunks", 0)) for task in tasks])

# 修正失败原因后，仅重新尝试失败项。
for progress in batch_build_index(tasks, "data/raw", retry_failed=True):
    print(progress)
```

## 验证记录（2026 年 9 月 29 日）

新增 9 个批量索引测试、2 个界面测试，并将原有界面测试升级为真实临时 Chroma 联调。全部 **107 个测试通过**。验证内容如下：

- PDF/Word/TXT/Markdown 实际文件完成加载、默认分块和写入，来源指向保存文件；只有索引完成后才标记成功。
- 新客户端向已有库添加新文献，仅新文献进入 Embedding；原块、正文、来源保留。
- 页面重跑跳过完成任务，重新创建任务或重新上传相同原文时新增为零、不重新编码。
- 一份文献索引失败不阻断后续文献；重试不重载已有原文，也不重试成功项。
- 用实际固定切分产生 600 个测试块：第一批 500 块持久化后模拟第二批失败，重试只编码剩余 100 块；全部编码次数合计恰好 600。此处 2 字符窗口仅用于批次边界测试，不是分块选型参数。
- 可观察加载、分块、索引阶段；生成器在索引阶段中断后可继续，且不会误报成功。
- 空批次、加载失败不初始化模型；空分块不标为索引成功。
- Streamlit AppTest 实际操作上传/开始/重试组件，验证旧加载成功任务显示“待索引”、缺失模型的错误状态、原文保留与恢复，以及先上传 A、再上传 B、再上传 A 时只编码前两份。旧状态误报先由测试复现，再修复显示与成功计数。

单元测试用明确二维向量核对编码次数，数据库为真实 Chroma；不会将其当模型质量或速度数据。

另在 `HF_HUB_OFFLINE=1` 下使用**真实 M3E**和临时生成的四格式短示例文件：初始 4 份生成 4 块；再次导入新增 0 块，真实编码方法调用次数不增加；新文献增加 1 块，最终 5 块且原 ID 全部保留；重新打开索引后中文、英文查询均返回正文与来源。真实编码方法仅被包装记录输入数量，输出未替换。全部 7 次编码调用为初始 4 次、新文献 1 次及中英查询 2 次，见 [原始功能验证结果](../../reports/5_1_3%20向量化与存储/批量索引验证结果.json)。该验证使用短示例，不是论文质量/性能评测。
