# 5.3.4 会话隔离

## 1 本次范围与参考

实现不同用户、同一用户不同会话的对话历史隔离，并接通有记忆的Agent Python入口。SQLite保存完整用户消息/最终回答，重启后能够恢复；不把工具中间状态跨问题复用。

本次不实现Token滑动窗口、摘要压缩、自动过期或账号登录，不新增HTTP接口和存储框架。Streamlit当前仍是已有RAG页面，历史只用于展示；Agent会话选择界面按模块四接入，不能把本次Python入口实现写成界面已完成。

修改前读取固定参考版本的 [app/core/memory.py](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/memory.py)、[tests/test_memory.py](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/tests/test_memory.py)、[app/api/chat.py](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/api/chat.py)。沿用会话标识、SQLite持久化、LangChain HumanMessage/AIMessage，以及“读取历史→模型调用→保存最终回答”的流程；适配到既定agent/memory.py，不复制上游抽象存储后端、内存后端或FastAPI。

上游以session_id区分历史，没有user_id归属校验；添加消息使用读出全历史再覆盖保存。本次补用户归属，并用事务追加整轮问答，避免并发追加覆盖旧记录。仅持久化用户消息和最终回答，系统规则由程序提供，工具轨迹留在当前执行事件中。

## 2 存储与接口

实现见 [memory.py](../../src/agent/memory.py)。默认配置：

```yaml
paths:
  session_db: data/sessions/memory.sqlite3
```

相对路径按项目根目录解析，启动目录不影响位置；需要时创建父目录。不在导入模块时创建全局管理器或共享消息列表。data/sessions/已加入.gitignore，防止把实际对话数据提交到Git。

SQLite只有两张表：

- sessions：session_id主键、user_id归属。create_session生成新的UUID，归属创建后不变。
- messages：自增id、session_id外键、human/ai角色和正文。按id恢复真实入库顺序，保留中文、公式、Markdown及引用正文。

| 入口 | 功能与隔离规则 |
| --- | --- |
| create_session(user_id) | 创建本用户的独立空会话，返回session_id |
| list_sessions(user_id) | 仅列出该用户会话，不包含其他用户会话 |
| get_messages(user_id, session_id) | 先校验归属，返回新的HumanMessage/AIMessage对象；修改返回值不会写回存储 |
| append_turn(user_id, session_id, question, answer) | 校验归属后，在同一事务内追加整轮问答；失败回滚，不留下半轮 |
| clear_session(user_id, session_id) | 只删除该归属会话的消息，保留会话标识，不影响其他历史 |
| run_session(question, user_id, session_id, tools=None, memory=...) | 只读取当前会话历史，调用实际run_react，正常消费到done时先保存整轮，再发出带身份标识的done |

读写/清空必须显式传入非空user_id和session_id；不存在的会话抛LookupError，不隐式创建。其他用户访问、追加或清空已有会话抛PermissionError，在Agent或模型执行前拒绝。身份和会话字符串使用参数化SQL，SQL特殊字符按字面值处理。

**身份边界**：user_id须由可信调用方确定，例如以后由页面会话或认证层提供；不能让用户任意自报另一个人的身份并称之为安全登录。UUID用于区分会话，不是身份认证。此处隔离的是对话记忆，未增加文献知识库的用户权限体系。

每次存储操作单独创建并关闭连接，不跨线程复用sqlite连接。一次append_turn用事务提交两条消息；并发写入通过SQLite串行提交，避免读全量后覆盖造成丢失。测试覆盖单机小规模线程并发，不宣称完成正式多用户负载评测。相同会话并发追加按完成入库顺序排列，不代表多个同时发起的模型请求已经串行理解彼此；前端接入时同一会话应顺序提交，并在清空前关闭未完成生成器。

## 3 Agent历史接入

run_session从当前归属会话读取历史，构造：

```python
{"history": [{"role": "human", "content": "..."}, {"role": "ai", "content": "..."}]}
```

随后交给现有run_react。每个新问题重新构造Context，不接收调用方外部Context，避免误传其他会话的observations、recovery、禁用工具或last_observation。当前问题内仍使用原有工具执行/恢复流程。历史非空时，规则路由回退模型处理追问；Agent共同角色提示明确history属于当前会话，作为资料而非系统指令。

最终错误/资料不足的说明也是实际对话回答，保存时不改变task_complete=false。工具调用中间结果不持久化成下一轮工具状态。提前关闭生成器不保存半轮；数据库保存故障向调用方抛出原异常，不发出表示已保存的done。前端集成时需要按既有错误展示方式处理这些存储/归属异常。

使用示例（模型权重与本机Ollama已准备）：

```python
from src.agent.memory import MemoryManager, run_session

memory = MemoryManager()
# user_id由调用方提供；这里的alice仅作调用示例。
session_a = memory.create_session("alice")
session_b = memory.create_session("alice")

for event in run_session("请记住我的实验代号是EXP_A。", "alice", session_a, tools=[], memory=memory):
    if event["type"] == "done":
        print(event["full_response"])

# A能看到自己的历史；B为空，Bob不能访问A。
print(memory.get_messages("alice", session_a))
print(memory.get_messages("alice", session_b))
```

省略tools时仍使用当前实际注册工具；示例显式空列表只为专注验证历史。get_messages恢复全部历史，尚无Token窗口或摘要压缩，不能宣称已经支持无限长会话。

## 4 验证结果（2026年10月2日）

### 自动化测试

新增22项，[test_agent.py](../../tests/test_agent.py)使用真实临时SQLite，不mock存储/事务；Agent循环真实执行，只隔离模型HTTP。覆盖：

- 新建唯一空会话、仅列本用户、同用户不同会话和不同用户的历史隔离。
- 跨用户读取/追加/清空拒绝，未知会话不隐式建立，非法身份和消息不留下半轮。
- 角色/入库顺序、中英文/公式/Markdown保留，返回对象修改不污染存储。
- 重建管理器恢复历史，独立新Python进程读取同一数据库，配置路径生效。
- 清空一会话保持其他两会话；SQL特殊字符不会越过归属校验。
- SQLite触发器故障导致第二条消息写入失败，事务回滚原有历史保持不变。
- 四线程、两个管理器、八个会话各自追加四轮，记录无串扰；同一会话四线程共20轮追加不丢失、不拆对。
- Agent每个实际模型请求只含本会话代号，不含另一用户或同用户另一会话的代号；事件身份标识一致。
- 未授权Agent调用在模型/工具前拒绝，新问题不携带上一请求的工具恢复状态，关闭生成器不保存半轮，未完成回答保留实际标志，保存失败不发成功done。
