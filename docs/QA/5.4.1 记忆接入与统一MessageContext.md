## 2. 统一Message边界

| 使用位置 | 表示 |
| --- | --- |
| 文献处理/检索 | LangChain Document，保留稳定ID与真实来源位置 |
| 内部模型消息 | SystemMessage、HumanMessage、AIMessage、ToolMessage；正文为字符串 |
| 记忆归档 | 持久化human/ai角色与最终问答文本；get_messages恢复Human/AI Message |
| Context.history | `[{"role": "human或ai", "content": "字符串"}]` |
| Ollama HTTP边界 | 统一转换为system/user/assistant/tool；AI调用使用原生function.name/arguments，工具返回保留tool_name |

RAG非流式、流式和Agent三个阶段共用该转换，阶段摘要通过Agent模型请求入口复用。工具的call_id继续在AIMessage/ToolMessage之间关联；按现有Ollama原生请求格式使用工具名，不把call_id当作文献引用编号。正文不支持多模态消息块，非法消息明确拒绝，不静默转换为字符串。

History入口同时接收Human/AI Message或role/content字典；user/assistant转换为统一的human/ai。系统消息、工具返回、中间AI工具调用及额外历史字段拒绝进入长期历史。工具事件中的Message保留为对象，写报告时由明确的序列化函数转换，不要求整个事件自动成为JSON。

## 3. Context约定与数据传递

Context始终是普通字典；各阶段按职责使用同一快照，不引入请求模型或通用协议层。以下字段按实际需要出现，不给RAG生成上下文塞入无关会话字段：

```python
context = {
    "history": [
        {"role": "human", "content": "我的实验系数为3.14。"},
        {"role": "ai", "content": "已记录。"},
    ],
    "summary": "旧对话摘要",             # 长历史压缩后存在
    "history_window": {"tokens": 240, "max_tokens": 2000},
    "observations": [                    # 当前请求的实际工具结果
        {"name": "knowledge_base_search", "status": "success", "result": {
            "answer": "……", "citations": [{"id": 1, "source_file": "论文.pdf",
                "location": "第3页（物理页码）", "metadata": {"doc_id": "……"}}]
        }}
    ],
}
```

这段结构是格式说明，不是实际检索证据。`history_window`、`memory_summary`提供实际预算/摘要用量；`observations`、`last_observation`、`recovery`只用于当前执行。RAG的`context`文本、`sources`、`references`及预算仍使用模块二既有检索Context；工具通过result/citations把来源传到Agent，不将检索Context和会话历史扁平合并。

normalize_context返回深复制快照，保持摘要/检索来源和稳定ID，统一历史角色并校验JSON可传输性；NaN、原始Document或放错位置的Message明确拒绝。run_react仍校验observations为工具结果字典列表。Thought、Action、Observation读取同一份历史和摘要，不把资料提升为System指令。

## 4. 记忆接入流程

```text
run_session(question, user_id, session_id)
  → SQLite校验会话归属
  → get_context：阶段摘要 + 最近完整问答 + Token窗口
  → run_react：规范化Context → Thought → Action → Observation
  → 完成/未完成的实际最终回答
  → 事务保存完整用户问题与最终回答 → 发出done
```

每个新问题重新从当前归属会话读Context，不复用上一轮observations、工具禁用集合或恢复状态。身份由可信调用方传入；SQLite归属校验不等于登录认证。摘要和最近历史共享默认2000 Token预算，旧问答保留完整归档。

Action可根据history/summary理解“刚才的系数”“这篇论文”等追问，填写具体工具参数；它应改写完整检索问题或使用已知论文ID，不将整个会话直接送给检索/联网工具。记忆能提供已保存的语义上下文，但不保证模型任意省略指代都能正确理解；工具轨迹及结构化引用不额外持久化，历史保留的是最终回答文本及其中的来源。

入口示例（先启动本机模型；代码示范不计为测试结果）：

```python
from src.agent import MemoryManager, run_session

memory = MemoryManager()
session_id = memory.create_session("demo")
list(run_session("我的实验系数为3.14，请记住。", "demo", session_id, tools=[], memory=memory))
for event in run_session("请用计算器把刚才的系数乘以2。", "demo", session_id, memory=memory):
    if event["type"] == "done":
        print(event["full_response"])  # 来自实际工具结果及模型回答
```

省略tools使用真实注册表，`tools=[]`明确禁用工具。消费到done前才保存；提前关闭无半轮，保存失败不发出已完成存储的done。公开run_session负责归属检查；直接run_react接收的外部Context由可信调用方提供，不代替会话权限校验。
