# 5.3.3 工具选择路由与并行调用

实现与验收日期：2026 年 10 月 2 日。代码为 `src/agent/router.py` 与 `src/agent/react_loop.py`，配置新增 `agent.max_parallel_calls: 2`。使用标准库线程池，没有新增依赖、服务或 Agent 框架。八个本地工具仍完成 6/8，本次不将测试计算器计入生产工具。

## 1 实现依据

已核对固定上游 [Agent 源码](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/agent.py)、[工具测试](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/tests/test_tools.py) 和 [API 分层测试](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/tests/test_api.py)。沿用实际工具列表、原生 Function Calling、`invoke()`、关联 `AIMessage/ToolMessage` 和生成器事件；上游逐个顺序执行，本次补充课程要求的快速路由与线程并行。

[Ollama 官方工具调用说明](https://docs.ollama.com/capabilities/tool-calling)提供同一 assistant 消息内多个 `tool_calls`，随后反馈全部工具结果的原生协议。本项目保留这个消息结构；Python 中的线程池负责真正重叠执行工具，模型服务的计算并发另由 Ollama 决定。

## 2 快速路由

`route_question(question, tools, context)` 只选择实际注册的工具，不填写参数或执行工具。命中时产生 `route=rule` 的 Thought 事件，规划阶段 Token 为 0、`model=null`；Action 继续由本地模型按工具 Schema 填写真实输入。

| 意图 | 路由 |
| --- | --- |
| 明确当前系统时间/日期 | `current_time` |
| 提取关键词、生成结构化摘要、论文元信息 | 对应已注册工具 |
| 两篇论文比较 | `paper_compare` |
| 论文/文献资料、知识库问题 | `knowledge_base_search` |
| 独立的一般概念 | 跳过 Thought 模型及 Action，直接进入 Observation 回答 |
| 明确联网请求 | 仅实际注册 `web_search` 时命中；默认关闭时回退模型 |
| 明确算式 | 仅实际注册 `calculator` 时命中；生产计算器仍未实现 |

只在第一轮且无已使用的对话状态时快速路由；已有 observations/历史/上下文、否定调用、前后依赖或多个意图时回退模型，不选其中一项冒充完整任务。没有明确工具/文献意图的“最新/最近”等问题也回退模型。规则是简单意图匹配，没有训练分类器，不声称覆盖所有自然问法。

明确“分别/同时”处理两份论文的元信息、摘要等请求可产生同名工具独立批次。未知论文 ID 不能由规则补造；Action 仍需从问题/Context 获得已上传 SHA-256 ID，否则明确报错或要求补充。路由不启用禁用的联网工具。

## 3 模型规划与独立性

Thought 的结构化输出为四个字段：

```json
{
  "thought": "时间查询与给定文本的关键词提取相互独立。",
  "next_step": "tool",
  "tool_name": "current_time",
  "parallel_tools": ["current_time", "keyword_extract"]
}
```

- `parallel_tools=[]`：单调用或直接回答。单调用使用 `tool_name`，回答使用 `null`。
- 非空列表：本轮独立工具批次，主要 `tool_name` 必须等于列表首项；列表名称不重复且来自实际注册表。
- 同一工具分别处理两篇论文时列表只含一次该工具名，Action 在原生调用数组中填写两套不同输入。
- 所有输入必须已存在于问题/Context；需要“先提取关键词，再按提取结果检索”时只规划当前一步，Observation 决定下一轮。独立性是模型的语义判断，不是通用依赖图分析器。

Schema 要求四字段；Python 保持已有调用方的三字段单调用计划可用，并检查完整字段、主要名称、批次名称与数量。未注册、重复或不一致的计划拒绝执行。

## 4 并行执行与消息关联

1. Action 只提供 Thought 选中的工具，一次模型请求返回本轮全部原生调用；上限来自 `max_parallel_calls`，默认 2。
2. 完整检查模型是否正常停止、调用数量、工具名称、参数对象、重复的名称/参数，以及是否覆盖选中工具；协议不合格时不开始任何调用。具体参数类型/必填项仍由现有执行器校验，单项错误保留为真实工具结果。
3. 先产出本批所有 `tool_call`，随后 `execute_calls()` 使用最多两个线程执行。关闭在调用事件阶段时尚未开始工具。
4. 工具实际执行可重叠，但结果按原调用顺序输出，便于 Ollama 对应同名工具的不同输入。每个调用有独立 UUID、参数副本、结果、错误、耗时和 `execution_mode`。
5. 整批只附加一条包含所有调用的 `AIMessage`，各结果有自己的 `ToolMessage`；同一 Action 模型请求的实际 Token 仅在第一条调用事件计一次，其余为 0。工具内部模型用量另保留，未知仍为 `null`。
6. 任一当前批次失败、资料不足或待确认，Observation 都不能用最后一条成功结果覆盖它并声称任务完成。仍可如实继续剩余步骤或说明未完成，未新增自动重试。

Thought 已选择 `answer` 时，Observation 的 Schema 只允许 `finish` 且答案非空；Python 再次校验。`task_complete=false` 仍可用于资料不足说明，避免“准备回答 → 不执行工具 → 继续等待”的无效循环。正常需要下一步工具时仍按既有 ReAct 分轮，上限仍为 8。

同步函数开始后，关闭生成器会等待当前线程池结束，不能强制取消函数。工具超时、限次重试和替代恢复仍属于待完成的 M3-04；线程上限不等于实现这些机制。

## 5 自动化验证及实际发现

新增 **22 项**，Agent **134 项**、全项目 **422 项通过，18.884 秒**。记录见 [最终验收日志](../../reports/工具路由与并行验收测试_20261002.log)。`pip check`、`git diff --check` 通过。

覆盖规则与实际注册表、概念/论文区分、多个意图/依赖/已有状态回退、规划 Schema/主要工具一致性、串行顺序、并行线程屏障、单项异常、调用上限、批次完整性/未知/重复拒绝、关闭前零执行、同批消息关联和只计一次模型用量、整批失败不可误完成，以及回答阶段拒绝空转/允许未完成说明。屏障要求两个真实线程同时到达，串行假实现会超时，不依赖容易抖动的耗时阈值。

模型 HTTP 在单元测试中明确隔离，不把 mock 当作模型质量或真实并发。真实验证另外记录以下问题和修复：

- 首版把单名称/名称数组放入同一字段；Qwen 的计划文字要执行工具，但输出 `next_step=answer`，空转至上限。改为独立 `parallel_tools` 字段后，实际模型能提出两个独立工具调用。
- 两篇论文元信息已实际返回时，Observation 仍继续；仅加强完成提示未解决。进一步让已选择回答的 Thought 对应只允许结束的 Observation，保留未完成标志，最终正确返回两篇标题与作者。
- 新路由绕过一个旧注册表测试 mock 的 Thought，误触发三次真实 RAG 读取。为只检查注册表的用例显式屏蔽路由后复跑通过；这三条本轮测试请求从业务统计移至 `logs/路由并行测试误调用_20261002.jsonl`，未执行文档写入/索引重建。相关失败日志 [回答阶段测试](../../reports/工具路由并行回答阶段测试_20261002.log)、[首次最终回归](../../reports/工具路由与并行最终回归_20261002.log)保留，没有隐藏错误。

## 6 真实本地模型结果

使用现有本机 Qwen2.5:7b、默认采样与 512 生成 Token 上限。主验证使用临时上传/日志路径，两篇完整公开 Attention/ViT PDF；工具解析、模型、执行器均真实，计时包装仅记录区间。Ollama 启动参数 `OLLAMA_NUM_PARALLEL=1`，GPU 模型计算仍可排队；预热单独记录，不计入比较。

当前时间样例的总 Token 从 4078 到 2613，减少一次规划模型请求；这是单题原 ReAct 的对照，不是固定每题走 RAG 的正式研究实验，也不等于课程宣传的 80% 节省。验证期间回归测试曾误占用模型服务，时间样例的耗时受到额外负载影响；不将 29.209→8.396 秒视为受控加速结论。

元信息串/并行执行段实际约省 1.25 秒，但只是一组热模型样例、固定执行顺序，存在缓存和调度影响。不同工具、设备、冷启动及 Ollama 并发配置的收益需要独立复测；并行不减少相同工具的模型 Token，也不能承诺端到端等比例加速。两篇 Agent 任务仍多花一轮生成最终答案，如实保留这个开销。

这些 `passed` 检查实际调用、同一轮批次、线程区间、返回结果及完成标志；不代表正式的路由准确率、引用质量或所有问题都能独立性判断正确。尚未做 50+ 题路由评分、全 RAG 对照、冷启动模型并发、安全取消、前端 Agent 接入及独立质量评分。本轮自启 Ollama 服务在验证结束后关闭。

## 7 复现

启动现有本机 Ollama/Qwen 后，在项目根目录运行；使用新输出路径，脚本拒绝覆盖历史实验。

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
.venv/bin/python reports/verify_routing_parallel.py --output reports/工具路由与并行新验证.json
```

`run_react()` 默认启用路由和独立批次；`think()`仍是可单独验证的模型规划入口。可用 `execute_calls(calls, tools, parallel=False/True)`对同一组已给定输入分别做串/并行比较。参数、真实模型和工具结果均不替换；只有对照用例关闭规则，路径与计时观察采用验证隔离。
