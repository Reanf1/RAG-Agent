## 分词与计分

- 沿用上游轻量分词：英文和数字按词、小写化；中文按单字。文档和查询使用相同规则，不引入 jieba、停用词库、词干处理或同义词扩展。
- 在分词前增加标准库 NFKC 归一化，处理学术 PDF 中的全角英文/数字。例如 `ＢＥＲＴ ２０２４` 与 `bert 2024` 具有相同词项。归一化只用于检索，返回的 Document 正文与元数据保持原样。
- 使用库默认参数 `k1=1.5`、`b=0.75`、`epsilon=0.25`；K 复用 YAML 的 `retrieval.top_k`，当前默认 5，不预建额外调参配置。

BM25Okapi 根据词频、文档长度、平均长度与文档频次计分：

```text
score(q, d) = Σ IDF(t) × f(t, d) × (k1 + 1)
              / [f(t, d) + k1 × (1 - b + b × |d| / avgdl)]
原始 IDF(t) = ln[(N - n(t) + 0.5) / (n(t) + 0.5)]
```

库会将负 IDF 替换为 `epsilon × 平均 IDF`；该平均值本身可能为零或负数。因此 BM25 分数不是概率，不一定为正，也不能与向量余弦相似度直接比较。词频增加的收益存在饱和，长度归一化用于避免长文档仅因词更多而占优。

上游只保留 `score > 0` 的块，实测在单文档语料中查询 `BatchNormalization` 得到约 `-0.27465`，两篇各含不同术语的语料中可能得到零分，直接过滤会漏掉命中。本实现先选择有查询词项交集的块，再按原始 BM25 分数降序取 K，保留零分和负分，不返回无词项交集的块。同分维持语料顺序，不额外加入排序算法。

中文按单字意味着存在共同字即可进入候选，不能当作完整中文词或短语的精确匹配。英文按完整词匹配，`Normalization` 不会命中 `BatchNormalization`；`BatchNormalization` 与 `Batch Normalization` 也不自动等同。词项或短语质量的优化留待后续评测。

## 索引生命周期与接口

`BM25Retriever(vector_store=None)` 从 `VectorStore.list_chunks()` 读取全文块，保留原有 `doc_id/chunk_id` 和位置，构建内存索引。空白/标点等无可检索词项的块不参与计分；全空语料不构造 BM25，以避免库内除零错误。

`search(query, k=None, doc_id=None)` 返回 `list[tuple[Document, float]]`。K 必须为正整数；空查询、无词项交集、空语料或指定文档无匹配返回 `[]`。文档过滤在 Top-K 截断前应用，分数仍基于完整语料的统计，不为每篇文档另算 IDF。

`rebuild()` 重新读取当前正文并更新词频统计，返回可检索块数，不重新计算文档向量。长期复用 Python 实例时，在新增/删除后调用；页面每次提交 BM25 查询都新建实例并读取最新语料，采用上游的小规模重建方式，不增加缓存失效机制或独立 BM25 持久文件。

为让 BM25 只读流程无需模型，`VectorStore` 构造不再加载 M3E；仅添加实际新块或有效向量查询前调用 `_ensure_embeddings()`。正文读取、计数、删除、重复块跳过及空/无匹配向量查询都无需权重。向量操作仍只使用配置的本地模型，失败明确上报；BM25 读取失败同样上报，不静默切换为向量检索。

## 使用方式

页面的“文档 Top-K 检索”选择 **BM25 关键词**，填写术语、K 和可选文档 ID，点击“检索”。结果显示 BM25 分数、原文块、文件名和来源位置，支持 PDF 页码、Word 段落/表格和 TXT/Markdown 行范围。已有知识库的 BM25 查询无需模型权重；新文献入库仍需要 M3E。

Python 示例：

```python
from src.retrieval.bm25_retriever import BM25Retriever

retriever = BM25Retriever()  # 从现有 Chroma 正文构建，不加载 Embedding。
for document, score in retriever.search("BERT", k=5):
    print(document.metadata, score, document.page_content)

# 外部新增/删除后，长期复用同一实例时刷新语料。
# retriever.rebuild()
```
