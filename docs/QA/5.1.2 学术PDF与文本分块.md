## 学术 PDF 处理

在现有 PyMuPDF 加载器内处理常见双栏、规则表格和公式，不新增 OCR 或视觉模型。

- 双栏：使用字符与行坐标，两侧长行且存在纵向重叠、中央留白时分栏；通栏标题／图表划分区域，区域内先左栏后右栏。长行宽度至少页宽 20%，中央留白至少 2%，为启发式条件，不保证不对称多栏或倾斜文字。
- 表格：网格表调用 `find_tables(lines_strict)`；有编号、横线区域和规则留白的三线表按列及文字基线提取。独立 Markdown 表格保留单元格空值，正文只留定位标记；无法可靠识别的复杂表头保留正文并警告。
- 跨页：只合并相邻页、上一片段位于末 25%、下一片段位于前 25%、列数一致且列边界差不超过 4 点的片段；还需原表编号及重复表头或同编号续表标记。去重表头，保留逐行真实页码；无证据不强并。
- 公式：保留 Unicode 数学符号，可识别上下标输出 `^{...}`／`_{...}`。`formula_layout`、`image_regions` 保存原位置／字号／图像区域，复杂分式和图片公式通过原 PDF 核对，不猜测完整 LaTeX。

依据：[PyMuPDF 字符与 span](https://pymupdf.readthedocs.io/en/latest/textpage.html#span-dictionary)、[表格 API](https://pymupdf.readthedocs.io/en/latest/page.html#Page.find_tables)。新增布局元数据采用 JSON 字符串，保留稳定表 ID、起止页、行来源及区域。返回数量可大于 PDF 页数。

## 三种分块

| 策略 | 实现 | 参数与重叠 |
| --- | --- | --- |
| 固定大小 | 步长 = 大小 − 重叠，字符窗口覆盖尾部 | 仅此策略实验比较 256／512／1024，重叠 64 |
| 递归字符 | `RecursiveCharacterTextSplitter`，段落→换行→句末→空格→字符 | 默认 512／64；实际重叠可能小于目标或为零 |
| 句段语义 | 短段落完整保留，长段按中英文句界拆分，超长单句字符兜底 | 默认 512／64；只在完整单元边界重叠，不使用 Embedding 聚类 |

统一入口 `split_documents()` 读取 YAML，大小为字符数，不是 Token 数。每块继承来源并补稳定 `chunk_id`、父正文字符区间 `[start_index,end_index)` 和策略参数；TXT／Markdown 细化行号，PDF 与 Word 不跨原内容单元合并。

独立识别的 PDF／Word 表格整块保留并标记 `chunk_preserved=table`，可能超限；Markdown 内嵌表格及复杂表格回退正文不在保护范围。固定窗口仍可能截断公式，原位置继承不表示当前块包含全部公式。[递归切分依据](https://docs.langchain.com/oss/python/integrations/splitters/recursive_text_splitter)
