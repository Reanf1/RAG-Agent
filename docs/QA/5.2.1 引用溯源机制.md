上游在上下文中编号并写文件名，要求模型注明来源，聊天接口返回检索到的文件名列表，前端用 caption 展示。测试检查 `sources` 与块数，没有验证答案中的编号、页码或对应原文。因此本项目沿用编号与简单字典，补充真正的答案引用映射，不把“检索过哪些文件”当成“答案引用了哪些证据”。

## 2. 本轮上下文的引用映射

`build_context()` 新增 `references` 列表，仅记录经过排序、预算筛选后实际入选的块，与 `[参考文档N]` 一一对应：

| 字段 | 依据与用途 |
| --- | --- |
| `id` | 本轮上下文中的连续编号；每次构建重新编号，不能跨请求复用 |
| `source_file`、`location` | 加载器的文件名及真实位置；PDF 物理页码/跨页范围、Word 段落或表格、文本行范围 |
| `text` | 实际送入模型上下文的正文证据；截断时仅保留前缀，不包含提示标记或未读尾部 |
| `metadata` | 原始定位快照，包括已有 `source` 路径、`doc_id`、`chunk_id`、页码和字符区间等；可含原始布局元数据 |
| `truncated` | 该块正文是否已被上下文预算截断 |

快照不修改原 Document，也不随调用方修改原 Document 而变化。原始块范围不能冒充截断后更精确的位置；缺少位置明确提示，不伪造页码。被预算排除的块不能获得编号或被后续引用。

## 3. 答案处理流程

`rag-v2` 要求模型在正文使用严格格式 `[参考文档N]`，在末尾 `## 参考来源` 只列编号，不自行补写文件名和页码。完整原始答案必须与生成它的同一份 Context 一起传入：

```python
resolved = resolve_citations(raw_answer, context)
```

处理规则：

1. 识别正文中有效编号，从映射补全文档名与真实位置。例如 `[参考文档1]` 展示为 `[参考文档1：attention.pdf；第3页（物理页码）]`。
2. 以正文首次引用的顺序返回证据。重复引用的来源列表只出现一次；同一文件不同块/页仍是不同证据，未使用的块不列入答案来源。
3. 丢弃模型约定的末尾 `## 参考来源` 区，按实际正文引用重建，避免采用模型手写的文件名或页码。该标题是约定的末尾来源区，后面内容不再作为答案正文。
4. 编号不存在时标记 `[无效引用：参考文档N]` 并返回提示，不猜测或改配文件。来源信息不完整、存在上下文却没有任何有效正文引用时也明确提示。
5. 常见 fenced/行内代码中的编号以及反斜线转义编号不视为依据；普通 Markdown 引用链接的模型地址不作为真实来源链接使用。文件名中的 Markdown 字符按文本转义。

返回值：`answer` 为最终 Markdown，`citations` 为实际引用证据快照，`invalid_citation_ids` 为无效编号，`missing_citations` 表示有上下文却没有任何有效正文引用，`warnings` 为校验提示。后续调用方必须展示提示，不能只展示答案而隐藏错误。空白答案直接报错。

这是面向约定输出的轻量解析，不是通用 Markdown 解析器；其他引用写法不自动推断。函数用于完整原始答案的一次处理，逐 Token 动态引用属于后续流式任务。

## 4. 调用示例

以下为 Codex 显式构造的功能样例，未调用业务 LLM：

```python
from langchain_core.documents import Document
from src.generation.rag_pipeline import build_context, resolve_citations

document = Document(
    page_content="功能示例：编码器由6层构成。",
    metadata={"source_file": "示例论文.pdf", "page_number": 3},
)
context = build_context("编码器有几层？", [(document, 0.9)])
raw_answer = "## 回答\n编码器有6层[参考文档1]。\n\n## 参考来源\n[参考文档1]"
resolved = resolve_citations(raw_answer, context)
print(resolved["answer"])
print(resolved["warnings"])
print(resolved["citations"][0]["text"])
```

已有检索结果可直接传给 `build_context()`，之后把 `context["context"]` 填入 Prompt，最后处理生成的完整原始答案。`context["sources"]` 是入选文件名，不等于最终答案实际引用来源，后者应使用 `resolved["citations"]`。

其中一个用例临时创建两页 PDF、含段落与表格的 Word、TXT 和 Markdown，调用真实加载器和默认分块，得到 6 个块；解析答案引用后逐一核对已有 `doc_id`、`chunk_id`、原文、文件路径及页/段落/表格/行位置。样例答案明确构造，不调用 LLM，也不替换加载器或分块器。
