# 5.2.4 RAG 请求日志与检索质量自评

实现与验证日期：2026 年 9 月 30 日。当前完整 RAG 请求入口为 Streamlit 聊天；上传与独立检索表单的日志、Agent 工具监控仍属于后续范围。`generate_answer()` / `stream_answer()` 是只消费给定 Context 的生成接口，直接调用它们不会冒充一次完整检索请求。

## 1 参考与实现方式

阅读固定上游 [utils/logger.py](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/utils/logger.py)、[core/metrics.py](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/metrics.py)及 `test_rag.py`、`test_api.py` 的分层/mock 测试方式。上游使用 Loguru 按日轮转、保留7天，指标是线程锁保护的内存累计，Token 用 tiktoken 估算；没有这里要求的完整请求 JSONL 与 Top-1 分布。

本项目保留按日文件和线程锁，使用 Python 标准库写入 UTF-8 JSONL，不新增依赖、服务或指标框架。使用已有 `paths.logs`，默认文件为 `logs/rag_YYYY-MM-DD.jsonl`；相对路径按项目根目录解析，不受启动目录影响。日期与时间统一为北京时间，旧文件保留，不自动删除原始证据。日志包含用户问题与原文，只保存在本地，`logs/` 已由 Git 忽略。

实现位于 [logger.py](../../src/utils/logger.py) 的 `record_rag_request()`、`read_rag_requests()`、`retrieval_score_distribution()`；[app.py](../../src/frontend/app.py) 负责把实际问答状态写入并展示统计。页面启动不会创建请求记录，也不会为统计加载模型。

## 2 每个请求记录的内容

| 字段 | 实际内容 |
| --- | --- |
| `request_id` / `session_id` / 时间 | 每次提交唯一编号、本页面会话编号、开始时间与本条快照时间 |
| `status` | started、retrieved、awaiting_confirmation、completed、error、cancelled、superseded |
| `question` | 本次用户问题，保留原文 |
| `retrieval` | 实际执行/空结果/失败/缓存跳过状态、配置的K、重排模型与版本、完整返回块及Top-1分数 |
| `retrieval.documents` | 每块排名、完整正文、原始来源元数据与模型分数；不足K如实记录实际数量 |
| `context` | 实际送入模型的拼接正文、来源映射、预算与截断状态；与完整召回正文分开保存 |
| `answer` / `raw_answer` | 页面展示答案与模型原始回答；失败时保存已收到部分，不把错误当答案 |
| `citations` / `warnings` | 同轮引用原文快照、缺引用/无效引用/长度上限等提示 |
| `timing` | 实际检索、生成处理和请求处理耗时，单位秒；请求处理不计等待用户确认的时间 |
| `tokens` / `usage` | 当前输入、输出、总Token及来源；服务原始用量/耗时另存 |
| `cache` / `original_usage` | 命中方式及原问题，原答案的服务用量单独保存 |
| 模型与配置 | 生成模型、服务配置、实际返回参数、Prompt版本及检索参数快照 |
| 错误 | 可操作提示、原始详情与重试建议；错误状态不标完成 |

Token 来源为 `ollama`、`cache`、`not_called` 或 `unavailable`。正常生成使用 Ollama 返回的 `prompt_eval_count` / `eval_count`；缓存、未生成的等待/取消请求确定为零。模型已尝试但断流或404等没有用量时保留 `null`，不能用零或字符估算值替代；输入/输出任一缺失时总量为 `null`。

每行是完整快照，不需要按碎片还原正文。开始时先记录；检索完成后在调用模型之前再次保存，避免生成中断后连Top-K也无法复查；结束/失败追加最终状态。低相关请求的确认、取消、被新问题替换使用原编号。读取时按编号保留最新快照，等待后确认不会把同一次检索计两次。缓存命中本轮未检索，`documents=[]`、`top1_score=null`，保留原引用而不声称它们是新召回结果。

追加和读取共用线程锁，适用于单个 Streamlit 进程的会话线程。文件有损坏或半行时保留原始内容，后续追加先隔开半行，读取跳过坏行并显示数量。写入失败会明确提示，不丢掉已完成答案；清空或替换待确认请求后也能显示故障。没有声称多进程写入、强制杀进程恢复或多用户压力测试已验证。

## 3 Top-1 分布的含义

页面底部“检索分数分布”从日志计算实际 RAG 检索的 **BGE sigmoid 重排Top-1分数**，显示10个区间的次数及样本数、均值、最小/最大值。区间左闭右开，最后一个包含1.0；模型与固定版本不同则单独分组。使用检索原始排名第一的分数，`context.top_score` 则是字符预算内实际入选块的最高分，两者可能不同，均保留用于诊断。

空结果、检索失败、缓存跳过单独计数，不把它们补成0分样本；真实0分的有结果检索仍计入第一档。生成失败之前已成功检索，其分数仍计入。统计包含历史会话的本地请求，不随清空当前对话而删除；普通页面重跑不增加日志或样本。独立检索表单的向量/BM25/RRF原始分数不混入本分布。

这是简单的相关性观察：低分集中时可排查语料、召回与跨语言问题。它不是已经校准的置信概率，不等于Hit@5、MRR或回答正确率。正式质量指标仍需要问题与相关块的标注，既有三档评测原始数据没有改写。

## 4 测试与真实验证

新增14项：8个真实临时文件测试、6个页面测试；覆盖完整长正文、UTF-8/换行、实际/未知/零用量、按日文件、重复快照、区间边界与模型版本隔离、空结果/缓存排除、坏行恢复、32次线程追加、序列化故障，以及确认/取消/替换/清空/重跑/断流/日志故障。生成模块123项、全项目 **288项测试通过（16.046秒）**，`pip check` 无依赖冲突。线程写入和确定数值是功能测试，不当作真实并发性能或模型用量实验。

[verify_rag_logging.py](../../reports/verify_rag_logging.py) 使用真实 M3E、BGE、Qwen2.5:7b、临时 Chroma 和 Streamlit AppTest；核对两篇公开论文PDF的SHA-256，加载两个真实标注块。默认用户知识库与日志目录没有用于实验，既有评测输入没有修改。以前的缓存/降级验证脚本也补上临时日志路径，避免复测污染用户的统计。

原始证据见 [验证结果JSON](../../reports/RAG日志与检索分数验证结果.json) 和 [真实请求JSONL](../../reports/RAG日志与检索分数验证结果.jsonl)，SHA-256匹配。5个请求、15条状态快照、4次有结果检索、1次空结果；页面真实显示分布图。均值0.512433，第一档1次、0.6–0.7档3次；其余区间为0，不人为补满样本。

| 场景 | 生成HTTP次数 | 输入/输出Token | 结果 |
| --- | ---: | --- | --- |
| 空库解释机器学习 | 1 | 435 / 39 | 完成、无引用，Top-1为空，独立计空结果 |
| BERT-base层数 | 1 | 833 / 21 | Top-1=0.683232；答12层但缺有效正文引用，有警告 |
| 重复同一问题 | 1 | 833 / 21 | 原答案不满足缓存条件，因此重新检索/生成，不能记为零用量或缓存跳过 |
| 无关地铁票价问题取消 | 0 | 0 / 0 | Top-1=0.00003742，取消请求仍保留一次真实检索样本 |
| 实际不存在的模型 | 1 | 未知 / 未知 | 真实HTTP404，错误/建议保留，已完成检索分数计入分布 |

这一轮真实模型漏写引用，因此缓存命中为0；复用检查正确验证了“不合格答案不得缓存”。缓存命中零用量、原始用量单列及不重复统计的路径由页面功能测试覆盖，先前真实缓存实验仍见 [语义缓存QA](5.2.3%20语义缓存.md)。本次未把模型回答标成独立人工质量通过。AppTest验证组件与状态，没有新增浏览器截图；报告中的耗时是实际AppTest处理时间，逐阶段耗时以JSONL的 `timing` 为准。
