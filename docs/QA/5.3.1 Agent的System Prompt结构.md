# 5.3.1 Agent的System Prompt结构（2026-10-02）

## 1 设计依据与实现范围

System Prompt规定Agent的身份、可以使用的能力和本阶段的输出契约。它帮助模型作出决策；工具查找、实际执行、结果检查和迭代终止仍由Python负责，不能仅凭一句“不要出错”保证正确。

本次读取固定上游的[对话Prompt](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/api/chat.py)、[工具绑定](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/llm.py)、[Agent](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/agent.py)及工具注册/API mock测试。上游已有助手角色、回答规范与bind_tools，但没有课程要求的三个阶段统一Prompt。本项目沿用Message和实际工具描述，补充共同角色与阶段输出约束，不照搬HTTP服务或云端模型。

此前Thought/Action/Observation已有各自的职责与约束，工具描述放在Human消息中。本次在[react_loop.py](../../src/agent/react_loop.py)新增`AGENT_ROLE_PROMPT`和`build_agent_messages()`，把三个阶段组织成统一结构；保留`build_thought_messages()`入口。不新建模板服务、配置层或Agent框架。

## 2 四段结构与消息边界

```text
SystemMessage
  【角色定义】      共同科研助理角色、语言与事实边界
  【可用工具描述】  当前注册工具的名称、用途与参数Schema
  【阶段职责】      当前Thought / Action / Observation要做的事
  【输出格式约束】  当前阶段必须返回的格式和结束规则

HumanMessage
  question、context；Action另含thought

AIMessage + ToolMessage
  Observation接收本轮实际调用和结果
```

**角色定义。** 系统是智能科研助理，帮助理解、比较和分析论文，中文简洁回答并保留英文术语与公式。论文事实依赖已有证据，区分事实和推断，不编造论文、页码或执行结果；只展示必要的计划/结果说明，不要求模型披露私有思维过程。

**可用工具描述。** 来自调用方实际传入的LangChain BaseTool或`@tool`，经`convert_to_openai_tool()`生成`name`、`description`、`parameters`，完整保留类型、必填项、枚举和默认值。用途来自代码中的工具docstring，参数来自函数注解与Schema；不能只写一个名字让模型猜参数。后续科研工具的docstring应说明用途、返回内容及已知限制。

Thought与Observation描述当前传入的全部工具，Action只描述Thought选中的一个工具，原生请求tools字段也只绑定该工具。空列表明确说明“当前没有可用工具”，不自动加入尚未开发的知识库工具或联网工具。工具描述是开发代码提供的定义，用户资料中的同名字段不能替换它。

**阶段职责。** Thought只规划一步，Action只准备一次调用并交给Python执行，Observation根据实际结果判断完整任务是否完成。三个阶段共享角色，职责与输出各自明确，避免把“选择工具”当作“已执行工具”，或把单次成功当作整个任务完成。

**输出格式约束。** 用文字解释字段含义，再用模型请求Schema和Python校验落实。用户问题、论文正文、Context、Thought内容及工具结果保留在数据消息中，不拼入System规则。中文、花括号和嵌套结构以JSON序列化；输入资料不会修改调用方Context。

## 3 各阶段输出契约

| 阶段 | 输出方式 | 必要约束 |
| --- | --- | --- |
| Thought | JSON Schema：thought、next_step、tool_name | 说明1～200字符；tool必须选择实际工具，answer的工具名为null；空工具列表的next_step枚举仅允许answer |
| Action | tools Schema：原生Function Calling | function.name匹配已选工具；arguments为参数对象，只返回一次调用；缺参不编造，不把文本JSON当作原生调用 |
| Observation | JSON Schema：observation、decision、task_complete、answer | continue时未完成且答案为空；finish时有答案或无法完成说明；最后一次工具失败不能标记成功 |

以下为格式说明，不作为模型实测数据：

```json
{"thought":"先用乘法工具计算。","next_step":"tool","tool_name":"multiply"}
```

Action原生`message.tool_calls`中的单个元素：

```json
{"function":{"name":"multiply","arguments":{"a":3,"b":4}}}
```

对于仅要求“3乘4”的任务，观察实际结果后的完成格式：

```json
{"observation":"乘法工具返回12，任务已完成。","decision":"finish","task_complete":true,"answer":"结果为12。"}
```

JSON格式正确不等于答案正确。Python继续检查字段、类型、工具名/参数及完成状态；工具查找与invoke仍使用真实注册表，最大轮次仍来自agent.max_iterations。Prompt不能代替业务校验、工具超时、引用语义验证和质量评测。

## 4 验证与复现

新增5项测试并更新既有消息/工具范围断言，Agent共45项，全项目333项通过（18.607秒）；pip check与git diff --check通过。新增用例核验三个阶段的统一结构、真实用途/类型/必填/枚举/默认值、用户资料及伪造工具描述隔离、空工具列表、未知阶段和空工具时的请求Schema。完整结果见[自动化复测日志](../../reports/AgentSystemPrompt自动化测试_20261002_复测.log)。

首次真实Qwen验证中，“未上传论文”在空工具列表下仍规划tool，Python拒绝了这个计划，没有执行假工具。问题在于文字规则要求answer，但JSON Schema仍允许tool。先用[失败测试](../../reports/AgentSystemPrompt格式约束缺陷复现_20261002.log)复现，再将空列表时的next_step枚举限制为answer；保留[首次实测JSON](../../reports/AgentSystemPrompt验证结果_20261002.json)，另存修复后的结果。
