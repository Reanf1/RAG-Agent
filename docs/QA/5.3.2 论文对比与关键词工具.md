## 2 论文对比：证据选择与原文表格

输入为`paper_a_id`和`paper_b_id`，必须是两个不同的已上传SHA-256文档ID。先检查原文存在、路径和内容指纹，再按ID读取各自索引。支持同名但内容不同的两篇论文，不将文件名当唯一标识。

```text
两篇上传ID
  → 各按方法/数据集/实验结果分别中英文查询
  → 向量 + BM25 + RRF + BGE精排，每个查询取2块
  → 同维度合并取2块、按稳定chunk_id去重
  → 读取首页/开头摘要块，给摘要单独留预算
  → 每篇本地模型选择三个证据编号（可为null）
  → 程序回填原文，形成三个维度的比较表并绑定引用
```

共12次顺序混合检索，不声称已完成Agent并行调用。每篇获得`generation.max_context_chars`的一半，当前3000字符，其中三分之一留给摘要，其余用于检索证据；输入会截断并明确记录。为复用模块二的预算与来源逻辑，`build_context()`新增本次预算参数，普通RAG默认行为不变。摘要来自已入库的真实块，新加入的摘要候选仍通过真实BGE评分，不伪造分数。

两篇分别按实际入选证据Top-1和现有0.1阈值判断；这一规则与模块二一致，分数不是命中概率。各维度的低分单独记录和警告，不要求所有检索块都达到阈值。缺一篇索引时`insufficient_evidence`，整篇低相关性时`needs_confirmation`，均不调用选择模型、不返回假比较；原文缺失/已改变、无效ID或预算错误由执行器如实记录。

最终选择Prompt要求区分本篇贡献、背景和前人方法。每篇只返回`method/datasets/results`三个本篇证据编号或null；Schema枚举限定实际来源，Python继续拒绝跨论文编号、布尔值、多余/缺失字段和未正常完成的响应。每篇独立选择，避免六字段混合时混淆论文归属。没有找到证据时表格写“资料不足”，返回`missing_dimensions`。

比较表中的内容明确标为**原文摘录**。程序不翻译或改写实验数字、任务与条件；通过`resolve_citations()`自动补全文档名和真实物理页码/非PDF位置。返回`comparison`结构化三行证据、`citations`、两篇资料和维度分数、截断/质量警告、实际模型调用与Token总量、工具耗时。Token只有两次模型均报告该项时才求和，否则保留未知。

该工具提供按同一维度并列的可追溯证据对照，不输出未经证据核对的自由改写结论。不同任务的BLEU和分类准确率不可直接排名。有效编号可以证明片段来自对应论文，仍不能自动证明该片段适合作为该维度证据；选择不完整、参考文献混入及检索质量不足需要人工核验和后续独立评测。无需让模型披露私有推理过程。

## 3 关键词提取

输入`text`（用户问题）或`doc_id`（已上传文档），必须二选一。默认最多5个关键词，不新增参数体系。文档复用原文加载器和现有开头读取函数：PDF前三页、其他格式开头连续前缀，预算6000字符；长问题也只取预算内前缀。返回`input_truncated`，不冒充全文主题分析或OCR。

本地模型按重要性选择中英文主题词/专业术语，返回JSON的`keywords`数组。Python检查类型、数量、非空值和原文存在性，允许空格、大小写与NFKC归一化，按原词匹配结果去重；不扩展同义词，不翻译或联网补充。英文匹配有字母边界，不将training中的字母片段误算为AI；跨行词组保留所有相关行的位置。

返回关键词、每个词对应的原文及位置、文档ID/文件名、截断状态、真实模型/用量和耗时；无实质主题可返回空数组。模型故障或编造词语由执行器明确失败，不自动重试或转云。原文匹配只验证词语存在，关键词是否最能代表主题仍需人工判断。

## 4 调用与状态

```python
from src.agent.tools import AVAILABLE_TOOLS, execute_tool

# 两个ID来自成功上传记录，而不是文件名或arXiv编号。
comparison = execute_tool("paper_compare", {"paper_a_id": doc_id_a, "paper_b_id": doc_id_b}, AVAILABLE_TOOLS)
question_terms = execute_tool("keyword_extract", {"text": "Transformer如何用于机器翻译？"}, AVAILABLE_TOOLS)
paper_terms = execute_tool("keyword_extract", {"doc_id": doc_id_a}, AVAILABLE_TOOLS)
```

执行器外层`status=success`只表示工具成功返回；仍需查看对比内层是否`needs_confirmation/insufficient_evidence`、是否有缺项或警告。Observation的Prompt与Python均禁止将待确认/缺少论文证据误标为任务完成。

真实关键词调用曾出现Observation以空答案结束。保留失败记录，将已有约束同步到JSON Schema：finish答案非空，continue答案为空且未完成。Ollama使用Schema分支时，每个分支都带完整字段、类型和required，避免稀疏分支导致其他字段丢失；Python校验继续保留。
