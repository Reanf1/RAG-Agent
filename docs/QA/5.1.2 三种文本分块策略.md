# 5.1.2 三种文本分块策略

**测试入口更新（2026-10-03）**：测试已按课程小节拆分，当前入口见[测试目录说明](../../tests/README.md)。本页历史测试数量、耗时及结论保留；复测命令使用当前路径。

实现日期：2026 年 9 月 29 日。范围：固定大小、递归字符、基于句子/段落边界的语义切分。单位为 Python `len()` 的字符数，不是字节数或模型 Token 数。

## 1 参考与实现取舍

已阅读固定版本的 [app/core/rag.py](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/rag.py) 和 [tests/test_rag.py](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/tests/test_rag.py)。上游在 RAG 引擎初始化递归切分器，`split_documents()` 调用该对象；测试覆盖短文档、长文档、元数据继承与长度。本项目将相同递归算法放入指定目录，固定和句段策略是课程补充。

递归沿用上游分隔符顺序：段落空行、换行、中文句末标点、英文句末标点、空格、单字符。设置 `length_function=len`、保留分隔符，并关闭首尾空白清理，便于定位原文。官方说明强调分隔符逐级处理和字符长度，重叠为目标值；见 [LangChain 递归切分文档](https://docs.langchain.com/oss/python/integrations/splitters/recursive_text_splitter)。具体运行 API 已核对安装的 0.3.5 源码。

新增 `langchain-text-splitters==0.3.5`，其依赖要求为 `langchain-core>=0.3.29,<0.4.0`，兼容当前 core 0.3.29 和 Python 3.10.10；见 [该版本发布信息](https://pypi.org/project/langchain-text-splitters/0.3.5/)。上游通过 `langchain==0.3.14` 间接依赖分块库，没有直接固定分块包版本。本次仅安装这一实际使用的依赖，不升级其他直接依赖。

语义切分按用户指定的句段边界实现，不加载 Embedding、不计算句子向量相似度、不增加 NLP 模型，学生可直接阅读规则和循环。

## 2 三种策略

| 策略 | 文件/函数 | 核心规则 | 重叠行为 |
| --- | --- | --- | --- |
| 固定 | `fixed_chunk.py / split_fixed()` | 从第一个字符开始，步长为 `chunk_size - chunk_overlap`；末块覆盖尾部后停止 | 相邻正文窗口精确重叠设置的字符数 |
| 递归 | `recursive_chunk.py / split_recursive()` | 调用 `RecursiveCharacterTextSplitter`，从粗分隔符逐级递归到字符 | 在切分单元之间选取，可能小于设置值或为零 |
| 句段 | `semantic_chunk.py / split_semantic()` | 短段落完整保留，长段落拆句；超长单句按字符兜底；按大小合并相邻单元 | 仅复用完整尾部单元，保证下一块能加入新内容；可能为零 |

句段规则识别 LF/CRLF 空行作为段落边界，中文 `。！？`、英文 `!?` 为句末；英文句点后需为空白或段尾，避免从 `3.14` 或 `10.1000/xyz` 中间拆句。句末引号、右括号跟随原句。英文缩写、无空格的英文句子、不规则排版不保证语言学意义上的完美句界；单句超过大小仍会按字符切开。

重叠不会跨越父内容单元：PDF 不合并不同正文页，Word 不合并不同段落或表格。全部策略不清理或改写块内文本，空文档和仅空白块跳过。

### 表格与公式

已独立标记的 PDF 表格（`content_type=table`）和 Word 表格（`block_type=table`）整块保留，不截断表头、单元格或跨页行来源。增加 `chunk_preserved=table`，表格可能超过 `chunk_size`；普通正文严格限长。Markdown 内嵌表格、回退为正文的复杂 PDF 表格不在这项保护范围内。以后接入模型上下文时仍需核验超长表格预算，不能直接假设所有块都不超限。

PDF 的 `formula_layout`、`image_regions`、`table_rows`、`table_regions` 等来源字段继承到块。公式原位置字段属于整个父内容单元，不表示其中每个公式都落在当前字符区间。固定窗口或超长单句兜底可能截断公式字符串；原 PDF 和位置继续保留供核验，不宣称公式自动还原或完整 LaTeX。

## 3 接口、配置和元数据

三个直接函数接口相同：

```python
split_fixed(documents, chunk_size, chunk_overlap=0)
split_recursive(documents, chunk_size, chunk_overlap=0)
split_semantic(documents, chunk_size, chunk_overlap=0)
```

接收、返回 `list[langchain_core.documents.Document]`。块大小必须为正整数；重叠必须为整数且满足 `0 <= chunk_overlap < chunk_size`。非法参数和未知策略明确报错。

统一入口位于 `src/chunking/__init__.py`，未指定参数从唯一配置 `config.yaml` 读取。当前默认 `recursive`、512 字符、64 字符重叠；上游 500/50 是参考值，不是本项目生效值。仅固定切分比较 256/512/1024 的效果；递归和句段策略调用统一入口时仅指定策略名，使用默认参数，不开展这两种策略的大小参数对比：

```python
from src.data_loader import load_document
from src.chunking import split_documents

documents = load_document("data/raw/论文.pdf")  # 替换为真实文件路径。
chunks = split_documents(documents)
for size in (256, 512, 1024):
    chunks = split_documents(documents, strategy="fixed", chunk_size=size)
chunks = split_documents(documents, strategy="recursive")
chunks = split_documents(documents, strategy="semantic")
```

| 新增字段 | 含义 |
| --- | --- |
| `chunk_id` | SHA-256：文档 ID（无 ID 时使用来源）、页/正文块/表格位置、父正文、策略、参数和字符区间共同确定 |
| `chunk_index` | 当前父 Document 内切分区间的索引，从 0 开始；跳过仅空白区间后可能不连续 |
| `chunk_strategy` | `fixed`、`recursive` 或 `semantic` |
| `chunk_size`、`chunk_overlap` | 本次使用的大小与重叠目标，非实际块长度/实际重叠量 |
| `start_index`、`end_index` | 相对父 Document 的字符区间，左闭右开；不是整个 PDF 的字符偏移 |
| `chunk_preserved` | 独立表格为 `table`，普通正文不添加该字段 |

重复执行和同一文档的副本在内容/位置/配置一致时块 ID 稳定；重复正文位于不同 PDF 页或 Word 正文块时 ID 不同。子块复制来源元数据，不修改输入 Document。TXT/Markdown 的 `line_start/line_end` 细化到当前区间，CRLF 按一个换行处理；Word 保留 `block_index` 等位置，不伪造物理页码。

## 4 验证与结果

新增 21 个分块测试，加载、分块、批量导入与界面共 79 个测试通过，`pip check` 通过。测试范围包括三种策略的长度、重叠、字符兜底、句段边界、参数校验、来源保留、稳定 ID、原文区间、CRLF 行号，以及真实 Word/PDF/TXT 加载后直接切分。

测试先复现上游 `add_start_index=True` 的位置问题：在重复段落、大小 16/重叠 15 的情况下，查找可能返回与前一块相同的起始位置。保留真实 LangChain 切分算法，改为用其输出文本查找原文：下界同时满足“前一块结尾减重叠”和“前一起点加一”，保证位置向前推进。重复文本、无分隔符文本、CRLF 文本的多组大小/重叠组合，均核验块内容等于原文区间且所有非空白字符被覆盖。

```bash
.venv/bin/python -m unittest "tests.5_1_2 文本分块策略.test_chunking.TestChunking" -v
.venv/bin/python -m unittest discover -s 'tests/5_1_2 文本分块策略' -p 'test_*.py' -v
.venv/bin/python -m pip check
```

同一公开论文五组分块统计（固定三档、递归和句段各一组默认参数）与复现方法见 [分块策略对比实验报告](../../reports/5_1_2%20文本分块策略/分块策略对比实验报告.md)。单元测试中的小尺寸/大重叠仅用于检验边界和已复现的位置问题，不属于递归/句段策略的参数选型实验。目前未构建 Embedding、检索索引和标注问题，未计算召回、Hit@5/MRR；不能凭块数或平均长度评选最优策略。

三种分块可通过 Python 调用；Streamlit 当前导入仍只保存文件和加载正文，尚未自动分块和构建索引。技术设计中 M1-03 为部分实现，保留后续召回对比的验收要求。

## 2026年10月4日：五组检索实验完成

同一12篇英文视觉Transformer论文和60题，固定256/512/1024、递归默认512/64、语义默认512/64，共300次实际混合＋重排查询；K=3/5/10的900组逐题指标独立复算通过。递归Hit@5为66.67%、Recall@5为42.97%，最高；固定512的MRR@5为0.3708，更高。保留递归默认，不能称全部指标都最优。耗时共享负载且发生断点恢复，不能作隔离速度排名。[完整方法、数据与限制](../../reports/5_1_2%20文本分块策略/五组分块检索对比实验报告_20261004.md)。
