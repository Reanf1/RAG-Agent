# 5.3.1 Action：工具选择与执行（2026-10-02）

## 1 实现范围

在[react_loop.py](../../src/agent/react_loop.py)增加`act(question, thought, tools, context=None)`，承接Thought的候选工具，使用本地Ollama原生Function Calling生成一次参数，然后交由[tools.py](../../src/agent/tools.py)的`execute_tool()`实际执行。

模型只收到本步已选择工具的Schema；没有再次开放整个工具集。Thought规划`answer`时返回`action_skipped`，不调用Action模型或工具，也不生成最终答案。当前支持同步LangChain BaseTool与`@tool`，不引入Agent执行框架、新依赖或配置层。

本次完成单轮Action基础能力。八个生产科研工具尚未开发，工具注册列表由调用方提供；验证脚本的开发工具不计为生产工具集。Observation反馈、再次Thought、有界循环、并行、工具执行超时、重试/替代恢复与前端接入仍待实现。只记录异常不等于已完成错误恢复。

## 2 参考与本地适配

已读取固定上游[Agent源码](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/agent.py)、工具注册测试与API事件测试。沿用“注册表查找→tool.invoke→工具结果”的执行方式，以及`tool_call`、`tool_result`事件和关联ToolMessage；不照搬云端ChatOpenAI、高层执行器或HTTP/SSE服务。

根据[Ollama官方工具调用文档](https://docs.ollama.com/capabilities/tool-calling)，本地请求使用`tools`字段和非流式`/api/chat`，读取`message.tool_calls[].function.name/arguments`。已在本地Ollama0.34.0与Qwen2.5:7b实测，不把之前Thought的JSON Schema当成工具调用。

Thought与Action共用一个小型`_model_request()`，读取原有`llm`地址、模型和采样参数，继续只允许本机HTTP、绕过系统代理。完整回归验证Thought既有行为保留。

## 3 执行与事件

```python
from langchain_core.tools import tool
from src.agent.react_loop import think, act

@tool
def multiply(a: float, b: float) -> float:
    """计算两个数的乘积。"""
    return a * b

# 需先启动本地Ollama；此例工具由调用方明确提供。
tools = [multiply]
question = "3.14乘以2.56是多少？"
thought = think(question, tools)
for event in act(question, thought, tools):
    print(event["type"], event.get("result"), event.get("error"))
```

`act()`是生成器，必须持续消费才会执行。首个`tool_call`事件到达时工具尚未运行，继续消费产生`tool_result`；中途关闭会停止未开始的执行。不会自动重试、循环或返回伪造的done/最终答案。

| 事件 | 主要字段 |
| --- | --- |
| `tool_call` | `call_id`、工具名、模型原始参数、实际模型/输入输出Token、参数生成耗时、含对应调用ID的AIMessage |
| `tool_result` | 同一`call_id`、工具名/参数快照、`status=success/error`、真实`result`、错误详情、执行耗时和ToolMessage |
| `action_skipped` | Thought规划直接回答时的跳过说明 |
| `error` | 无效计划、模型/网络/调用格式故障的提示、详情和重试建议；不执行工具 |

ToolMessage的`tool_call_id`关联AIMessage的工具调用ID，状态区分成功/失败；消息正文采用上游的文本方式，事件`result`另外保留原始结构化返回值，避免丢失来源等信息。本次仅准备消息，尚未把它们接回下一轮模型。

工具名必须存在且匹配Thought。空/多次调用、切换工具、字符串代替参数字典、未完成响应和输出截断在执行前拒绝。多余字段与非法JSON/非有限值提前拒绝；必填项和参数类型由LangChain/Pydantic校验，遵循其默认转换规则，不额外承诺严格类型模式。

工具异常返回`status=error`、`result=None`及实际异常详情，不假称成功。参数深拷贝保护调用记录；原始选中工具固定用于本次执行，消费首个事件后改变调用方注册列表也不会换成同名其他工具。同步`invoke()`没有额外执行超时控制，后续M3-04再实现。

本轮服务只监听本机、关闭云端，用已有本地权重；结束后关闭本轮服务，不写用户文献、索引或RAG聊天日志。真实生成可能改变参数或拒绝调用，复测按原始结果判断，不保证每次都获得相同用量与耗时。
