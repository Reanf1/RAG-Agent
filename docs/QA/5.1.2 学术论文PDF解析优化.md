# 5.1.2 学术论文 PDF 解析优化

实现日期：2026 年 9 月 29 日。环境：Python 3.10.10、PyMuPDF 1.28.2；没有新增依赖。

## 1 目标与依据

在现有 `src/data_loader/pdf_loader.py` 内补充常见双栏阅读顺序、规则表格及跨页续表、公式保留。接口仍为 `load_pdf(file_path) -> list[Document]`，批量导入无需增加第二套解析流程。

已核对 [参考固定版本](https://github.com/dsy1018/ai-chatbot/tree/6979d7173ed0f92910a8571dd4ca1b4a171a2c49) 的 `app/core/rag.py` 与 `tests/test_rag.py`：其 PDF 为普通 Loader，未实现上述版面处理。本次沿用 Document/来源字段和基础工程结构，算法作为课程补充，不声称来自上游现成功能。

PyMuPDF 的位置和字号接口为本次处理提供基础：[文本处理指南](https://pymupdf.readthedocs.io/en/latest/recipes-text.html)、[TextPage 字符与 span 字段](https://pymupdf.readthedocs.io/en/latest/textpage.html#span-dictionary)。网格表和原图定位使用其 [Page API](https://pymupdf.readthedocs.io/en/latest/page.html#Page.find_tables)。以下分栏、续表和保留条件是本项目实现选择，不是库保证的准确率。

## 2 双栏阅读顺序

初版 `get_text("text", sort=True)` 按位置输出，同高左右栏可能交错。新增测试已复现该现象。

现在读取字符/文本行的坐标：两侧各至少两条较长文本行、存在纵向重叠、中央有明显留白时，按常见居中双栏处理。通栏标题、图表占位和通栏小节作为区域边界，每个区域读完整左栏，再读右栏；单栏则按纵向位置排序。

长行最低宽度为页宽 20%，中央留白最低为页宽 2%；这些只是明确的启发式条件，不是经过大规模实验得到的最优参数。检测不处理任意多栏、复杂不对称栏、竖排或倾斜文本的语义阅读顺序；没有通栏边界的短段落属于哪一栏仍可能有歧义。不删除页眉、页脚或推测性拼接断词。

## 3 表格提取与跨页合并

网格表使用 `find_tables(strategy="lines_strict")`，立即复制实际单元格数据，避免保留依赖页面生命周期的表对象。规则三线表需有 `Table/表/续表 + 编号` 标题和横线区域：按横向文字覆盖及留白分列，按主字号基线划分数据行，表头可多行。小于 5 点的横向间隔视为同一列，避免把公式字符拆列。

密集行的字形框可能重叠，使用相邻基线中点作为行边界，并按字符原点过滤裁剪边缘的邻行残片。复杂多级三线表无法可靠确定列时，记录警告并保留原始正文，不移除原数值。未对整页使用文本对齐识别表格，避免将双栏正文误当作表格。

每张表独立返回 Markdown Document，正文对应区域只保留表格定位标记，防止重复单元格文字。空格保持为空，不用上下行数值填充；单元格换行转为 `<br>`，竖线转义。网格中的物理合并单元格可包含多条文字，不等于已拆出每个逻辑实验行或指标列。

跨页合并同时要求：

- 物理页码相邻；上一片段结束于页高 75% 以后，下一片段从页高 25% 以内开始。
- 列数量一致，列起点和右边界差异不超过 4 点。
- 首片段有表编号；下一页重复表头，或有同编号的明确 `continued/续` 标记。编号冲突不合并。

去除重复表头，保留数据首行；无重复表头只在同编号明确续表时合并。无编号的两张表不单凭相同表头合并。中间续页未重复标题时沿用首片段编号，支持三页以上连续片段。无明确证据、页码断开、页边条件不符或列结构变化时分别保留，不强行合并。

## 4 公式与原图保留

保留原文本层的 Unicode 数学字符，不删除希腊字母、积分、求和或根号。对水平文本中的上标标志，以及较小字号且偏离主基线的字符，输出 `^{...}`、`_{...}`；如 `x^{2}`、`a_{i}`。这只是保留上下标关系，不表示整段文字已转为有效 LaTeX。

检测到数学符号/上下标的页面，将原文本行、span 的文字、位置、字号和标志保存到 `formula_layout`。二维分式不猜测分子/分母关系，原 PDF 保留其字形和分数线；图片区域另保存位置，并在正文留下图像标记。图像区域不自动判断为公式，当前没有公式 OCR 或视觉模型。

示例：按持久来源回看图片公式，坐标使用 PyMuPDF 的点单位：

```python
import json
import pymupdf
from src.data_loader.pdf_loader import load_pdf

# 选择含图像的正文页；原 PDF 仍是精确的视觉依据。
document = next(d for d in load_pdf("论文.pdf") if "image_regions" in d.metadata)
region = json.loads(document.metadata["image_regions"])[0]
with pymupdf.open(document.metadata["source"]) as pdf:
    page = pdf[region["page_number"] - 1]
    page.get_pixmap(clip=region["bbox"]).save("formula-preview.png")
```

没有文本层的整页扫描件仍按原行为警告/跳过，全篇无文本报错；不以图像标记冒充已解析。遇到无法映射字符时记录警告，需按原 PDF 核对。当前前端没有区域预览组件，仅展示导入状态；裁剪接口与位置已在测试中实际验证。

## 5 输出与来源字段

普通正文仍逐页返回原来源和物理页码。检测到表格后，额外返回独立表格，数量不再等于 PDF 页数；各页正文在前，表格随后。所有内容共用文件字节 SHA-256 的 `doc_id`。

| 字段 | 含义 |
| --- | --- |
| `layout` | 识别到双栏时为 `two_column`；未写入时不代表完整布局识别已通过 |
| `formula_layout` | 数学页面原文本布局的 JSON 字符串，保留行/字形位置与字号 |
| `image_regions` | 图片区域的 JSON 字符串，含 `page_number`、`bbox` |
| `content_type` | 独立表格为 `table`，普通正文保持原接口 |
| `table_id` | 文档 ID 加表序号，重复加载同一文件时稳定 |
| `page_number`、`page_end` | 表格起始与结束的物理页码；`page` 仍为起始页的 0 基索引 |
| `table_rows` | 逐行 `cells` 和真实 `page_number`，JSON 字符串；含首表头，已去重续页表头 |
| `table_regions` | 各片段的页码和区域，JSON 字符串 |

元数据的新增复杂字段采用 JSON 字符串，后续索引可保持简单字段类型。批量导入保存原 PDF 后照常更新 `source`，位置字段不含临时路径；图像定位测试已验证保存后的来源仍可打开和裁剪。未来分块需保留表格与这些来源字段，尚未实现分块实验。
