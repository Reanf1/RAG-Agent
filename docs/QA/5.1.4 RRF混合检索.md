## 2. 算法与教学示例

对一个文档块，把它在两路候选中的排名贡献相加：

```text
RRF(d) = Σ 1 / (rrf_k + rank_i(d))
```

`rank` 从 1 开始；某一路没有召回该块，贡献为 0。默认 `rrf_k=60`，用于平滑前后排名的差距。向量余弦相似度与 BM25 原始分数不参与相加，避免两种量纲直接混用。RRF 分数用于排序，不是相关概率。

以下为单元测试的手算示例，不是论文检索实验：向量排名为 A、B、C，BM25 排名为 B、C、D。

| 块 | 向量排名 | BM25 排名 | RRF 分数 | 最终排名 |
| --- | --- | --- | --- | --- |
| B | 2 | 1 | `1/62 + 1/61 ≈ 0.032522` | 1 |
| C | 3 | 2 | `1/63 + 1/62 ≈ 0.032002` | 2 |
| A | 1 | 无 | `1/61 ≈ 0.016393` | 3 |
| D | 无 | 3 | `1/63 ≈ 0.015873` | 4 |

每路同一块重复出现时只用第一次的排名，不重复加分；其后其他块仍使用原列表位置。合并后保留第一次出现的完整 Document，不改写正文、来源或页码。纯函数 `rrf_fusion()` 返回全部融合候选，混合检索接口再截取最终 K 项。

## 3. 调用与配置

实现文件：[hybrid_retriever.py](../../src/retrieval/hybrid_retriever.py)。已准备本地 M3E 权重且已有 Chroma 索引后，从项目根目录调用：

```python
from src.retrieval.hybrid_retriever import HybridRetriever

retriever = HybridRetriever()
for document, score in retriever.search("Transformer 使用了什么方法？", k=5):
    print(document.metadata, score, document.page_content)

# 可传入真实文档 ID，限制两路都只搜索同一篇论文。
# results = retriever.search("实验结果", k=5, doc_id="实际文档 ID")

# 返回融合后的 Top-20，供后续模型重排使用；此处尚未执行重排。
candidates = retriever.search("注意力机制", k=20)
```

默认读取 `config.yaml` 的 `retrieval.top_k=5`、`candidate_k=20`、`rrf_k=60`。每路实际请求 `max(candidate_k, 最终K)`；不足时使用实际返回结果，不能用补齐或重复项冒充候选。最终 K、候选数必须是正整数；RRF 常数允许非负整数，0 只用于边界测试，业务默认仍为 60。

`HybridRetriever(existing_store)` 可以复用现有 VectorStore。两路共享同一 Chroma，BM25 每次查询从当前正文重建小规模内存索引，新增/删除后再查即可，不维护第二份正文，也不重新编码旧文档。向量查询只编码问题。独立长期复用 `BM25Retriever` 仍按原接口调用 `rebuild()`，与混合接口区分。

空问题、空库或无匹配文档返回空列表，不加载 Embedding。有效混合查询需要本地 M3E；某一路正常返回空列表时使用另一条排名，模型或数据库异常则明确上报，不静默切换检索方式。没有关键词命中不等于语义检索没有结果。

页面在“文档 Top-K 检索”选择“RRF 混合检索”，沿用 K、文档 ID 和来源展示；结果标注 RRF 分数。与其他检索方式的分数不能直接比较。
