# 5.1.3 向量相似度 Top-K 检索

## 实现与参考依据

沿用已选定的本地 **M3E-base + Chroma**，保持原目录和依赖。存储封装阶段已有 `VectorStore.search()`，本轮核对其数量、排序和来源，补充空问题提前返回，并将接口接入 Streamlit 查询表单，不新增检索类或服务。

已阅读固定参考版本的 [RAGEngine._retrieve_vector()](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/rag.py)、[检索测试](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/tests/test_rag.py) 和 [前端来源展示](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/frontend/app.py)。沿用 LangChain Chroma 查询流程，保留完整 Document 与分数，便于后续混合检索及评测。

上游对分数使用 0.3 阈值、全部较低时才保留原结果。本任务要求返回 Top-K，因此不照搬该固定阈值，避免有匹配块却不足 K；分数不解释为命中概率。生成层的低相关性判断留待后续实测实现。

## 查询流程与分数

1. 校验 K 为正整数，未指定时读取 `config.yaml` 的 `retrieval.top_k`，当前为 5。
2. 空问题直接返回 `[]`；读取全库或指定 `doc_id` 的块数，无匹配则返回 `[]`。
3. 真实 M3E 现场编码问题，复用索引中的文档向量，不重新编码旧文献。
4. Chroma 在 `cosine` 距离下查询 `min(K, 匹配块数)` 个结果；按距离升序返回。
5. 将距离转为相似度，返回 `list[tuple[Document, float]]`，包含正文、完整来源元数据与分数。

余弦相似度与距离的关系为：

```text
similarity(q, d) = (q · d) / (||q|| × ||d||)
cosine_distance = 1 - similarity
返回分数 = 1 - Chroma 返回的 cosine_distance
```

理论范围为 `[-1, 1]`，浮点计算可能有微小误差。分数越高越相关，允许负分；不取绝对值，不裁剪为概率。不同模型的分数不能直接混用。Chroma HNSW 是近似最近邻索引，当前 `search_ef=100`；结果按返回分数降序，但不承诺所有数据和查询都与全量精确搜索一致。

## 使用方式

先按 [用户手册](../用户使用手册.md) 准备本地 M3E 权重，导入文档并完成索引。页面“向量相似度 Top-K 检索”支持中英文查询、K 输入和可选文档 ID；留空 ID 搜索整个持久化知识库，不只搜索本批上传文档。

结果逐块展示原正文、余弦相似度、文件名和文档/块 ID。PDF 显示物理页码或跨页范围；Word 显示段落/表格位置；TXT/Markdown 显示行范围，不伪造页码。表单提交时更新结果，其他页面操作重跑后可以重新检索。

Python 调用：

```python
from src.retrieval.vector_store import VectorStore

store = VectorStore()  # 本地模型与已有 Chroma 集合，不重建索引。
results = store.search("论文采用了什么方法？", k=5)
for document, similarity in results:
    print(document.metadata, similarity, document.page_content)

# 可限定一篇文献；将 ID 替换为检索结果中实际的 doc_id。
# results = store.search("What dataset does the paper use?", k=3, doc_id="实际文档 ID")
```

页面启动和提交空问题不加载模型；有效查询初始化 `VectorStore()` 时需要本地权重，包括空库场景。空库/文档 ID 无匹配会提示先导入或检查 ID，且不计算查询向量。模型或数据库异常单独显示，修复后重新提交即可；不把异常伪装成空库，不转云端。当前只返回相关片段，不调用 LLM 生成答案。
