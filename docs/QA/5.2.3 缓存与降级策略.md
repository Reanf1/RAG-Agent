# 5.2.3 缓存与降级策略

## 缓存范围与失效

`SemanticCache` 支持标准化问题精确命中和本地 Embedding 余弦匹配，阈值0.97、最多100项。相似匹配先核对数字、实体标识、否定词及回答语言等保守约束；上下文指代追问跳过缓存，不缓存整个多轮 Agent 回答。

科研对话在核心 `knowledge_base_search` 内接入缓存，按用户／当前会话隔离。知识库内容、文档过滤、模型／Prompt／检索／生成配置改变后范围失效。仅缓存自然结束、非空、grounded、有效正文引用、无警告的回答；低相关、无证据、失败、截断不入缓存。合法引用并不保证语义正确，历史误拒答被缓存的案例仍保留。

命中复用答案和来源，工具不重新检索／重排／生成，当前工具生成Token为0、保留`original_usage`；Agent其他阶段仍可消耗Token。日志记录cache状态，不能当作新检索。

## 三类降级

| 条件 | 行为 |
| --- | --- |
| 无检索结果 | 纯模型回答，明确“当前知识库中未找到相关文档”；不能作为论文证据 |
| 实际入选块的BGE sigmoid Top-1低于0.1 | 返回`needs_confirmation`，展示候选／来源，等待用户确认或取消；恰好达到门槛正常生成 |
| 模型API失败或断流 | 友好原因和重试建议，保留部分答案及失败状态，不伪造完成或静默转云端 |

## 科研对话候选确认

Python Observation结束等待态，模型不能自行确认。页面保存候选Context审阅快照与不透明确认ID；确认时核验用户、会话、原问题／过滤、语料和配置，固定使用已审阅参数，复用候选生成，不再次检索。取消不调用LLM；新问题、切换会话、页面断开或范围变化使确认失效。确认答案保留低相关声明及引用，不进入缓存。

指标把cache和confirmed复用排除新检索次数、候选命中率分母及平均检索耗时；原候选搜索只计一次，用户阅读等待不当作模型响应耗时。

## 验证与局限

2026-10-04临时Chroma／原文、明确二维向量及mock模型验证：首次低相关搜索1／生成0，取消后不变；重新提问2／0，确认后2／1；正常问答3／2，相同问题精确命中后仍3／2。浏览器截图与调用计数为功能证据，不作性能结论。

Windows新入口2026-10-05[复测](../../reports/5_4_4%20端到端联调与测试/Windows浏览器复测_20261005/Windows浏览器复测报告.md)候选等待、取消、确认通过，确认未新增检索；空库提示丢失、有原文却拒绝溯源仍失败。重复问题由Agent直接复述历史，没有新增核心工具调用，精确／语义缓存及范围失效未独立验证；正式性能未运行。旧真实M3E缓存与降级失败不覆盖，见[历史及修复证据](../../reports/5_2_3%20缓存与降级策略/README.md)、[688项通过](../../reports/5_2_3%20缓存与降级策略/候选确认接入_20261004/全量688项通过.log)。实现：[cache.py](../../src/generation/cache.py)、[RAG](../../src/generation/rag_pipeline.py)、[工具](../../src/agent/tools.py)。
