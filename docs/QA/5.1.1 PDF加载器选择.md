# 5.1.1 PDF 加载器选择

资料查询与实现日期：2026 年 9 月 29 日。

## 1 结论与范围

选择 **PyMuPDF**，在 [pdf_loader.py](../../src/data_loader/pdf_loader.py) 实现分页文本加载。按用户指令，PyPDF2、pdfplumber 只做官方资料对比，不安装、不实现另外两套加载器。本次目标是为分块和检索提供论文正文、来源与页码，采用普通 Python 函数，不增加解析器插件或独立服务。

“最优”指符合当前本科项目的任务和实现规模，不表示在所有 PDF、表格或复杂版面上都优于其他工具。资料比较不能代替三库在同一论文上的实测，本文不提供未经测量的准确率或速度提升。

## 2 三种方案的官方资料对比

| 比较维度 | PyPDF2 | pdfplumber | PyMuPDF |
| --- | --- | --- | --- |
| 定位与基础能力 | 纯 Python PDF 工具，可逐页提取文本，并进行合并、拆分等操作 | 基于 pdfminer.six，关注字符和图形位置、文本/表格提取、版面调试 | 基于 MuPDF，提供文本提取、页面渲染和位置相关接口 |
| 本项目正文加载 | `PdfReader` / `extract_text()` 可以实现基础加载 | `extract_text()` 可以实现基础加载，有较多布局调节参数 | `open()` / `get_text()` 可直接遍历页面并返回文本，代码较短 |
| 阅读顺序与表格 | 官方说明 PDF 缺乏语义结构，表格、公式和阅读顺序均有歧义 | 提供表格识别和可视化调试，适合以表格为主的分析 | `get_text(..., sort=True)` 提供位置排序；另外有 `find_tables()`，本次未接入 |
| 扫描件 | 不提供 OCR，不能从纯图片中直接读出文本 | 不提供 OCR，官方说明更适合机器生成的 PDF | 可调用 Tesseract OCR，但需要另装该软件；本次只使用已有文本层 |
| 维护情况 | PyPDF2 已合并回 pypdf；比较旧工具时不能混用两个包的版本和结论 | 官方仓库提供现行接口和示例 | 官方提供现行文本 API 和常见平台安装包 |

上表 PyPDF2 信息依据 [PyPDF2 文本提取文档](https://pypdf2.readthedocs.io/en/3.x/user/extract-text.html) 和 [pypdf 项目历史](https://pypdf.readthedocs.io/en/stable/meta/history.html)。pdfplumber 信息依据 [官方 README](https://github.com/jsvine/pdfplumber)，包括其文本/表格接口及无 OCR 的说明。PyMuPDF 信息依据 [文本处理指南](https://pymupdf.readthedocs.io/en/latest/recipes-text.html)、[Page API](https://pymupdf.readthedocs.io/en/latest/page.html#Page.get_text)、[安装文档](https://pymupdf.readthedocs.io/en/latest/installation.html) 和 [OCR 说明](https://pymupdf.readthedocs.io/en/latest/recipes-ocr.html)。

## 3 为什么选择 PyMuPDF

### 3.1 以论文正文入库为先，接口足够简单

当前 RAG 先需要逐页正文和页码，用 `pymupdf.open()` 打开文档，逐页 `get_text("text", sort=True)` 即可；上下文管理器自动关闭文件。未来若验证双栏顺序需要位置分析，同一库的 `blocks`、`words` 等输出可提供坐标，无须立即引入另一套解析框架。这是根据当前任务做出的工程选择。[官方文本指南](https://pymupdf.readthedocs.io/en/latest/recipes-text.html)

pdfplumber 的字符定位、表格提取和可视化调试有价值，但本轮不实现结构化表格分析；保留为文档中的对比对象即可。[pdfplumber 官方 README](https://github.com/jsvine/pdfplumber)

### 3.2 官方性能资料支持将其作为正文提取起点

PyMuPDF 官方公布的八个 PDF、合计 7,031 页的基准中，基础文本提取总耗时为 PyMuPDF 8.01 秒、PyPDF2 101.64 秒、PDFMiner 227.27 秒，且注明未进行版面重排。这是库作者的特定环境与样本结果，可以支持选型方向，不能写成本项目的耗时或准确率，也不能把 PDFMiner 的成绩直接当作 pdfplumber 成绩。[官方性能概览](https://pymupdf.readthedocs.io/en/latest/about.html#performance)、[基准方法与数据](https://pymupdf.readthedocs.io/en/latest/app4.html#text-extraction)

本项目仅验证 PyMuPDF 加载功能，未安装另外两个库，没有开展三库同机性能比赛。

### 3.3 符合本地部署和当前环境

官方提供 Windows、Linux、macOS 常见平台的 wheel，并说明基础功能没有必须另外安装的外部组件；没有可用 wheel 时才可能需要源码编译。当前 Python 3.12 / macOS arm64 环境已安装并验证 `PyMuPDF==1.28.2`。加载过程仅访问本地文件，不连接模型、云端服务或向量数据库。[安装文档](https://pymupdf.readthedocs.io/en/latest/installation.html)

本次仅新增 PyMuPDF 和 `langchain-core==0.3.29`；后者沿用参考仓库版本，仅用于统一 Document 类型。未安装完整 LangChain 加载框架，也没有新增 OCR 组件。

## 4 与参考代码的关系

已阅读固定提交的 [RAG 源码](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/rag.py)、[RAG 测试](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/tests/test_rag.py) 和 [依赖清单](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/requirements.txt)。

- 沿用 `load_document()` 的“文件路径 → Document 列表”及 `source_file`、`file_type`、`doc_id` 字段。
- 上游 PDF 通过 `PyPDFLoader` 使用 pypdf 5.1.0，不是 PyPDF2。本项目按用户指定改为 PyMuPDF，仍放在既定 `src/data_loader/pdf_loader.py`。
- 上游每个返回 Document 随机生成一个短 `doc_id`；本项目按文件原始字节生成 SHA-256，各页共用，重复导入同一内容保持稳定。相同内容的文件副本会拥有相同 ID，路径和文件名仍分别保留。
- 上游测试没有直接验证真实 PDF 分页解析，本项目在既定 `tests/test_retrieval.py` 补充实际 PDF 测试。没有初始化模型或 Chroma，也没有宣称上游测试已运行。

## 5 已实现的接口与边界

```python
from src.data_loader.pdf_loader import load_pdf

# 每个返回对象对应一个有文本的 PDF 页面。
documents = load_pdf("data/raw/论文.pdf")
for document in documents:
    print(document.metadata["source_file"], document.metadata["page_number"])
    print(document.page_content)
```

| 字段 | 含义 |
| --- | --- |
| `page_content` | 页面正文，仅去除首尾空白，不主动删除公式字符或页眉页脚 |
| `source` / `source_file` | 规范化绝对路径 / 原文件名 |
| `file_type` | `.pdf` |
| `doc_id` | 原文件字节的 SHA-256，各页一致 |
| `page` / `page_number` | 从 0 开始的页面索引 / 从 1 开始的物理页码 |
| `total_pages` | 原 PDF 总页数，包含被跳过的无文本页 |

物理页码不是论文正文印刷的页码。例如封面是 PDF 第 1 页，仍记录为 1。跳过无文本页不会重新编号，避免后续引用错位。

- 文件不存在或不是普通文件：`FileNotFoundError`。
- 后缀不是 PDF、实际内容不是 PDF、需要打开密码：`ValueError`；当前不提供密码参数。
- 页面无文本：记录警告后跳过。不能仅凭无文本就认定为扫描页；也可能是空白页。
- 全篇无可提取文本：`ValueError`，提示检查空白或扫描件，不返回空列表冒充成功。
- 损坏文档：PyMuPDF 原生解析异常向上传递，后续批量导入模块再负责状态追踪与重试。

`sort=True` 根据位置调整文本顺序，不保证论文双栏阅读顺序完整恢复。当前没有跨页表格合并、公式转 LaTeX、图片理解或 OCR；不把纯文本中的表格字符当作结构化表格。后续学术排版实验需记录这些损失。[Page API](https://pymupdf.readthedocs.io/en/latest/page.html#Page.get_text)、[PyMuPDF 文本指南](https://pymupdf.readthedocs.io/en/latest/recipes-text.html)
