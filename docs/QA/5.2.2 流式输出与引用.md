# 5.2.2 流式输出与引用

## 流式协议

单个 Streamlit 应用直接读取本地 Ollama NDJSON，没有另建 HTTP／SSE 服务。模块二 `stream_answer()` 输出 `token`／`done`／`error` 事件，逐步累积正文；闭合合法引用时即时映射同轮来源，未闭合标记不提前确认为引用。

完成包验证自然结束、用量和引用；`length` 提示可能截断，异常保留已收到的部分文本，不冒充完整回答，不写语义缓存。实际 Token 以服务返回为准，未知值保持未知。

## Agent 页面中的应用

科研对话由 Agent 统一调度，核心 RAG 工具先完成内部检索／生成；Observation 的公开答案字段再流式输出到页面。不能把内部工具耗时说成已即时输出到用户。最终完成包通过校验后替换临时文本，引用入口保留原文物理页与下载。

独立单轮 RAG 标签已删除，模块二接口和测试仍保留。消息区滚动、输入“发送”后清空及等待转圈见[前端 QA](5.4.3%20前端与会话管理.md)。

实现：[streaming.py](../../src/generation/streaming.py)、[ReAct](../../src/agent/react_loop.py)。真实历史模型／浏览器事件见[5.2.2 证据](../../reports/5_2_2%20流式输出与引用/README.md)及[正文流式交付证据](../../reports/5_4_3%20前端与会话管理/交付补齐_20261004/README.md)；mock断流测试不代表模型质量。
