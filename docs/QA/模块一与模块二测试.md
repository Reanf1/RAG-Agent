## 1 结论与范围

模块一 165 项、模块二 123 项自动化测试全部通过，共 288 项，耗时 15.937 秒。真实本地模型验证了多格式入库、增量索引、持久化重开、检索/重排、生成、降级与日志之间的连接。**功能回归通过，不代表全部课程验收或答案质量通过。**

本轮发现或复现了检索漏召回、模型混用论文参数、误拒答和缺正文引用。六请求语义缓存实测在第四个请求因缺有效正文引用失败，不能标记全部通过。M1-03 的五组分块检索召回实验仍未完成；独立答案与引用语义人工评分仍待完成。

环境为 Python 3.10.10、macOS 27 ARM64，使用项目 `.venv`；模型保持 M3E-base、bge-reranker-base 与本地 Ollama Qwen2.5:7b，Prompt 为 rag-v3，生成参数为 0.1/0.9/40。模型及配置快照保存在各结果 JSON。所有实际索引、导入目录及聊天日志采用临时目录，不写用户默认知识库。测试使用本地权重和本机服务；没有进行物理断网、多用户并发或本轮浏览器视觉检查。

## 4 质量问题与验收缺口

1. **完整论文中文检索/生成失败**：Transformer头数/每头维度应为8/64。当前Top-1为BERT第3物理页，Top-5没有该标注事实块；模型引用BERT的12/16头并错误推断每头维度为H。引用文件/页码映射正确，陈述仍错误。
2. **缺正文引用**：英文BERT数字为12/768/12与24/1024/16，但仅末尾写引用或完全未写，系统正确报告未溯源且拒绝缓存。流式接口完成不是引用质量通过。
3. **有依据却拒答及缓存复用**：两个标注块的缓存探测中，Attention原文明确给出8头/64维，模型仍称未给头数，并带一个合法编号。当前缓存只检查结束状态、警告及来源编号，无法识别这类语义错误。
4. **低相关提示措辞**：用户确认候选后，系统保留low模式与相关性提示，但模型仍写“未找到相关文档”；实际上有候选却不能回答票价。这是生成措辞问题。

逐例原文、根因与后续改进方向见[Bad Case报告](../../reports/Bad_Case分析报告.md)。本轮未调模型、改Prompt或补造引用，不声称已改善答案质量；优化后应在同一问题/来源上复测并另存数据。

M1-03维持“部分实现”。M1其余功能和M2-01～M2-06的接口/页面状态保留，M2-02及M2-04明确附带上述质量限制；本轮不把模块三Agent或模块五正式评测标记完成。此前rag-v2的160条参数实验和三档检索质量数据未覆盖，也未宣称用rag-v3重跑参数选型。
