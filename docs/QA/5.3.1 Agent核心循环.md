## 手写有界ReAct

沿用上游工具注册／消息执行流程，在`react_loop.py`手写多步循环，上游一轮Function Calling不等同于本项目ReAct。

| 阶段 | 输入与输出 | 校验 |
| --- | --- | --- |
| Thought | 原问题、当前Context、实际工具描述 → 公开决策与下一步工具／直答 | 工具名及并行计划来自实际注册表，资料与用户文本不能伪造系统指令 |
| Action | 选定工具、Schema与原生tool_calls → 实际执行结果 | 名称／次数一致，参数字典、必填项与多余字段核验，禁止未声明调用 |
| Observation | ToolMessage结果 → 继续、完成或资料不足 | 待确认／缺证据不能标完成；只引用真实工具来源 |

System Prompt统一科研角色、实际工具用途／参数、各阶段结构化输出和来源规则；工具描述来自`@tool`与Schema。公开轨迹展示规划说明／动作／结果，不要求披露模型私有思维过程。

终止包括完成、信息不足／待确认、最大8轮、相同工具参数重复上限2、错误及用户中断。每轮新建执行状态，模型失败不当作成功答案；工具副作用不因终止自动回滚。

## ID交接与报告保留

论文工具缺真实ID时先`paper_list`；仅依据成功列表将唯一文件名／干名映射为实际SHA-256。知识库文件名问题保留文档过滤，未知／歧义不猜测编号。页面显示八位ID，内部和工具仍使用完整指纹。

简单单工具任务中，完整回答原问题、grounded、有效引用并明确成功的RAG／结构化摘要／对比报告直接保留，避免Observation二次改写丢字段或来源。多步骤、子问题、低相关、缺证据或未完成不直通；不能用结构完整推断语义正确。
