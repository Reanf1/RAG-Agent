# 5.4.3 ID与侧栏显示精简

2026年10月4日，按用户要求统一ID与侧栏显示。

- 文档列表、知识归档、会话恢复、知识库详情表、引用块、检索文档/块、请求与工具调用编号，只展示前八位；ID标签与编号同行。JSON中的id、*_id和*_ids字段递归生成展示副本，工具执行、SQLite/Chroma、原始事件、引用定位和组件key保持完整编号；原文内容不改写。
- 上传组件名称改为“上传文档”，支持格式与批量能力保留。开始导入与重试失败项并排；原有启用/禁用、成功清空上传选择及失败重试流程保留。
- 系统状态、文档上传与管理、对话历史管理统一为header，与原文档上传标题字号相同。
- 文档检索筛选支持八位ID的唯一匹配；若前缀重复则明确提示使用完整ID，不会选错文档。完整ID查询仍可用。

固定参考前端采用“上传文档”和Streamlit会话状态，本轮复用该组件方式；参考测试核对会话隔离，实际业务验证使用本项目测试。

四个测试文件118项通过，新增验证标题及上传名称、真实文献的八位ID限定检索与前缀冲突、轨迹展示短ID且日志/参数保留完整ID。浏览器首次发现columns在窄窗口堆成两行，改为横向容器后文档流程34项复测通过。

浏览器实测三个标题均20px；两个导入按钮Y坐标均609.59（页面当时位置），知识库ID标签与八位编号各只有一行。验证只使用隔离原文、Chroma、SQLite、小型向量及模拟健康状态，不启动Mac生成模型、不进行性能测试。
