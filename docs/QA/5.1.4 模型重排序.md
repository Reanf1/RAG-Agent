# 5.1.4 接入 BGE 模型重排序

2026 年 9 月 29 日接入本地 `BAAI/bge-reranker-base`，对 RRF 融合后的默认 Top-20 候选精排，再返回最终 Top-K。页面新增“RRF + 模型重排”，保留纯向量、BM25 和普通 RRF 供后续对比实验使用。本次完成模型接入和功能核验，尚未进行三档 Hit@5/MRR 质量评测。

## 1. 依据与实现取舍

实现前阅读固定版本的 [RAGEngine.rerank()、_get_reranker() 与 _rerank_cross_encoder()](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/app/core/rag.py)、[重排测试](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/tests/test_rag.py) 和 [依赖](https://github.com/dsy1018/ai-chatbot/blob/6979d7173ed0f92910a8571dd4ca1b4a171a2c49/requirements.txt)。上游用可选 FlagEmbedding：懒加载模型，将问题与每个候选正文成对输入，计算分数、降序排列、截取 K；缺少依赖时默认改用关键词重排，现有测试主要覆盖该关键词分支。

本项目沿用模型分支的流程，复用已安装的 `sentence-transformers==3.3.1` 中的 CrossEncoder，底层同样使用 Transformers 的序列分类模型，无需新增 FlagEmbedding。显式 sigmoid 对应上游 `normalize=True`；本地模型、CPU/FP32 与批量输入适配当前环境。模型缺失或推理失败明确报错，不用关键词分数冒充模型结果。

选用当前配置已经指定的 base，而不增加 v2 的运行时选型。官方 [模型资料](https://huggingface.co/BAAI/bge-reranker-base) 将 base 标为中英文 Cross-Encoder，并提供“问题—段落”的 Transformers 推理示例。它联合阅读问题和正文，输出相关性分数；Embedding 模型分别编码二者，适合全库粗召回。重排只处理少量候选，不能找回未召回的段落，是否改善本项目质量仍需实测。

## 2. 流程与接口

```text
向量 Top-20 + BM25 Top-20
          ↓ 手写 RRF 合并
       融合 Top-20
          ↓ BGE 成对打分
       模型分数降序
          ↓ 截取最终 K
    原文块 + 来源 + 模型分数
```

实现文件：[reranker.py](../../src/retrieval/reranker.py)、[混合接口](../../src/retrieval/hybrid_retriever.py)。在项目根目录调用：

```python
from src.retrieval.hybrid_retriever import HybridRetriever
from src.retrieval.reranker import Reranker

retriever = HybridRetriever()
# 完整链路：先融合足够候选，再模型精排；最终只返回 5 项。
results = retriever.search("Transformer 编码器有多少层？", k=5, rerank=True)
for document, score in results:
    print(document.metadata, score, document.page_content)

# 也可单独精排已有候选；不在模型评分前截成最终 Top-5。
candidates = retriever.search("注意力机制", k=20)
results = Reranker().rerank("注意力机制", candidates, k=5)

# 文档过滤在两路召回阶段生效；改为实际文档 ID。
# results = retriever.search("实验结果", k=5, doc_id="实际文档 ID", rerank=True)
```

`rerank=False` 为混合接口的默认值，原有 RRF 调用结果保持原语义。启用时两路各取 `max(candidate_k, 最终K)`，融合后取同样数量交给模型；默认 20。最终 K 超过 20 时候选相应扩大，不人为限制返回数量。不足 K 时只返回实际候选，不补齐。

`Reranker.rerank(query, candidates, k=None)` 接收现有 Document/检索分数列表，旧分数只随候选传入，不与模型分数相加。返回同样二元组，分数改为 sigmoid 后的模型相关性分数；同分保持候选原顺序，即沿用 RRF 排名作为平分处理。不修改 Document、正文或元数据，页码、续表范围、公式位置与其他格式来源保持原样。

分数位于 0～1，不是经校准的命中概率，不能与向量或 RRF 分数直接比较。本轮不设置相关性阈值；数量不一致或非有限分数明确报错。空问题/空候选不加载模型，加载成功后同进程复用；失败不缓存，修复权重后可重新提交。

## 3. 本地权重与配置

| `retrieval` 字段 | 当前值 | 用途 |
| --- | --- | --- |
| `reranker_model` | `BAAI/bge-reranker-base` | 权重来源 |
| `reranker_revision` | `2cfc18c9415c912f9d8155881c133215df768a70` | 固定下载版本及溯源 |
| `reranker_local_path` | `data/models/bge-reranker-base` | 运行时唯一加载路径 |
| `reranker_device` | `cpu` | 当前已验证设备 |
| `reranker_batch_size` | `8` | 每批问题—正文对数量 |
| `reranker_max_length` | `512` | 每对输入合计的 Token 上限 |

本机权重已准备。在其他电脑首次使用时，从项目根目录显式联网下载：

```python
from huggingface_hub import snapshot_download
from src.utils.config import load_config

config = load_config()["retrieval"]
snapshot_download(
    config["reranker_model"], revision=config["reranker_revision"],
    local_dir=config["reranker_local_path"],
    allow_patterns=["*.json", "model.safetensors", "sentencepiece.bpe.model"],
    max_workers=2,
)
```

权重文件实际为 1,112,206,140 字节（约 1.11 GB），另有 Tokenizer 文件；`data/models/` 已忽略，不提交到 Git。运行时 `local_files_only=True`、`trust_remote_code=False`，不自动下载、不执行远程代码、不调用云端 API。版本字段用于准备和溯源，推理只读本地路径；修改设备、模型或输入上限后重启进程，避免复用缓存实例。

输入 512 Token 包含问题、正文和特殊标记，与分块的 512 字符不同。超过上限由 Tokenizer 截断，完整原文仍用于结果展示与来源核验；超长表格的关键内容可能未进入模型，不能将“原文保留”解释为模型读完全文。默认使用 FP32，不照搬上游 FP16。

## 4. 验证证据

新增 7 个精排、3 个加载、3 个混合链路和 3 个界面测试，全部 160 个测试通过。单元测试隔离大模型，用明确的模拟分数核验成对输入、降序/同分、默认/超大 K、单候选、零分、来源保留、空输入、配置、错误和恢复；模拟分数不作为模型效果数据。链路测试让 RRF 第 20 项经模型升至最终 Top-1，验证没有过早截成最终 K。页面用例实际操作检索、上传、文档过滤与错误恢复。

真实功能核验使用既有 6 篇中英 AI 论文的 821 块，复用真实 M3E 文档向量，查询现场编码；临时 Chroma 不写业务索引。按既有样本顺序选每个语言组合的第一题，再增加第一题的文档过滤，共 5 组；不按输出结果挑选题目。

| 查询组 | 问题 ID | 文档过滤 | 模型实际评分候选数 | 最终返回数 | 与直接 Transformers 分数最大误差 |
| --- | --- | --- | --- | --- | --- |
| 中文问英文论文 | attention-01-zh | 无 | 20 | 5 | 0.0 |
| 英文问英文论文 | attention-01-en | 无 | 20 | 5 | 0.0 |
| 中文问中文论文 | cnn_survey-01-zh | 无 | 20 | 5 | 0.0 |
| 英文问中文论文 | cnn_survey-01-en | 无 | 20 | 5 | 0.0 |
| 中文问英文论文 | attention-01-zh | attention | 20 | 3 | 0.0 |

逐项对照官方示例的 Tokenizer → 序列分类模型 logits → sigmoid，100 个候选分数均一致，排序与来源核验通过。实际模型为 XLMRobertaForSequenceClassification，CPU/FP32；单实例复用、索引重开、空输入不加载，以及单个合成长段按 512 Token 截断且保留原文的核验通过。配置、输入/权重哈希、RRF 排名、模型分数和直接推理分数见 [验证 JSON](../../reports/模型重排序验证结果.json)。

没有新增依赖，`pip check`、`git diff --check` 与本地文档链接核验通过。以上验证接入正确性，未统计质量指标或做模型速度比较；三档 Hit@5/MRR、参数选型、完整 RAG 生成及浏览器视觉检查尚未完成，不宣称已达到课程的 85% 命中率。
