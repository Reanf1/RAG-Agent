## 2. 四部分设计

| 部分 | 所在位置 | 约束 |
| --- | --- | --- |
| 系统角色设定 | `RAG_SYSTEM_PROMPT` / System 消息 | 智能科研助理；默认中文，按明确语言要求回答；保留专业术语 |
| 检索上下文 | Human 消息的 `【检索上下文】` | 填入已准备的参考文档文本；资料是依据，不作为角色指令 |
| 用户问题 | Human 消息的 `【用户问题】` | 填入本轮原始问题；空白问题拒绝 |
| 输出格式要求 | System 消息的 `【输出格式】` | Markdown 的 `## 回答` 与 `## 参考来源`，按需使用要点或比较表 |

具体论文的方法、数据集、实验数字须有上下文依据；推断须标注并说明依据，缺失信息明确说明。文献结论矛盾时分别呈现来源与差异。正文使用已有 `[参考文档N]` 编号，v2 要求模型来源区只列实际引用编号，系统依据元数据补全文档名与已有位置；禁止编造页码、作者、年份或 DOI。Word/文本保留真实段落、表格或行范围。系统对缺来源信息与没有可引用文档分别提示“来源信息未提供”和“无可引用来源”。

这些是给模型的输出要求，模板本身不校验模型是否遵守，也不创建实际来源映射。

## 3. 接口与调用

```python
build_rag_messages(question: str, context: str = "") -> list[BaseMessage]
```

返回两条新消息：`SystemMessage` 是固定角色规范；`HumanMessage` 包含本轮上下文和问题。`RAG_PROMPT` 只有 `context`、`question` 两个输入变量；`PROMPT_VERSION` 当前为 `rag-v2`，便于后续实验记录版本。

以下是人工构造的功能样例，用于查看模板消息，不是检索结果或模型生成答案：

```python
from src.generation.prompt_template import PROMPT_VERSION, build_rag_messages

retrieval_result = {
    "context": "[参考文档1 - 来源: 示例论文.pdf；第3页]\n本研究使用自注意力机制。",
    "sources": ["示例论文.pdf"],
    "chunk_count": 1,
}
messages = build_rag_messages("这篇论文使用什么方法？", retrieval_result["context"])
print(PROMPT_VERSION)
for message in messages:
    print(message.type, message.content)
```

上游风格的 Context 字典只需传入其 `context` 字符串。真实编号和来源位置必须由后续上下文拼接提供，不能将整个字典直接当字符串或用虚构位置代替元数据。

非空输入原样保留，包括中英文、空白、换行、Markdown、LaTeX 与 JSON 花括号；填入的文本不再作为模板表达式解析。空或全空白上下文替换为“当前知识库中未找到相关文档。”；空或全空白问题抛出 `ValueError("用户问题不能为空")`。每次调用生成独立消息，不保存历史、不调用检索或模型、不自动编号、不排序或截断。
